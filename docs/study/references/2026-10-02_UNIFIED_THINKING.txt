# 문제를 읽고 풀이를 만드는 통합 사고 과정

작성일: **2026-10-02 (Asia/Seoul)**

목적: 해시에서 사용한 8단계를 스택/큐를 비롯한 모든 유형으로 이어간다. 질문 제목을 암기하는 데서 그치지 않고, 각 질문의 답을 만드는 행동을 익힌다.

이 문서는 사용자가 요청한 개념 설명용 참고서다. 실제 문제 수업에서는 한 번에 질문 하나를 다루고, 사용자가 먼저 해석·접근을 제안한다. 미풀이 Kit 문제의 완성 풀이·제출 코드는 포함하지 않는다.

## 1. 통일할 것은 사고의 순서다

문제마다 사용할 자료구조는 달라도, 다음 연결은 유지할 수 있다.

> **요구되는 결과 → 입력 규모와 조건 → 직접적인 해결 절차 → 비싼 일 → 보존할 정보와 처리 순서 → 정확성 근거 → 총비용 → 검증**

기존 8단계를 버리지 않는다. 3단계에서 비용의 목표를 먼저 세우고, 4~6단계에서 구체적인 풀이를 만든 뒤 실제 비용을 다시 계산한다. 사고는 앞뒤로 오갈 수 있지만, 코딩 전에는 근거가 연결되어 있어야 한다.

머릿속의 짧은 문장은 다음 정도면 충분하다.

> **무엇을 구하나 → 얼마나 큰가 → 그대로 하면 어떻게 하나 → 무엇이 비싼가 → 무엇을 기억하고 어떤 순서로 처리하나 → 왜 맞나 → 실제로 확인했나.**

바로 떠오르지 않는 순간을 없애는 것이 목표는 아니다. 막혔을 때 할 구체적인 행동을 갖추고, 독립적으로 복원할 수 있는 범위를 넓히는 것이 목표다.

## 2. 자료구조와 알고리즘의 본질

**자료구조는 필요한 정보를 표현·배치해, 조회·삽입·삭제·선택을 정해진 비용으로 수행하는 방법이다.**

해시는 키로 찾기, 스택은 최근에 넣은 항목 꺼내기, 큐는 먼저 넣은 항목 꺼내기, 힙은 현재 극값 선택을 지원한다. 어떤 구조를 선택한다는 것은 필요한 연산을 싸게 만드는 대신 다른 연산이나 메모리 비용을 받아들이는 것이다.

**알고리즘은 입력에서 요구된 출력을 만드는 유한한 절차다.** 설계에서는 상태의 의미, 처리 순서, 갱신 규칙, 종료 조건을 정하고, 그 절차가 올바르며 예산에 맞는지 설명한다. 완전탐색도 알고리즘이다. 모든 알고리즘이 선계산이나 생략을 해야 하는 것은 아니다.

둘을 연결하는 질문은 다음이다.

> **다음 결정을 내리려면 과거에서 무엇을 알아야 하고, 그 정보를 어떻게 유지해야 하는가?**

같은 키의 개수가 필요하면 빈도표가 후보이고, 최근에 남겨둔 작업이 필요하면 스택이 후보다. 매번 현재 최소 작업을 골라야 하면 힙이 후보가 된다. 컨테이너 이름을 먼저 정하면 이 연결을 건너뛰기 쉽다.

### 최소한의 상태를 찾는 기준

서로 다른 두 과거를 같은 상태로 저장했다고 하자. **이후 같은 입력을 주었을 때 올바른 판단이 달라진다면, 그 상태는 정보를 너무 많이 버렸다.**

- 존재 여부만 저장하면 중복 개수를 구별할 수 없다.
- 최댓값 하나만 저장하면 그 최댓값이 삭제된 뒤의 다음 최댓값을 알 수 없다.
- 추가만 하는 데이터의 지금까지 최댓값은 값 하나로 갱신할 수 있다.
- 경로에서 사용한 자원에 따라 다음 행동이 달라지면, 위치만 같은 두 상황을 같은 탐색 상태로 합칠 수 없다.

정보를 얼마나 저장할지는 사용 가능한 다음 연산에 달려 있다. 데이터가 변한다는 이유만으로 힙이나 트리가 필요한 것은 아니다.

## 3. 공통 8단계 — 질문과 답을 만드는 행동

| 단계 | 머릿속 질문 | 실제로 할 행동 | 남겨야 할 결과 |
|---|---|---|---|
| 1 목표 | 정확히 무엇을 반환하는가? | 출력 형식·선택 규칙·순서·동률·없을 때의 처리를 표시한다 | 입력과 반환 규칙을 담은 문장 |
| 2 제약 | 어떤 경우까지 책임져야 하는가? | 개수 N, 값 범위 U, 문자열 길이 L, 종류 G, 관계 V/E를 분리한다 | 변수별 범위와 중복·순서·보장 조건 |
| 3 예산 | 직접 계산하면 얼마나 커지는가? | N², N log N, 경우의 수 등을 최댓값에 대입한다 | 목표 시간·공간과 탈락 후보의 수치 |
| 4 기준선 | 손으로 하던 일을 그대로 프로그램으로 만들면? | 후보/진행 상태를 만들고, 검사하고, 답을 갱신하는 절차를 적는다 | 반복 구조가 보이는 올바른 풀이와 비용 |
| 5 병목→유형 | 어느 일을 왜 반복하는가? | 비싼 연산을 한 문장으로 쓰고 저장·순서·재사용·후보 제거를 검토한다 | 필요한 연산, 선택한 방법, 절약과 유지 비용 |
| 6 선서술 | 처리 중 무엇이 항상 맞아야 하는가? | 상태 뜻·초기화·갱신·종료 후 답을 연결한다 | 구현 전에 말한 절차와 정확성 근거 |
| 7 4게이트 | 어디까지 실제로 확인했는가? | Build / Example / Edge / Judge를 각각 확인한다 | 게이트별 실행 결과와 미실시 구분 |
| 8 회고 | 다음 문제에서 무엇을 재사용할 수 있는가? | 실패한 가정, 적용 조건, 반례, 도움의 양을 적는다 | AC 후 회고·지연 복원·변형 과제 |

이 표는 한 번에 제출할 설문이 아니다. 실제 수업에서는 현재 단계의 질문 하나를 해결하고 다음으로 이동한다.

## 4. 완전탐색 기준선이 안 떠오를 때

기준선은 **가장 직접적으로 맞는 절차**다. 반드시 무저장이어야 하거나, 반드시 비효율적이어야 하거나, 반드시 이중 반복문이어야 하는 것은 아니다. 배열·방문 표시·재귀를 사용해도 된다. 처음부터 선형 순회로 충분하다면 그것이 기준선이자 최종 풀이일 수 있다.

다음 세 동작을 작은 입력에서 해본다.

1. **대상을 정한다.** 한 원소인지, 두 원소의 쌍인지, 구간인지, 부분집합인지, 순열인지, 이동 경로인지 적는다.
2. **빠짐없이 만들어 검사한다.** 각 대상이 조건을 만족하는지 판단하는 데 필요한 정보를 적는다.
3. **출력 규칙대로 합친다.** 최선 갱신, 개수 누적, 정렬된 결과 구성 중 무엇인지 적는다.

| 출력의 성격 | 직접적인 출발점 | 비용에서 셀 것 |
|---|---|---|
| 각 원소에 대한 답 | 원소 하나를 잡고 답을 찾는 데 필요한 범위를 훑는다 | 질문 수 × 검색 범위 |
| 가장 좋은 쌍/구간 | 모든 쌍/구간을 만들고 점수를 계산한다 | 후보 수 × 점수 계산 비용 |
| 선택/배치 방법 | 각 단계의 선택지를 전부 시도한다 | 탐색 노드 수 + 완성 후보 검사 비용 |
| 시간에 따른 동작 | 규칙대로 사건을 진행한다 | 실제 진행 횟수 × 사건당 비용 |
| 연결/도달성 | 상태에서 가능한 이동을 차례로 조사한다 | 구별되는 상태와 전이 수 |

### 이미 AC인 완주하지 못한 선수로 연결하기

중복 이름이 있으므로 같은 참가자 한 명을 여러 완주자와 중복해서 짝지으면 안 된다.

직접적인 절차는 **완주자 한 명마다 아직 짝짓지 않은 참가자들을 훑어 같은 이름 하나를 사용 처리하고, 마지막에 남은 참가자를 반환하는 것**이다. 사용 여부 배열을 쓰는 것은 기준선에서 허용된다.

참가자 N명, 완주자 M명, 이름 최대 길이 L로 두면:

- 완주자 M명 각각 최대 N명 검색: O(MNL).
- 마지막 참가자 검사: O(N).
- M=N−1이므로 전체 최악 O(N²L), 사용 여부 공간 O(N).

여기서 비싼 질문은 “이 이름으로 아직 짝지을 사람이 남아 있는가?”다. 이름별 남은 수를 유지하면 전체를 다시 검색할 필요가 줄어든다. 해시의 핵심은 이 **반복 검색과 빈도 유지의 교환**이다.

이 예시는 기존 AC 문제의 개념 복습이다. 오늘 독립적으로 재유도한 증거로 기록하지 않는다.

### 기준선 작성 중 자주 생기는 막힘

- “완전탐색”이라는 단어가 막연하다 → 입력을 3~4개로 줄이고 손으로 정답을 만드는 동사를 쓴다.
- 후보 하나를 검사하는 법이 없다 → 출력 규칙을 더 쪼갠다. 아직 알고리즘 유형을 고를 단계가 아니다.
- 전체 풀이와 부분 연산을 혼동한다 → 장르 합계를 구하는 스캔 하나만으로는 앨범의 전체 순서가 완성되지 않는다. 마지막 출력 구성까지 적는다.
- 순진한 풀이가 너무 느리다 → 오히려 병목을 찾을 근거가 생긴 것이다. 느리다는 이유로 기준선을 지우지 않는다.

## 5. 복잡도는 호출 횟수와 한 번 비용을 분리한다

> **전체 시간 = 전처리 비용 + Σ(연산 종류별 실행 횟수 × 한 번의 비용) + 후처리 비용**

먼저 N, M, G, L, V, E가 무엇인지 정한다. 최악 총비용을 먼저 쓰고, 해시의 평균 비용이나 상환 비용을 사용하면 따로 표시한다.

### O(20,000)을 어떻게 고치는가

`N=10,000일 때 순회 두 번이면 약 20,000회의 반복`은 특정 입력 크기에서의 산술이다. 각 반복이 상수 비용일 때, 입력 N에 따른 성장률은 `O(N+N)=O(N)`이다.

반면 같은 인덱스 i로 `genres[i]`와 `plays[i]`를 함께 읽는 루프는 N회 반복이다. 배열이 두 개라는 이유만으로 N×N이 되지 않는다. 뒤에 정렬을 했다면 정렬 비용을 따로 더해야 한다.

| 구조 | 계산 | 결론/주의 |
|---|---|---|
| 길이 N 순회 후 길이 M 순회 | N+M | O(N+M) |
| N개 각각에 M개 전체 검사 | N×M | O(NM) |
| N개 정렬 후 N개 순회 | N log N+N | 비교 한 번 O(1)일 때 O(N log N) |
| 각 원소를 한 번 넣고 최대 한 번 빼기 | push≤N, pop≤N | 연산당 O(1)이면 최악 총 O(N) |
| N개를 힙에 넣고 전부 빼기 | Σ log k를 두 번 합산 | O(N log N), top 하나만 읽기는 O(1) |
| 길이 n_g인 서로 다른 그룹들을 순회 | Σ n_g=N | 중첩 for여도 O(N) |
| 그룹별 정렬 | Σ n_g log n_g≤N log N | G×N log N으로 중복 계산하지 않음 |
| 상태 S개, 상태마다 전이 최대 K개 | S×K | 전이당 비용도 곱해야 함 |

`for` 안에 `while`이 있다는 모양만으로 O(N²)이라 판정하지 않는다. 같은 원소를 몇 번 처리하는지 세어야 한다. 반대로 한 번의 for 안에 `find`, `sort`, 문자열 복사, vector 앞 삭제가 있으면 그 비용을 포함한다.

### 스택/큐에서 필요한 상환 분석

어떤 입력에서는 원소 하나를 처리할 때 스택에서 여러 개를 뺄 수 있다. 그래도 **전체 실행에서 각 원소가 한 번 들어가고 최대 한 번 나오는 것이 증명되면**, 총 push/pop은 O(N)이다.

이는 좋은 입력에서만 빠르다는 평균 분석이 아니다. 조건을 만족하는 모든 입력의 연산열에 대한 총비용 분석이다. 뺀 원소를 다시 넣는 구조라면 이 근거를 그대로 쓸 수 없다.

### 최대 입력을 대입한 규모

| N | N | N log₂ N (근삿값) | N² |
|---:|---:|---:|---:|
| 1,000 | 1,000 | 약 10,000 | 1,000,000 |
| 10,000 | 10,000 | 약 133,000 | 100,000,000 |
| 100,000 | 100,000 | 약 1,661,000 | 10,000,000,000 |

이는 성장항의 규모이며 실행 시간 측정값이 아니다. “10⁸회=1초”, “N=10,000이면 N²은 반드시 실패”라는 고정 판정은 하지 않는다. 시간 제한, 연산의 내용, 상수, 메모리 접근, 구현을 함께 보고 후보를 좁힌다. 제한을 모르면 모른다고 적는다.

### 최악·평균·상환 구분

- 서로 다른 키가 K개인 unordered 조회 한 번: 최악 O(K), 평균 O(1). 해시·키 비교 자체의 비용은 별도로 반영한다. 최대 N개 키를 삽입하는 전체 비용은 최악 O(N²), 평균 O(N). [C++ 표준 초안의 unordered 요구사항](https://eel.is/c++draft/unord.req)
- map/set 조회·삽입 한 번: O(log K)회의 키 비교. 문자열 비교가 길이 L까지 필요하면 O(L log K) 상한.
- vector 끝 삽입: 재할당이 있는 한 번은 O(N), 연속 삽입의 원소당 비용은 상환 O(1).
- `std::sort`: O(N log N) 비교. 비교 함수가 비싸면 그 비용을 더 반영한다. [C++ 표준 초안의 sort](https://eel.is/c++draft/sort)

문자열이 있다는 이유로 모든 항에 L을 곱하지 않는다. 문자열을 해시·비교·복사하는 연산에만 길이 비용을 붙인다.

### 베스트앨범의 미완성 비용식을 완성하는 방식

N=곡 수, G=장르 수, n_g=장르 g의 곡 수, L=최대 장르 문자열 길이로 둔다. 현재 방식의 연산을 분해하면:

| 처리 | 비용 |
|---|---|
| 해시로 그룹 만들기 | 최악 O(NGL), 평균 O(NL) |
| 각 그룹의 정수 재생 수 합산 | O(Σ n_g)=O(N) |
| 장르 G개를 정수 총합 기준 정렬 | O(G log G) |
| 각 장르의 곡을 정수 기준 정렬 | O(Σ n_g log n_g) |
| 장르별 최대 두 곡 선택 | 배열 접근만 세면 O(G), 해시 조회 비용은 추가 |

현재 코드의 해시 조회까지 포함한 전체 상한은 최악 O(NGL+G log G+Σ n_g log n_g), 평균 O(NL+G log G+Σ n_g log n_g)로 묶을 수 있다. G≤N이라 후반 O(G²L) 조회는 O(NGL)에 포함된다. 문자열 길이를 유계로 취급하는 관례에서는 평균 O(N log N)으로 요약할 수 있지만, 가정을 먼저 말한다.

G<100이라는 실제 제약을 함께 대입하면 더 구체적으로 판단할 수 있다. 숫자 N만 보고 모든 비용을 N² 또는 N log N 중 하나로 단순화하지 않는다.

공식 지문에는 N≤10,000과 G<100은 있지만 **plays[i]≤10,000이라는 상한은 명시되어 있지 않다.** 예전 문서의 “합계≤10⁸, int 안전”은 지문으로 입증되지 않는다. 총합은 넓은 정수형을 고려하고, 수치를 확인하지 못했다면 그 사실을 적는다. [프로그래머스 공식 베스트앨범](https://school.programmers.co.kr/learn/courses/30/lessons/42579)

### 공간과 값의 범위

추가 배열·컨테이너·큐·재귀 스택에 동시에 살아 있는 원소를 센다. 결과 배열 포함 여부도 밝힌다. 4바이트 정수 N개는 4N바이트이지만, 해시 노드와 문자열은 별도 관리 비용이 있다.

값의 범위 U는 정수 오버플로뿐 아니라 빈도 배열 O(U), 용량 DP O(NU), 답 범위 이분탐색 O(log U)에도 영향을 준다. “개수와 값 범위를 구별한다”는 말은 값 범위를 버리라는 뜻이 아니다.

## 6. 병목에서 유형을 고르는 방법

병목은 “느리다”가 아니라 **무슨 질문을 몇 번 다시 해결하는지**로 쓴다.

| 비싼 일 | 바꿔볼 방향 | 정당화해야 하는 것 |
|---|---|---|
| 같은 키를 찾으려고 전체를 반복 검색 | 직접 주소·해시·정렬·트리 | 필요한 조회와 갱신, 키 범위, 순서 |
| 다음 처리 대상을 매번 검색 | 스택·큐·힙 | 다음 대상이 최근/먼저/극값 중 무엇인지 |
| 쌍을 전부 비교 | 정렬 후 이웃·포인터 등 | 일부 관계만 봐도 답을 잃지 않는 이유 |
| 같은 남은 문제를 반복 해결 | DP | 같은 상태라면 이후 문제가 같다는 근거 |
| 답 후보를 하나씩 전부 검사 | 이분탐색 | 판정의 단조성과 경계 유지 |
| 모든 선택을 끝까지 탐색 | 그리디·안전한 가지치기 | 최적해를 버리지 않는 증명 |
| 같은 상태를 여러 경로로 재방문 | 방문/거리 기록 | 무엇을 같은 상태로 볼지, 재방문이 필요한지 |

이 표는 후보를 제안한다. 자료구조 이름을 고르는 것만으로 정확성이 증명되지는 않는다. 앞의 직접 풀이가 이미 예산 안이면 그대로 진행할 수 있다.

## 7. 10개 유형을 같은 문법으로 읽기

고득점 Kit의 분류는 같은 층위가 아니다. 해시·스택/큐·힙은 주로 자료구조, 그리디·DP는 설계 방법, DFS/BFS는 탐색 절차, 그래프는 관계 모델이다. 한 문제에서 그래프+BFS+큐, 정렬+그리디, 해시+정렬이 함께 쓰일 수 있다.

각 유형은 **필요한 질문 → 저장할 상태/처리 순서 → 정확성 조건 → 비용 → 실패 조건**으로 이해한다.

### 7.1 해시 — 같은 대상을 다시 찾는 비용 줄이기

- 시작 질문: “같다는 것을 판정하는 키는 무엇이며, 그 키마다 어떤 정보를 유지해야 하는가?”
- 상태: 존재 여부, 빈도, 합계, 위치, 같은 키의 원소 목록 중 필요한 것.
- 핵심 원리: 키로 관련 정보를 찾아 반복 전체 검색을 줄인다. 중복을 없앨지 셀지는 문제의 의미로 결정한다.
- 불변식 예: “앞에서 i개를 처리한 뒤 count[x]는 그 구간에서 x가 등장한 횟수다.”
- 비용: K개 키에서 연산당 최악 O(K), 평균 O(1), 문자열 처리 비용 별도. 저장 공간은 값의 내용까지 센다.
- 실패 조건: set으로 개수 정보를 잃음, unordered 순회 순서를 답의 순서로 믿음, 없는 키 조회가 삽입을 일으킴.
- 알아볼 신호: 같은 이름/종류/상태별 조회·집계가 반복된다. 키가 작은 정수 범위면 배열도 후보다.

### 7.2 스택/큐 — 다음에 처리할 순서를 보존하기

- 시작 질문: “남아 있는 항목 중 다음에 필요한 것은 가장 최근 것인가, 가장 먼저 들어온 것인가?”
- 스택: LIFO. 나중에 연 작업부터 먼저 마무리해야 하는 중첩·복귀 구조에서 후보가 된다.
- 큐: FIFO. 먼저 대기한 항목부터 처리해야 하는 순서에서 후보가 된다.
- 상태: 값만 필요한지, 위치·시간·남은 양까지 필요한지 정한다.
- 불변식 예: “스택에는 아직 해결되지 않은 항목만 들어 있으며 top은 그중 가장 최근 항목이다.” “큐에는 아직 처리하지 않은 항목이 도착 순서로 남아 있다.”
- 비용: 기본 연산 O(1)이어도 **전체 삽입·삭제 횟수**를 세어야 한다. 회전·재삽입이 있으면 N회라고 단정하지 않는다.
- 실패 조건: 입력에서 바로 이전 항목과 현재 남아 있는 마지막 항목을 혼동함, 빈 컨테이너 접근, 값만 저장해 위치를 잃음, 우선순위를 FIFO로 잘못 처리함.
- 알아볼 신호: 가장 최근의 미해결, 중첩 복귀, 선착순 대기. 단원명이 스택이라고 무조건 stack을 만들 필요는 없다.

단조 스택은 “LIFO니까 사용”에서 한 단계 더 나아간다. 유지할 값의 순서를 정하고, 어떤 항목을 제거해도 미래 답을 잃지 않거나 그 항목의 답이 확정되는 이유를 증명해야 한다. 그다음 각 원소의 입출력 총횟수로 선형 비용을 입증한다.

### 7.3 힙 — 변하는 후보 집합의 극값 선택

- 시작 질문: “항목이 추가·제거되는 동안 현재 가장 작은/큰 항목만 반복해서 필요한가?”
- 상태: 우선순위와 식별 정보. 동률 규칙이 있으면 그 규칙도 우선순위에 포함한다.
- 핵심 원리: 전체 순서 대신 부모·자식의 힙 조건을 유지해 루트에서 극값을 얻는다.
- 불변식: “힙에는 현재 선택 가능한 후보가 들어 있고, top이 그중 최우선 후보다.”
- 비용: top O(1), 힙 조정 O(log K). 기본 vector의 재할당이 일어나는 push 한 번은 최악 O(K)일 수 있다. 상수 비용 원소 연산을 전제하면 연속 N회 삽입·추출의 총비용은 O(N log N)이며 배열 전체 heapify는 O(N)이다.
- 실패 조건: 한 번 정렬한 자료에 새 값이 생겨 순서가 낡음, 내부 전체가 정렬되어 있다고 믿음, 기본 max-heap 방향 착각, 아직 도착하지 않은 일을 후보에 넣음.
- 알아볼 신호: **현재 후보 중 극값을 선택하고 후보 집합이 변한다.** 고정 데이터의 전체 순서만 필요하면 정렬이 더 직접적일 수 있다.

### 7.4 정렬 — 순서로 비교해야 할 관계 줄이기

- 시작 질문: “어떤 기준으로 나열하면 필요한 관계가 이웃·앞부분·뒷부분으로 드러나는가?”
- 상태: 정렬 키와 필요하면 원래 인덱스. 원래 순서가 정답 조건이면 보존 방법이 필요하다.
- 핵심 원리: 비교 순서를 구조화해 이후 검색·그룹화·선택을 단순하게 한다.
- 정확성 조건: 비교자가 엄격 약순서를 만족하고, 정렬 후 줄인 비교 범위로 답이 충분히 결정되어야 한다.
- 비용: O(N log N) 비교+후처리. 비교자 내부 연산도 센다.
- 실패 조건: 2차/3차 기준 누락, 비교자를 swap 명령으로 해석, 동등한 두 항목에 `<=`처럼 true 반환, 정렬 후 원래 위치 유실.
- 알아볼 신호: 순위·동률·구간·가까운 값·같은 값의 묶음. “정렬하면 이웃만 보면 된다”는 결론은 문제별로 증명한다.

### 7.5 완전탐색 — 후보를 빠짐없이 만들기

- 시작 질문: “답 후보 하나는 어떻게 표현하고, 모든 후보를 어떻게 만들 것인가?”
- 상태: 선택한 것, 남은 선택지, 현재 단계. 필요하면 사용 여부와 부분 점수.
- 핵심 원리: 생략 없이 평가할 수 있을 만큼 경우의 수가 작으면 가장 직접적인 방법을 쓴다.
- 정확성 조건: 정답 후보가 반드시 생성되고, 각 후보의 판정이 맞아야 한다. 중복이 있어도 정답은 가능하지만 비용·개수 중복을 처리해야 한다.
- 비용: 후보 생성의 전체 노드 수+후보 검사 비용. 2^N개 후보마다 N개를 검사하면 O(N2^N).
- 실패 조건: N만 보고 작다고 판단, 순열/조합 혼동, 복사 비용 누락, 가지치기 근거 없이 정답 가지 제거.
- 알아볼 신호: 선택 수가 작고 전체 경우를 계산할 수 있다. 가지치기가 있어도 최악이 지수일 수 있다.

### 7.6 그리디 — 지금 선택을 확정할 수 있다는 증명

- 시작 질문: “이 선택을 포함하도록 최적해를 바꾸어도 손해가 없는가?”
- 상태: 확정한 선택과 남은 문제. 한 번 확정한 선택을 되돌리지 않는 이유가 필요하다.
- 핵심 원리: 안전한 선택의 근거가 많은 후보의 탐색을 대신한다.
- 정확성 조건: 선택 후에도 그 선택과 양립하는 최적해가 존재한다. 교환 논증·앞서감 논증 등의 형태로 설명한다.
- 비용: 선택 규칙에 따라 다르며 정렬을 쓰면 흔히 O(N log N). 그리디라는 이름으로 복잡도가 정해지지 않는다.
- 실패 조건: “당장 크다/작다”만 근거로 확정, 예제 성공을 증명으로 취급.
- 작은 반례: 액면가 {1,3,4}, 금액 6에서 큰 동전부터 고르면 4+1+1(3개), 3+3은 2개다. 지역 최선이 전체 최선을 보장하려면 별도 조건이 필요하다.
- 알아볼 신호: 선택을 교환해도 나머지의 가능성이나 최적값이 나빠지지 않는 구조.

### 7.7 DP — 같은 남은 문제의 답 재사용

- 시작 질문: “서로 다른 선택 경로가 도착한 이 두 상황은 이후에 정말 같은 문제인가?”
- 상태: 미래 선택과 답을 결정하는 데 충분한 과거의 요약. `dp[상태]`가 무엇을 뜻하는지 먼저 문장으로 정의한다.
- 핵심 원리: 같은 부분 문제를 다시 풀지 않고 저장한 결과를 사용한다.
- 설계: 상태 의미 → 마지막/다음 선택으로 전이 도출 → 초기값 → 계산 순서 → 정답 위치.
- 정확성 조건: 가능한 선택을 전이가 빠짐없이 반영하고, 이미 올바르게 계산된 하위 문제로 현재 답을 구성한다. 최적화이면 상태별 최선만 남겨도 되는 근거가 필요하다.
- 비용: 도달/계산하는 상태 수 × 상태당 전이 비용. 공간은 유지하는 상태 수. 비트마스크 DP는 지수일 수 있고 용량 DP는 값 범위에 의존할 수 있다.
- 실패 조건: 필요한 정보를 상태에서 누락, 의미 없이 점화식 암기, 아직 계산하지 않은 값 사용, 초기 불가능 상태를 0으로 취급.
- 알아볼 신호: 경로는 여러 개지만 같은 남은 문제를 반복해서 푼다. 최댓값 문제라는 말만으로 DP를 선택하지 않는다.

### 7.8 DFS/BFS — 상태와 이동을 체계적으로 탐색

- 시작 질문: “상태 하나와 가능한 다음 이동은 무엇이며, 같은 상태를 다시 구별해야 하는 조건은 무엇인가?”
- DFS: 한 방향을 깊게 탐색하고 돌아온다. 경로 열거·백트래킹에서는 경로별 사용 상태를 복원할 수 있다.
- BFS: 시작점에서 이동 횟수의 층을 넓혀간다. 모든 간선 비용이 동일한 양수인 최단거리에서 첫 발견 거리가 최단이다.
- 불변식: BFS 큐에는 발견했지만 아직 확장하지 않은 상태가 거리 순으로 있다. 방문 처리는 일반적인 BFS에서 삽입 시점에 해 중복 삽입을 막는다.
- 비용: 인접 리스트로 명시적 그래프를 한 번 방문하면 O(V+E), 행렬이면 보통 O(V²). 경로 전체 열거는 경로 수가 지수일 수 있어 같은 비용식을 쓰지 않는다.
- 실패 조건: 위치만 visited로 기록해 자원/방향 차이를 합침, 가중치가 다른데 일반 BFS로 최소 비용 확정, 모든 경로 열거에서 전역 visited를 무조건 사용.
- 알아볼 신호: 도달·연결·최소 이동·선택 경로. 같은 그래프에서 탐색 목적에 따라 방문 규칙이 달라진다.

### 7.9 이분탐색 — 한쪽 후보를 버려도 되는 단조성

- 시작 질문: “후보 x가 가능하면 더 큰 값도 항상 가능한가, 혹은 더 작은 값도 항상 가능한가?”
- 상태: 후보 구간과 경계 의미. 최소 가능값인지 최대 가능값인지 먼저 고정한다.
- 핵심 원리: 단조인 판정 결과로 답이 있을 수 없는 구간을 한 번에 제거한다. 정렬 배열 검색과 답 범위 탐색이 이 원리를 공유한다.
- 정확성 조건: 판정이 올바르고 단조이며, 매 갱신에서 답 또는 찾는 경계가 유지되고 구간이 줄어든다.
- 비용: 후보 범위 크기 R에서 O(log R × 판정 비용). 판정 O(N)이면 O(N log R).
- 실패 조건: 단조성 미확인, 경계 포함 여부 혼합, mid에서 답을 버림, 답 없음 처리 누락, 중간 계산 오버플로.
- 알아볼 신호: 최소/최대 수치 자체를 직접 구하기 어렵지만 “x 이하/이상에서 가능한가?”는 쉽게 판정된다. 숫자가 크다는 사실만으로 적용하지 않는다.

### 7.10 그래프 — 관계를 계산 가능한 모양으로 만들기

- 시작 질문: “정점 하나는 무엇이고, 간선 하나는 무슨 관계를 뜻하는가?”
- 상태: 방향·가중치·다중 간선·자기 간선 의미를 포함한 인접 관계.
- 핵심 원리: 관계 모델을 먼저 만든 뒤 목적에 맞는 알고리즘을 고른다.
- 목적별 후보: 도달/연결→DFS/BFS, 동일 비용 최단거리→BFS, 비음수 가중치 최단거리→Dijkstra, 선후 의존→위상정렬, 집합 병합→union-find, 최소 연결 비용→MST.
- 정확성 조건: 실제 문제의 이동/관계를 표현이 보존하고 선택한 알고리즘의 전제가 만족되어야 한다.
- 비용: 인접 리스트 저장 O(V+E), 인접 행렬 O(V²); 이후 비용은 선택한 알고리즘에 따른다.
- 실패 조건: 방향을 빠뜨림, 간선 수 E를 빼고 V만 계산, 도로 중복·역방향을 잘못 처리, 좌표에서 경유 상태를 빠뜨림.
- 알아볼 신호: 서로 연결됨, 이동 가능, 선후 관계, 관계를 여러 번 따라감. 지도 형태로 주어져도 그래프일 수 있다.

## 8. 선서술은 행동과 근거를 함께 쓴다

“현재 인덱스와 이전 인덱스를 비교한다”는 **행동 설명**이다. 어떤 항목을 보존해야 정답이 유지되는지는 아직 말하지 않았다.

다음 세 문장을 구분한다.

1. **상태 뜻:** “S에는 지금까지 처리한 입력 중 ___가 ___순서로 들어 있다.”
2. **갱신:** “새 항목 x를 읽으면 ___를 검사하고 ___를 바꿔 이 뜻을 유지한다.”
3. **종료:** “모든 입력을 처리하면 S의 ___가 문제에서 요구한 답이므로 ___를 반환한다.”

검증은 초기화(처음에도 맞음) → 유지(한 번 처리해도 맞음) → 종료(따라서 답이 맞음)로 한다. 종료한다는 근거도 필요하다. 재귀는 더 작은 문제로 가는지, 방문 기반 탐색은 유한한 상태 공간에서 중복 확장을 막고 처리 완료 상태가 늘어나는지, 이분탐색은 구간이 줄어드는지 확인한다. 탐색 도중 대기 큐의 크기는 늘어날 수도 있다.

불변식 하나를 적었다는 사실만으로 충분하지 않다. 그리디의 선택 안전성, DP의 상태 충분성, 이분탐색의 단조성처럼 그 유형에서 필요한 근거와 연결되어야 한다.

## 9. 스택/큐 진입에서 실제로 연습할 것

공통 8단계는 그대로 두고, 5단계에서 다음 대상과 남길 상태를 집중해서 본다.

간단한 사건열에서 A 다음 B 작업이 시작되었다고 하자. B를 끝내야 A로 돌아갈 수 있는 규칙이면 최근 작업이 먼저다. A부터 접수 순으로 처리하는 규칙이면 먼저 들어온 작업이 먼저다. 중요한 정보는 “순서가 있다”가 아니라 **어느 끝에서 다음 항목을 꺼내야 하는지**다.

실전에서는 아래 요소를 한 개씩 확인한다.

- 다음 대상: 최근 / 먼저 / 극값 / 특정 키 / 바로 인접한 항목 중 무엇인가.
- 저장 내용: 값, 인덱스, 시간 중 정답에 실제 필요한 것.
- 제거 시점: 답 확정인가, 이후에도 필요 없는가, 잠시 보류인가.
- 전체 비용: 한 항목이 총 몇 번 들어가고 나오는가. 다시 들어갈 수 있는가.
- 경계: 비어 있음, 같은 값, 하나 남음, 끝까지 미처리 상태.

바로 이전 입력과 현재 남은 마지막 항목은 다를 수 있다. 중간에 삭제·보류가 있다면 특히 구분해야 한다. 다만 실제 문제의 규칙으로 결정하며, 미리 스택을 정답으로 고정하지 않는다.

## 10. 질문을 자동으로 떠올리는 훈련

### 읽기보다 짧은 독립 생성

한 문제에서 모든 유형 질문을 순회하지 않는다. 현재 단계의 질문 하나에 답을 만든다. 막히면 다음 복구 절차를 쓴다.

1. 입력을 3~4개로 줄여 손으로 답을 만든다.
2. 손이 한 행동을 “찾는다/비교한다/선택한다/대기한다/되돌아간다”로 적는다.
3. 그 행동의 반복 대상과 비용을 센다.
4. 같은 정보를 다시 구하는지, 다음 대상을 다시 찾는지, 같은 상태를 다시 푸는지 확인한다.
5. 줄여도 되는 이유를 문장과 작은 반례로 시험한다.

답을 못 만들었을 때 설명을 읽는 것은 가능하다. 다만 도움받은 단계와 독립적으로 만든 단계를 구분한다. 설명 직후 이해와 하루 이상 뒤 백지 복원은 다른 증거다.

### 한 개념을 실력으로 환전하는 순환

- 해당 유형의 최소 원리 확인 → 대표 문제를 공통 8단계로 진행 → 사용자 구현 → 4게이트.
- AC 후: 적용 조건·실패 조건·새 신호를 사용자 문장으로 정리.
- 24시간 이상 후: 코드 없이 기준선·개선·불변식·비용부터 복원.
- 이후: 처음 보는 변형에서 유형명이 없어도 선택할 수 있는지 확인.

전 유형 설명은 전체 지도다. 모든 새 개념을 연속으로 정독하는 진도 대신 현재 스택/큐 개념을 문제 1개 AC로 연결하며 진행한다. 바닥 70%/천장 30%의 저장소 운영 기준도 유지한다.

### 개선을 확인할 관찰값

| 훈련 항목 | 관찰할 증거 |
|---|---|
| 목표 | 동률·출력 순서·반환 개수 누락 없이 자기 문장 생성 |
| 기준선 | 입력을 작게 하여 후보 생성→판정→출력까지 독립 설명 |
| 복잡도 | 전체 연산 수를 합산하고 N/M/G/L 의미와 최악/평균을 구분 |
| 선택 근거 | “이 유형이니까” 대신 필요한 연산과 안전한 생략으로 설명 |
| 선서술 | 코딩 전에 초기화·유지·종료를 말함 |
| 검증 | 자작 반례와 실제 게이트 결과, 사용한 힌트 단계 |
| 전이 | 지연 복원 및 낯선 변형에서 독립 적용 |

오늘 설명을 읽었다는 이유만으로 위 항목을 충족 또는 숙달로 올리지 않는다. 관찰 결과는 [날짜별 세션 기록](../records/2026-10-02_UNIFIED_THINKING_SESSION.md)에 이어 적는다.
