# 공통 8단계를 실제 답변으로 작성하는 가이드

작성일: 2026-10-10 Asia/Seoul

바로 작성할 때는 [공통 8단계 빈 양식과 채점 기준](../../.md/10-10/COMMON_ANSWER_TEMPLATE.md)을 복사한다. 사용자가 전체 양식을 요청하면 한꺼번에 제공하고 제출한 범위를 채점한다. 이 가이드와 walkthrough는 막힌 항목의 설명을 찾을 때 사용한다.

목표는 문제를 읽고 스스로 풀이를 만들어 설명한 다음 구현하는 것이다. 자료구조는 필요한 정보를 표현하여 연산을 지원하고, 알고리즘은 그 상태를 정해진 규칙으로 바꾸어 답을 만든다. 둘을 연결하는 질문은 **다음 판단에 무엇이 필요하며, 무엇부터 처리해야 하는가**다.

[기존 검문소 정본](../../.md/concepts/CHECKPOINT_QUESTIONS.md)의 8단계를 유지한다. 이 문서는 그 질문에 실제로 답을 작성하는 확장 가이드다. 1~6은 코딩 전에, 7은 구현 후, 8은 풀이를 마친 뒤 다룬다. 한 번에 질문 하나에 답하고, 답을 만들기 어려우면 작은 입력에서 손으로 수행한다. 문제마다 모든 유형의 추가 질문에 답할 필요는 없다. 문제 회고와 tracker의 갱신은 저장소 운영 기준대로 AC 확인 뒤에 한다.

연결: [개념서](ESSENCE_AND_STACK_QUEUE.md) · [100문항 연습](QUESTIONS.md) · [사용자 코드에 적용한 예시](SAME_NUMBER_WALKTHROUGH.md)

## 1 문제에서 근거를 만드는 사고 습관

이 자료에서 사용자가 말한 천재식 사고를 훈련으로 옮기는 방법은 **관찰 → 가설 → 반례로 점검 → 근거 설명 → 검증 → 복원**이다. 특별한 재능을 보장하는 공식으로 취급하지 않는다. 막혔을 때 다시 시작할 행동을 갖추는 것이 목적이다.

| 사고 행동 | 문제에서 하는 일 | 공통 단계 |
|---|---|---|
| 관찰 | 반환 규칙과 제약을 자기 말로 옮긴다 | 1~2 |
| 가설 만들기 | 손으로 푸는 절차를 만들고 비용을 추정한다 | 3~4 |
| 구조 찾기 | 반복되는 판단·필요한 정보·처리 순서를 찾는다 | 5 |
| 반박하고 설명하기 | 반례를 시도하고 살아남은 규칙의 근거를 설명한다 | 5~6 |
| 실행으로 확인하기 | 코드가 설명을 구현했는지 검사한다 | 7 |
| 복원과 전이 | 설명을 가리고 다시 만들고 조건을 바꿔 본다 | 8 |

반례를 찾지 못했다는 사실만으로 증명이 되지는 않는다. 반례 탐색은 잘못된 가정을 드러내는 행동이고, 정확성 설명은 왜 모든 허용 입력을 처리하는지 연결하는 행동이다. 두 행동을 함께 사용한다.

## 2 공통 8단계

### 1 목표

**정확히 무엇을 반환해야 하는가?**

- 값·위치·개수·참거짓·경로·목록 중 무엇인가?
- 원래 순서, 동률, 중복은 어떻게 처리하는가?
- 답이 여러 개이거나 없을 때 규칙은 무엇인가?

**산출물:** “입력 ___에서 ___ 규칙을 만족하는 ___를 ___ 순서로 반환한다.”

막히면 입력을 3개 정도로 만들고 정답부터 써 본다. 손으로도 정답을 정하지 못하면 자료구조 선택보다 지문 해석을 먼저 보완한다.

### 2 제약

**어떤 입력까지 책임져야 하는가?**

- 입력 개수 N과 값 범위 U는 각각 얼마인가?
- 문자열 길이 L, 종류 K, 정점 V, 간선 E 등 별도 크기가 있는가?
- 빈 입력·중복·정렬 여부·음수·항상 답이 존재한다는 보장이 있는가?
- 입력을 바꾸어도 되는가? 원래 위치가 필요한가?
- 합·곱·거리·시각의 최댓값은 어떤 타입에 들어가는가?

**산출물:** 변수별 의미·범위와 풀이가 의존하는 보장. 지문에 없는 조건은 사실처럼 적지 않는다.

### 3 예산

**입력 규모에서 감당할 수 있는 작업량의 후보는 무엇인가?**

- N, N log N, N², 2^N 등을 최대 입력에 대입하면 얼마인가?
- 연산 하나가 정수 비교인가, 긴 문자열 비교인가, 배열 복사인가?
- 시간·메모리 제한을 알고 있는가?

**산출물:** 목표 비용과 제외하거나 경계할 후보의 수치. 이 단계에서는 아직 풀이가 없을 수 있으므로 비용 목표를 잠정적으로 세운다. 4단계의 기준선과 6단계의 실제 절차로 돌아와 다시 계산한다.

### 4 기준선

**손으로 정답을 만드는 일을 그대로 절차로 쓰면 어떻게 되는가?**

- 원소·쌍·구간·부분집합·경로·시간 상태 중 무엇을 다루는가?
- 모든 필요한 대상을 어떻게 만들거나 방문하는가?
- 대상 하나의 조건을 어떻게 확인하는가?
- 확인한 결과를 어떻게 최종 반환값으로 합치는가?

**산출물:** 처음부터 반환까지 실행 가능한 직접 풀이와 그 비용.

기준선은 정확한 출발점이다. 반드시 느릴 필요도, 이중 반복문일 필요도 없다. 직접 풀이가 이미 효율적이면 그것을 채택하고 근거를 설명한다.

### 5 병목과 설계

**어떤 질문을 반복해서 해결하며, 무엇을 유지하면 그 일을 줄일 수 있는가?**

- 무엇을 몇 번 다시 찾고·세고·비교하고·계산하는가?
- 다음 판단에 필요한 과거의 정보는 무엇인가?
- 같은 상태로 합친 두 과거에 같은 후속 입력을 주어도 판단이 같은가?
- 다음 대상은 최근·먼저·극값·특정 키·의존관계 중 무엇으로 정해지는가?
- 항목을 제거하거나 선택을 확정하는 근거는 무엇인가?
- 정보를 유지하는 비용과 줄어드는 비용을 모두 합쳤는가?

**산출물:** “___를 반복하는 비용을 줄이려고 ___를 유지하고 ___ 순서로 처리한다. 이것이 가능한 이유는 ___다.”

이미 기준선이 예산 안이고 불필요한 반복도 없다면 “현재 기준선을 유지한다”라고 쓴다. 단원명만 보고 컨테이너를 추가하지 않는다.

### 6 선서술과 정확성

**무엇을 저장하고 어떻게 바꾸며, 왜 종료하면 답이 되는가?**

- 상태의 각 필드는 무엇을 뜻하는가?
- 불변식을 반복 직전과 직후 중 어느 시점에 주장하는가?
- 초기 상태에서 그 뜻이 맞는가?
- 한 단계 처리 뒤에도 그 뜻이 유지되는가?
- 종료 시 그 성질이 어떻게 반환 규칙으로 이어지는가?
- 반복·재귀가 끝나는 진행량은 무엇인가?
- 선택한 방법에 필요한 추가 증명은 무엇인가?
- 전체 연산 수와 한 번의 비용을 곱해 더하면 얼마인가?

**산출물:** 상태 의미 → 초기화 → 선택과 갱신 → 불변식 유지 → 종료와 답 → 종료 근거 → 총비용.

“두 값을 비교한다”는 행동이다. “왜 그 두 값만 비교해도 필요한 판단을 할 수 있는가”를 붙여야 근거가 된다. 선서술은 이 행동과 근거를 코딩 전에 설명하는 것이다.

### 7 네 가지 검증

**내 설명과 코드가 실제로 어디까지 확인되었는가?**

| 게이트 | 남길 기록 |
|---|---|
| Build | 사용한 컴파일 환경과 성공 또는 오류 |
| Example | 공식 예제의 기대값과 실제 실행값 |
| Edge | 깨뜨리려는 가정, 자작 경계 입력, 실제 실행값 |
| Judge | 온라인 제출 결과 또는 미제출 |

예상 결과·손추적·실제 실행을 구별한다. 경계 입력을 임의로 많이 만드는 대신 빈 상태 접근, 동률, 마지막 처리, 오버플로처럼 자신의 풀이가 의존하는 조건을 겨냥한다.

### 8 회고와 독립 복원

**다음 문제에서 어떤 판단을 다시 사용할 수 있는가?**

- 처음 놓친 규칙이나 잘못 가정한 것은 무엇인가?
- 선택한 방법의 적용 조건과 실패 조건은 무엇인가?
- 어디까지 직접 만들었고 어디에서 어떤 도움을 받았는가?
- 하루 이상 뒤 코드 없이 기준선·개선·불변식·비용을 복원할 수 있는가?
- 규칙 하나를 바꾸면 기존 근거의 어느 부분이 깨지는가?

**산출물:** 처음 가정 → 실패 사례 → 수정 근거 → 재사용 조건. 답을 이해한 직후와 나중에 독립적으로 만든 결과를 따로 기록한다.

## 3 모든 문제 위에 붙여 쓰는 템플릿

아래 틀을 유지하고 문제마다 내용을 바꾼다. 쉬운 문제는 항목별 한두 문장이면 충분하다. 필요한 근거가 생략되지 않는 범위에서 짧게 쓴다.

```cpp
/*
1. 목표
   - 입력에서 무엇을 어떤 규칙으로 반환하는가?

2. 제약
   - N과 다른 크기 변수 / 값 범위 / 중복·순서·보장 / 정수 타입

3. 예산
   - 최대 입력에 후보 작업량 대입 / 목표 시간·공간

4. 기준선
   - 손으로 푸는 절차를 처음부터 반환까지 / 직접 풀이의 비용

5. 병목과 설계
   - 반복되는 질문 / 보존할 정보 / 다음 처리 대상
   - 선택한 방법과 그 이유 / 이미 충분하면 기준선 유지

6. 선서술과 정확성
   - 상태의 뜻과 불변식의 기준 시점
   - 초기화 / 선택·갱신 / 유지되는 이유
   - 종료 후 답 / 종료하는 이유
   - 유형별 추가 증명
   - 전체 연산 횟수 × 한 번 비용 / 공간의 포함 범위

7. 검증 [구현 후]
   - Build / Example / Edge / Judge: 실제 결과 또는 미실시

8. 회고 [풀이 후]
   - 실패 가정 / 적용·실패 조건 / 받은 도움 / 지연 복원
*/
```

문제를 풀며 순서를 앞뒤로 오가는 것은 자연스럽다. 코딩 전에 1~6의 내용이 서로 모순 없이 연결되는지를 확인한다. 예산을 만족하지 못해 설계를 바꾸면 비용과 정확성 설명도 함께 고친다.

## 4 유형이 달라질 때 덧붙일 질문

공통 틀은 그대로 두고 5~6단계에 해당하는 줄만 추가한다. 자료구조·설계 방법·그래프 모델은 한 문제에서 함께 사용할 수 있다.

| 유형 | 설계에서 확인할 질문 | 추가로 설명할 근거 |
|---|---|---|
| 해시 | 같은 키라는 것은 어떤 의미이며, 존재·개수·합계 중 무엇을 저장하는가? | 같은 키로 묶어도 필요한 차이가 남는가? 평균·최악 비용과 문자열 처리 비용은? |
| 스택 | 왜 가장 최근에 남은 항목이 다음 대상인가? | top만 봐도 되는 이유와 pop 뒤에도 정보가 충분한 이유 |
| 큐 | 왜 먼저 들어와 남아 있는 항목부터 처리하는가? | FIFO가 문제 규칙을 보존하는 이유, 재삽입 횟수와 종료 근거 |
| 힙 | 현재 선택 가능한 후보와 우선순위는 무엇인가? | top을 선택할 자격, 동률 규칙, 갱신으로 낡은 항목을 다루는 방식 |
| 정렬 | 어떤 순서로 바꾸면 필요한 관계가 드러나는가? | 원래 정보 보존, 비교 기준의 일관성, 조사 범위를 줄여도 되는 이유 |
| 완전탐색 | 후보 하나를 어떻게 표현하고 모두 만드는가? | 생성의 완전성과 판정 정확성, 후보·탐색 노드 수 |
| 백트래킹 | 부분 선택에서 다음 선택은 무엇이며 언제 상태를 되돌리는가? | 상태 복원과 가지치기가 정답을 버리지 않는 이유 |
| 그리디 | 지금 선택을 되돌리지 않고 확정할 수 있는가? | 현재 선택을 포함하도록 최적해를 바꿔도 손해가 없는 이유 등 선택 안전성 |
| DP | 같은 상태라면 남은 선택과 그 결과가 정말 같은가? | 상태 충분성, 전이의 완전성, 초기값, 계산 순서 |
| DFS와 BFS | 상태 하나와 이동 하나는 무엇이며 재방문을 구별해야 하는가? | 방문 규칙이 목적에 맞는 이유, BFS 최단거리의 동일 비용 전제 |
| 이분탐색 | 어떤 판정이 어느 방향으로 단조인가? | 경계 의미, 매 갱신에서 답 보존, 구간 감소 |
| 그래프 | 정점·간선·방향·가중치는 현실의 무엇인가? | 표현이 실제 관계를 보존하고 선택한 알고리즘 전제가 맞는가? |

## 5 DP에서도 유지하는 같은 순서

DP라는 분류를 먼저 주어도 점화식부터 외우지 않는다. 목표와 제약을 읽고, 선택을 모두 시도하는 직접 풀이에서 어떤 남은 문제가 반복되는지 찾는다.

1. **상태 의미:** `dp[상태]`는 어떤 상황에서 무엇을 뜻하는가? 최댓값·최솟값·경우의 수·가능 여부를 구별한다.
2. **상태 충분성:** 같은 상태로 합친 과거들은 앞으로 가능한 선택과 비용이 같은가? 위치만 같아도 남은 자원이 다르면 구별이 필요할 수 있다.
3. **전이:** 마지막 선택 또는 다음 선택을 나누면 가능한 경우를 모두 표현하는가? 경우의 수라면 중복 합산은 없는가?
4. **초기 상태:** 아무것도 하지 않은 경우, 시작 상태, 불가능한 상태는 각각 어떤 값인가?
5. **계산 순서:** 참조하는 값이 먼저 올바르게 계산되는가? 한 배열을 재사용할 때 이번 단계의 값과 이전 단계의 값을 섞지 않는가?
6. **최적성:** 같은 상태의 여러 후보 중 하나의 값만 남겨도 미래의 더 좋은 답을 잃지 않는 이유는 무엇인가?
7. **종료와 답:** 무엇이 최종 답의 위치이며, 상태의 계산이 끝나는가?
8. **비용:** 실제 계산하는 상태 수와 상태당 전이·복사·조회 비용은 얼마인가?

이 질문들은 공통 5~6단계를 구체화한다. 상태 의미와 점화식만 적고 초기값·계산 순서·답 위치를 생략하지 않는다. 상태 수가 지수이거나 값 범위에 의존할 수도 있으므로 DP라는 이름만으로 빠르다고 판단하지 않는다.

## 6 고급 문제에서 추가되는 것

고급 문제는 여러 방법의 가정과 상태를 함께 관리해야 할 수 있다. 한 도구의 성질을 전체 풀이의 정답 보장으로 확대하지 않는다.

| 상황 | 기존 틀에서 더 정확히 물을 질문 |
|---|---|
| 단조 스택과 deque | 제거가 답 확정인가 후보 탈락인가? 같은 값과 유효 범위 이탈을 어떻게 처리하는가? |
| 최단경로 | 거리 갱신과 확정은 다른가? 음수 간선 가능성 등 선택한 알고리즘의 전제가 맞는가? |
| 위상 순서와 DP | 선행 의존관계가 모두 처리된 시점은 언제인가? 사이클이 있으면 어떤 의미인가? |
| 구간 자료구조 | 구간의 요약 정보는 무엇인가? 두 구간의 요약을 합쳐 같은 의미를 복원할 수 있는가? 갱신에도 유지되는가? |
| union-find | 대표가 같다는 것이 어떤 관계를 뜻하는가? 합침으로 잃어도 되는 정보는 무엇인가? |
| 이분탐색과 판정 알고리즘 | 판정 자체가 맞는가, 판정 결과가 단조인가를 각각 설명했는가? |
| 여러 상태가 결합된 탐색 | 위치·방향·자원·방문 집합 중 미래 선택을 바꾸는 차이를 빠뜨리지 않았는가? |
| 상태 공간 압축 | 두 상태를 합쳐도 되는 동등성 근거 또는 한 후보가 다른 후보보다 항상 불리한 근거가 있는가? |

“빠르게 하는 도구를 썼다” 뒤에는 그 도구의 상태가 뜻하는 것과 그 상태만으로 충분한 이유가 있어야 한다. 여러 모듈을 연결하면 앞 모듈이 만든 결과가 다음 모듈의 전제를 만족하는지도 확인한다.

## 7 도움을 주고받는 순서

실제 수업에서는 현재 단계의 질문 하나에 먼저 답한다. 피드백은 맞은 근거·빠진 조건·작은 반례를 중심으로 하고, 다음 단계를 통째로 대신 풀지 않는다. 사용자가 통합 설명이나 완성된 작성 예시를 요청하면 그 범위의 설명을 제공하되, 그것을 사용자의 독립 복원 성과로 기록하지 않는다.

코드가 돌아간다는 설명에서 멈추면 “그 판단이 왜 충분한가”를 묻는다. 반대로 올바른 근거가 있는데 표현만 다르면 정해진 문구로 고칠 필요가 없다. 목표는 문장을 외우는 것이 아니라 자신의 풀이를 재구성하고 조건 변경에 대응하는 것이다.
