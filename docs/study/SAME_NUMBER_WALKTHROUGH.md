# 같은 숫자는 싫어 AC 코드에 공통 8단계 적용하기

갱신일: 2026-10-10 Asia/Seoul

이 문서는 작성 예시다. 직접 답할 때는 [공통 빈 양식](../../.md/10-10/COMMON_ANSWER_TEMPLATE.md)을 사용한다. 사용자가 이후 제출한 8단계 답변과 경계 테스트 보고는 [오늘 답변 검토](../../.md/10-10/SAME_NUMBER_REVIEW.md)에 반영했다. 아래 검증 표는 그 추가 보고 이전 상태다.

현재 해설의 대상은 **오른쪽 값과 비교하고 마지막 원소는 무조건 저장하는 최신 AC 코드**다. 사용자가 정확성 17/17·효율성 4/4, 100점을 보고했다. 처음 공유한 왼쪽 비교 코드는 과거 풀이를 참고한 것이었다는 사용자 정정을 반영했다.

이 문서는 AC 뒤의 작성 예시다. 여기서 제공하는 근거를 사용자가 코딩 전에 독립적으로 만들었다고 기록하지 않는다. 공통 틀은 [8단계 작성 가이드](WORKFLOW_GUIDE.md), 실패 이력은 [문제 회고](../../problems/stack_queue/12906_같은_숫자는_싫어/REVIEW.md), 학습 증거는 [세션 기록](../../.md/records/2026-10-10_STACK_QUEUE_SESSION.md)을 따른다.

## 1 목표

**같은 값이 연속된 각 구간에서 대표값 하나씩을 남기고, 구간의 원래 순서대로 반환한다.** `[1,1,3,3,0,1,1]`은 `[1,1] / [3,3] / [0] / [1,1]`의 네 구간이다. 서로 떨어진 1은 다른 구간이므로 각각 남는다. [공식 지문](https://school.programmers.co.kr/learn/courses/30/lessons/12906)

현재 코드는 각 구간의 **마지막 원소**를 대표로 선택한다. 구간 안의 값은 같고 원래 인덱스는 반환하지 않으므로, 첫 원소를 선택하는 방식과 최종 값 배열은 같다.

## 2 제약

`N = arr.size()`, `1 ≤ N ≤ 1,000,000`, `0 ≤ arr[i] ≤ 9`다. N은 원소 개수이며 0~9는 값의 범위다. 값의 종류가 열 개여도 `[0,9,0,9,...]`의 모든 원소가 남을 수 있어 결과 길이는 최대 N이다.

현재 분기에서는 마지막 위치를 먼저 처리하므로 `arr[i+1]`은 i<N−1인 경우에만 읽는다. 원소가 하나일 때에도 마지막 분기로 들어가므로 오른쪽에 접근하지 않는다. 빈 입력은 공식 허용 범위 밖이다.

## 3 예산

최대 입력에서 N²은 10¹², N은 10⁶ 규모다. 한 번의 순회로 구간 끝을 판별할 수 있는지 검토한다. 이 수치는 연산 규모 비교이며 특정 초 단위 시간의 보장은 아니다.

결과가 N개일 수 있으므로 결과 공간 최악 O(N)을 허용해야 한다. 모든 값을 유지해야 하는 입력에서 반환 배열을 항상 상수 크기로 만들 수는 없다.

## 4 직접적인 기준선

원본을 왼쪽부터 본다. 현재 값과 다음 값이 다르면 현재 구간이 끝났으므로 현재 값을 남긴다. 마지막 위치는 다음 값이 없어도 구간의 끝이므로 남긴다. 모두 처리한 answer를 반환한다.

이 직접 풀이가 최종 코드다. 기준선은 올바른 직접 절차이며, 일부러 더 느린 풀이를 만들어야 하는 것은 아니다.

## 5 병목과 설계

매 위치의 질문은 **현재 위치에서 원본의 연속 구간이 끝나는가**다. 마지막이 아니면 오른쪽 값 하나만 비교하면 되고, 마지막이면 반드시 끝난다. 반복 전체 검색이 없어 현재 기준선을 유지한다.

원본 인접 접근과 결과 끝 삽입이면 충분하다. vector가 이 연산과 배열 반환을 지원하므로 별도 stack이나 queue를 선언할 필요는 없다. 구간 대표를 이미 저장했는지 임의로 추측하지 않고 저장 시점을 구간 끝으로 일관되게 둔다.

## 6 선서술과 불변식

**선서술:** 각 위치에서 구간이 끝나는지 확인한다. 끝나지 않았으면 보류하고, 끝났으면 현재 값을 answer에 한 번 추가한다. 마지막 원소도 같은 의미의 구간 끝으로 처리한다.

**불변식:** i번째 반복 직전 answer에는 **원본 전체에서 끝 위치가 i 미만인 연속 구간의 대표값만, 구간당 정확히 하나씩 원래 순서대로** 들어 있다.

앞의 i개 원소를 살펴봤다고 그 접두사의 모든 대표를 이미 저장한 것은 아니다. 접두사 끝의 구간이 원본에서 아직 이어지고 있다면 대표 저장은 대기 중이다. 별도 임시 구간을 저장하지 않아도 원본과 현재 위치로 판단할 수 있다.

- 초기화: i=0이면 끝 위치가 0 미만인 구간이 없고 answer도 비어 있다.
- 오른쪽 값이 같음: i에서 끝나는 구간이 없으므로 아무것도 추가하지 않는다.
- 오른쪽 값이 다름: i에서 구간 하나가 끝나므로 그 대표를 한 번 추가한다.
- 마지막 위치: 원본의 마지막 구간이 반드시 여기서 끝나므로 한 번 추가한다.
- 유지: 위 처리 후에는 끝 위치가 i+1 미만인 모든 구간이 정확히 한 번 저장된다.
- 종료와 답: i=N이면 모든 구간의 끝이 N 미만이므로 answer가 전체 답이다. i가 매번 증가해 N에서 멈추므로 절차도 종료한다.

`[1,1]`에서 i=1 반복 직전 answer는 빈 배열이다. 따라서 이 코드에 “answer는 처리한 접두사를 모두 압축한 결과”라고 쓰면 틀린다. 과거의 왼쪽 비교 코드와 최종 출력은 같지만 저장 시점과 중간 불변식은 다르다.

### 시간과 공간

순회 N회, 인접 비교 N−1회, 결과 추가 K회이며 K는 구간 수다. 정수 vector의 K회 끝 삽입은 재할당을 포함한 총비용이 O(K)이므로 전체 시간은 O(N)이다. 단일 push_back의 최악 비용과 전체 연산열의 비용을 구별한다. [vector 변경 연산](https://eel.is/c++draft/vector.modifiers)

결과는 O(K), 최악 O(N)이다. 입력·결과를 제외한 함수 본문의 지역 상태는 O(1)이다. `vector<int> arr`는 값 인자이므로 호출 시 입력 복사가 발생하면 추가 시간·공간 O(N)을 별도로 포함한다.

## 코드에 주석으로 옮기기

아래 함수의 분기와 비교 방향은 사용자의 최신 AC 코드를 유지했다. 주석은 사후 해설이며 선서술을 실제로 먼저 수행한 증거는 아니다.

```cpp
#include <vector>
using namespace std;

vector<int> solution(vector<int> arr)
{
    // 목표: 각 연속 구간에서 값 하나를 남겨 원래 순서로 반환한다.
    // 제약: 1 <= N <= 1,000,000, 0 <= arr[i] <= 9.
    // 예산과 연산비용: N회 순회, N-1회 인접 비교, K회 끝 삽입.
    //   삽입 총비용을 포함해 시간 O(N), 결과 공간 O(K), K <= N.
    //   본문 지역 상태 O(1), 값 인자 복사가 생기면 별도 O(N).
    // 기준선과 병목: 구간 끝인지 오른쪽 값 하나로 판단한다.
    //   이미 한 번 순회하므로 별도 반복 검색 개선은 필요하지 않다.
    // 선서술: 구간이 끝날 때 대표를 추가하고, 이어지면 보류한다.
    // 불변식: 반복 직전, 끝 위치가 i 미만인 구간들의 대표만 저장했다.
    //   마지막 위치도 반드시 구간 끝이므로 현재 값을 추가한다.
    // 종료: i == N이면 모든 구간의 대표가 들어 있다.
    vector<int> answer;

    for (int i = 0; i < arr.size(); ++i)
    {
        if (i == arr.size() - 1)
        {
            answer.push_back(arr[i]);
        }
        else
        {
            if (arr[i] == arr[i + 1])
            {
                continue;
            }
            else
            {
                answer.push_back(arr[i]);
            }
        }
    }

    return answer;
}
```

코드 주석을 매번 이 길이로 쓸 필요는 없다. 목표·중요 제약·선택 근거·불변식·비용을 짧게 쓰고, 7단계 검증과 8단계 회고는 실행 기록에 둔다. `산술서`라고 적었던 칸은 절차를 먼저 말하는 **선서술**로 이름을 통일하고 산술은 연산비용에 쓴다.

## 8 회고와 다음 출력

재풀이 초안은 중간에서 구간 끝을 고르면서 마지막에서는 왼쪽과 다른 경우에만 저장했다. 마지막 동일 구간이 누락된 원인은 두 분기의 대표 선택 기준이 달랐기 때문이다. 마지막 무조건 추가는 외울 예외가 아니라 **마지막 위치도 구간의 끝**이라는 동일한 규칙이다.

이번에 재사용할 질문은 “나는 대표를 언제 확정하는가?”, “마지막 항목도 같은 의미로 처리하는가?”, “아직 확정하지 않은 항목을 불변식에 어떻게 반영하는가?”다. 한 번의 경계 실수를 모든 문제의 약점으로 일반화하지 않는다.

다음 한 질문은 **`[2,2,5,2,2]`에서 각 반복 직전의 answer를 표로 적어 보라**는 것이다. 사용자가 표를 만든 뒤 그 표를 설명하는 불변식 한 문장으로 이어 간다. 24시간 이상 뒤의 백지 복원과 조건 변경은 별도로 확인하며, 이번 문서를 읽은 것만으로 완료 처리하지 않는다.
