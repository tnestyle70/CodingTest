# 자료구조와 알고리즘의 본질에서 스택과 큐까지

작성일: 2026-10-07 Asia/Seoul

목표는 문제를 읽고 **무엇을 기억할지, 무엇을 다음에 처리할지, 왜 그 절차가 맞는지, 얼마나 드는지**를 자기 말로 설명한 뒤 C++로 구현하는 것이다. 2026-10-02의 통합 사고 과정을 이어받아, 전 유형의 공통 원리를 스택과 큐에 집중해 적용한다.

개념을 확인한 다음 [출력 훈련 질문집](QUESTIONS.md)에서 한 질문씩 답한다. 문제마다 유지할 질문과 코드 주석 틀은 [공통 8단계 작성 가이드](WORKFLOW_GUIDE.md)를 사용하며, 질문의 정본은 [기존 검문소 문서](../../.md/concepts/CHECKPOINT_QUESTIONS.md)다. 설명을 읽은 상태, 도움을 받아 답한 상태, 혼자 복원한 상태를 구별한다. Kit 문제의 완성 풀이와 제출 코드는 여기서 제공하지 않는다.

## 1 문제를 푼다는 것

문제는 허용되는 입력마다 지켜야 할 출력 규칙을 정한다. 코드는 그 규칙을 실행하는 표현이다. 먼저 입출력 사이의 약속을 정확히 만들어야 한다.

예를 들어 정수 목록에서 가장 큰 값을 반환하는 것, 그 값의 첫 위치를 반환하는 것, 그 값이 나온 횟수를 반환하는 것은 다른 문제다. 같은 입력을 받아도 필요한 정보와 갱신 규칙이 다르다. `최대`라는 단어만 보고 풀이를 정할 수 없다.

풀이에는 세 가지 의무가 있다. 허용된 모든 입력에서 요구한 답을 만들고, 처리가 끝나며, 시간과 메모리 제한 안에서 실행되어야 한다. 예제 몇 개가 맞는 것은 확인한 사례에 관한 증거다. 모든 경우의 정확성은 상태와 규칙을 설명하며 별도로 다룬다.

## 2 자료구조의 본질

**자료구조는 정보를 표현하고 배치하여 필요한 연산을 수행할 수 있게 하는 방법이다.** 저장만 하는 상자가 아니다. 어떤 정보를 남기고, 어떤 접근을 허용하며, 그 접근에 얼마가 드는지가 함께 정해진다.

문자열 `민수`를 하나 저장하는 것과 `민수 → 3명`을 저장하는 것은 다른 상태다. 첫 표현은 존재를 알려 주고, 두 번째 표현은 개수까지 알려 준다. 조회 속도가 빨라도 정답에 필요한 정보를 버렸다면 올바른 풀이가 되지 않는다.

### 추상적인 규칙과 실제 구현

스택의 핵심은 최근에 넣고 아직 꺼내지 않은 항목을 먼저 꺼내는 규칙이다. 그 규칙은 배열 끝을 쓰거나 연결된 노드를 써서 구현할 수 있다. 스택이라는 개념과 `std::stack`이라는 C++ 도구를 구분한다.

배열은 연속된 저장 위치를 이용해 인덱스로 접근한다. 연결 리스트는 노드 간 연결을 따라간다. 리스트에서 지울 노드와 필요한 연결을 이미 알고 있다면 삭제 자체는 싸지만, 그 노드를 찾는 일까지 자동으로 싸지는 것은 아니다.

### 연산에서 자료구조로

아래 비용은 원소의 비교·복사 등 기본 처리를 상수 비용으로 보는 대표적인 경우다. 자료구조의 구현과 사용하는 연산에 따라 달라진다.

| 필요한 일 | 후보 | 얻는 이점과 부담 |
|---|---|---|
| i번째 값을 즉시 읽기 | 배열 또는 vector | 인덱스 접근 O(1), 중간 삽입·삭제는 원소 이동이 필요할 수 있음 |
| 작은 정수 키의 개수 조회 | 빈도 배열 | 조회·갱신 O(1), 키 범위 U만큼 O(U) 공간 |
| 키로 존재·개수·집계 조회 | 해시 테이블 | 평균 O(1) 조회, 최악은 저장된 키 수 K에 비례하며 정렬 순서는 제공하지 않음 |
| 키 순서와 조회를 함께 유지 | 균형 탐색 트리 | 조회·갱신 O(log K), 순서 유지 비용을 지불함 |
| 최근에 남은 항목 처리 | 스택 | 한쪽 끝을 사용, 임의 위치 접근은 기본 인터페이스에 없음 |
| 먼저 들어와 대기 중인 항목 처리 | 큐 | 뒤로 넣고 앞으로 꺼냄, 최댓값 자동 선택은 하지 않음 |
| 양쪽 끝을 모두 사용 | deque | 양끝 삽입·삭제 지원, 중간 삭제까지 O(1)인 것은 아님 |
| 변하는 집합의 현재 극값 선택 | 힙 | 극값 조회 O(1), 삽입·추출의 힙 조정 O(log K), 전체 정렬은 아님 |

자료구조 선택은 필요한 연산을 싸게 만드는 선택이다. 가장 복잡한 구조를 고를 필요도, 항상 가장 적은 메모리를 쓰는 표현을 찾아야 할 의무도 없다. **충분한 정보를 유지하며 예산을 만족하는 단순한 표현**이 좋은 출발점이다.

## 3 알고리즘의 본질

**알고리즘은 허용된 입력에서 요구한 출력을 만드는, 명확하고 끝나는 절차다.** 이 문서에서는 종료하는 문제 풀이 알고리즘을 다룬다. 완전탐색도 알고리즘이고, 이미 예산을 만족하는 한 번의 순회도 알고리즘이다.

구체적으로는 다음을 정한다.

1. 상태: 지금까지 무엇을 알고 있는가.
2. 선택: 다음에 어떤 입력이나 후보를 처리하는가.
3. 갱신: 무엇을 확인하고 상태와 답을 어떻게 바꾸는가.
4. 종료: 언제 끝내고 어디에서 답을 읽는가.

자료구조는 이 절차가 쓰는 연산을 뒷받침한다. 같은 큐를 사용해도 갱신 규칙이 다르면 다른 알고리즘이고, 같은 알고리즘의 상태를 배열이나 다른 컨테이너로 구현할 수도 있다.

둘을 잇는 핵심 질문은 **다음 판단을 하려면 과거에서 어떤 정보가 필요한가**이다. 해시에서 이름별 남은 개수가 필요했다면, 스택과 큐에서는 남은 항목의 처리 순서가 중요해질 수 있다.

## 4 상태가 충분한지 판단하기

상태는 과거를 요약한 것이다. 요약이 충분하려면 이후의 판단에 필요한 차이를 남겨야 한다.

지금까지 본 최댓값만 묻고 앞으로는 값의 추가만 허용된다고 하자. 과거가 `[2, 9]`든 `[7, 9]`든 현재 최댓값은 9다. 이후 같은 값을 추가하면 최댓값을 같은 규칙으로 갱신할 수 있으므로 이전의 모든 값을 보관할 필요가 없다.

규칙에 현재 최댓값 하나를 삭제하는 연산을 추가하면 상황이 달라진다. 두 과거를 모두 `최댓값 = 9`로 저장했지만 삭제 뒤 답은 각각 2와 7이다. **같은 상태로 합친 두 과거에 같은 후속 연산을 했더니 필요한 답이 달라졌다.** 최댓값 하나로는 충분하지 않다는 반례다.

이때 곧바로 힙을 정답으로 확정하지 않는다. 삭제 방식, 추가 여부, 전체 조회 횟수, 입력 규모를 확인한 뒤 배열 재검색·정렬·힙·트리 등을 비교한다.

### 무엇을 저장할지

| 출력 또는 다음 판단에 필요한 정보 | 저장을 검토할 내용 |
|---|---|
| 항목의 크기만 필요 | 값 |
| 원래 어느 항목인지 필요 | 인덱스 또는 고유 ID |
| 몇 칸 떨어져 있는지 필요 | 위치 |
| 언제 시작하거나 끝났는지 필요 | 시각 또는 사건 정보 |
| 같은 값이 몇 번 있는지 필요 | 빈도 |
| 순서대로 무엇이 남았는지 필요 | 순서를 보존하는 항목열 |

값이 같아도 위치가 다르면 서로 다른 항목일 수 있다. 원본 배열이 유지된다면 인덱스만 저장하고 값을 원본에서 읽을 수도 있다. 어떤 정보를 다른 곳에서 다시 얻을 수 있는지도 판단한다.

## 5 공통 8단계를 산출물로 바꾸기

| 단계 | 내가 만들 산출물 | 막혔을 때 할 행동 |
|---|---|---|
| 1 목표 | 입력·출력·순서·동률 규칙을 담은 문장 | 작은 입력에 직접 답을 붙인다 |
| 2 제약 | N·값 범위·중복·순서·보장 조건 | 개수와 값의 크기를 따로 적는다 |
| 3 예산 | 후보 비용을 최대 입력에 대입한 수치 | N²과 N log N의 규모를 비교한다 |
| 4 기준선 | 끝까지 실행 가능한 직접 풀이와 비용 | 손으로 한 행동을 동사와 반복으로 적는다 |
| 5 병목과 개선 | 반복되는 질문·남길 정보·처리 순서 | 어떤 결과를 매번 다시 구하는지 찾는다 |
| 6 선서술 | 상태 뜻·초기화·갱신·종료·정확성·비용 | 한 번 갱신 전후를 표로 그린다 |
| 7 검증 | Build·Example·Edge·Judge의 실제 결과 | 실행하지 않은 것은 미실시로 남긴다 |
| 8 회고 | 실패 가정·적용 조건·반례·도움 정도 | 다음날 코드 없이 풀이를 복원한다 |

3단계의 비용은 설계 목표이고, 6단계의 비용은 실제로 만든 절차의 분석이다. 기준선은 정확한 직접 풀이면 된다. 처음부터 효율적이어도 괜찮다. 생각은 앞뒤로 이동할 수 있지만 코딩 전에는 출력까지의 연결을 말할 수 있어야 한다.

## 6 스택의 본질

**스택은 남아 있는 항목 중 가장 나중에 넣은 항목을 다음 대상으로 정한다.** LIFO라는 이름보다 이 문장이 문제 규칙에 맞는지 확인하는 일이 중요하다.

작업 A를 시작한 뒤 A를 멈추고 B를 시작하고, B를 멈추고 C를 시작했다고 하자. 현재 작업을 끝내면 가장 최근에 멈춘 작업으로 돌아가야 하는 규칙이라면 C 다음 B, 그다음 A로 돌아간다. 아직 돌아가야 할 대상을 역순으로 보존해야 한다.

스택의 위쪽 끝을 top이라고 하자. 아래 표에서는 오른쪽이 top이다.

| 연산 | 연산 뒤 상태 | 꺼낸 항목 |
|---|---|---|
| push(A) | `[A]` | 없음 |
| push(B) | `[A, B]` | 없음 |
| pop | `[A]` | B |
| push(C) | `[A, C]` | 없음 |
| pop | `[A]` | C |

여기서 top은 마지막으로 읽은 입력과 같지 않을 수 있다. C가 제거된 후 남은 top은 A다. 삭제를 포함한 문제에서 입력의 바로 이전 원소와 현재 남은 마지막 원소를 구별해야 한다.

스택의 제약 덕분에 다음 항목을 다시 검색하지 않고 top에서 읽는다. 다만 **왜 top만 확인해도 충분한지**는 문제의 규칙으로 증명해야 한다. 스택을 선언했다는 사실이 그 증명을 대신하지 않는다.

## 7 큐의 본질

**큐는 남아 있는 항목 중 가장 먼저 들어온 항목을 다음 대상으로 정한다.** FIFO 규칙이며, 보통 뒤에 넣고 앞에서 꺼낸다.

아래 표는 왼쪽이 front, 오른쪽이 back이다. 같은 연산열을 스택 표와 비교하면 저장한 값이 같아도 꺼내는 순서가 달라짐을 볼 수 있다.

| 연산 | 연산 뒤 상태 | 꺼낸 항목 |
|---|---|---|
| push(A) | `[A]` | 없음 |
| push(B) | `[A, B]` | 없음 |
| pop | `[B]` | A |
| push(C) | `[B, C]` | 없음 |
| pop | `[C]` | B |

중간 항목이 더 급하다고 해서 기본 큐가 그 항목을 찾아 먼저 꺼내 주지는 않는다. 먼저 대기한 순서, 현재 우선순위, 도착 시각은 서로 다른 정보다. 문제에서 실제로 다음 대상을 결정하는 규칙을 먼저 찾는다.

꺼낸 항목을 다시 뒤에 넣으면 새로운 대기 위치가 생긴다. 따라서 항목 N개라는 사실만으로 pop 횟수가 N번이라고 할 수 없다. 재삽입 횟수와 종료 조건을 따로 설명해야 한다.

### 큐를 배열로 구현할 때

vector의 첫 원소를 매번 지우면 뒤의 원소를 이동시키는 비용이 생긴다. 앞 위치를 가리키는 인덱스만 증가시키는 방식도 FIFO를 구현할 수 있다. 이때 논리적으로 제거한 공간이 자동 반환되는 것은 아니며, 장시간 계속 쌓이는 입력에서는 메모리 관리가 별도 문제가 된다. 원형 버퍼는 저장 공간을 재사용하는 구현 방법이다.

## 8 제거는 정보가 사라지는 결정

항목을 꺼내거나 버릴 때에는 어떤 의미인지 설명한다.

- 처리 완료: 해당 항목의 일을 끝냈다.
- 답 확정: 해당 항목의 답이 결정되어 답 저장소에 반영했다.
- 후보 탈락: 앞으로 어떤 입력이 와도 정답에 기여하지 않는다는 근거가 있다.
- 위치 이동: 항목이 다른 상태나 대기열로 옮겨 갔다. 처리 완료와 구별한다.

처리 저장소에서 제거했어도 결과나 다른 상태에는 정보가 남을 수 있다. 제거 후 무엇이 보존되는지까지 확인한다. 이해가 불확실하면 제거할 항목이 나중에 다시 필요해지는 작은 후속 입력을 만들어 본다.

## 9 불변식과 종료로 정확성 설명하기

불변식은 **반복의 특정 지점마다 항상 성립하도록 유지하는 상태의 뜻 또는 성질**이다. 반복 직전인지 직후인지 기준 시점을 고정한다.

예를 들어 입력을 왼쪽부터 읽으며 합을 누적한다면, `i개 처리 직후 sum은 앞 i개 값의 합이다`라고 말할 수 있다.

1. 초기화: 0개를 처리했을 때 합 0으로 시작하므로 뜻이 맞다.
2. 유지: 다음 값 x를 더하면 앞 i+1개 값의 합이 된다.
3. 종료와 답: N개를 처리하면 전체 합이므로 sum을 반환한다.
4. 종료 근거: 매번 처리한 개수가 1 증가하고 N을 넘겨 반복하지 않는다.

스택·큐에서는 들어 있는 항목의 자격과 순서를 함께 설명한다. `미처리 항목이 있다`만으로는 내용이 충분하지 않을 수 있다. 무엇이 미처리인지, 누락이 없는지, 제거된 항목은 왜 다시 필요 없는지, top/front가 왜 다음 대상인지 연결한다.

큐 크기가 줄어야만 종료하는 것은 아니다. 새 항목을 넣으면 늘 수도 있다. 한정된 상태를 중복 처리하지 않는지, 처리할 총 사건 수가 유한한지 등 실제 알고리즘의 진행 근거를 찾는다.

## 10 시간과 공간을 세는 방법

**전체 시간 = 전처리 + 각 연산의 실행 횟수 × 한 번의 비용을 모두 더한 값 + 후처리**로 시작한다. N은 입력 개수, K는 현재 저장된 항목 수, L은 문자열 길이처럼 변수를 먼저 정의한다.

O 표기는 입력 크기에 따른 성장의 상한을 나타낸다. O(N)이 정확히 N번이라는 뜻은 아니다. N=10,000일 때 순회 두 번이면 약 20,000회라는 수치와 O(N)이라는 성장률을 구별한다. 관례상 가능한 한 의미 있는 좁은 상한을 쓴다.

| 코드의 실제 동작 | 총비용 |
|---|---|
| N개 순회 후 다시 N개 순회 | O(N+N)=O(N) |
| N개 각각에 대해 N개를 전부 확인 | O(N²) |
| 길이 N 배열 앞 삭제를 전부 소진할 때까지 반복 | 이동량의 합이 O(N²) |
| 각 항목을 한 번 넣고 최대 한 번 빼며 나머지 처리도 항목당 O(1) | 전체 O(N) |
| 큐 연산을 총 R번 수행 | 연산당 O(1)이면 O(R), R을 N으로 제한하는 근거는 별도로 필요 |

### 중첩 반복과 상환 분석

전체 N개 항목을 각각 최대 한 번 넣고 제거된 항목을 다시 넣지 않는다면, 안쪽 반복이 한 번에 여러 항목을 제거하더라도 총 제거는 최대 N번이다. 각 항목에 입장권과 퇴장권을 하나씩 준다고 생각하면 전체 push와 pop을 셀 수 있다. 바깥 반복 N회의 조건 검사 등 나머지 작업도 함께 센다.

이는 임의의 입력에 대한 전체 비용을 제한하는 논증이다. 좋은 입력이 많이 나온다는 평균 분석과 다르다. 항목을 계속 재삽입하는 절차나, 제거할 때마다 큰 배열을 복사하는 절차에는 이 결론을 그대로 적용할 수 없다.

### 시간의 축과 입력의 축

N개의 사건을 처리해도 매 시각을 하나씩 진행하면 마지막 시각 T에 비용이 의존할 수 있다. 사건이 없는 시간 동안 출력과 상태가 어떻게 변하는지 확인해야 다음 사건 시각으로 건너뛸 수 있다. 중간 상태에 대한 질문이 있거나 시각마다 변화가 있다면 생략에 추가 근거가 필요하다.

### 공간과 정수 범위

공간은 동시에 살아 있는 입력 복사·보조 컨테이너·결과·재귀 호출을 센다. 결과 배열을 제외한 보조 공간인지 포함한 전체 공간인지 적는다. 인덱스 하나로 충분한데 값과 큰 객체를 모두 복사하면 추가 비용이 생긴다.

최대 N과 값의 크기 U는 다르다. 합은 대략 N×U까지 커질 수 있고, 곱셈은 대입되는 변수보다 계산에 쓰이는 피연산자의 타입이 중요하다. 넓은 변수에 저장하는 것만으로 앞선 좁은 타입 연산의 오버플로가 해결되지 않는다.

## 11 C++ 도구와 개념 연결하기

`std::stack<T>`와 `std::queue<T>`는 기본적으로 deque를 내부 컨테이너로 사용하는 어댑터다. 필요한 연산을 제한해서 보여 준다. stack의 `top()`은 마지막 항목을, queue의 `front()`는 첫 항목을 읽는다. 둘 다 `push()`로 삽입하고 `pop()`으로 제거한다. **pop은 값을 반환하지 않는다.** 값을 사용할 때는 제거 전에 별도 값으로 읽어 둔다. [C++ stack 정의](https://eel.is/c++draft/stack), [C++ queue 정의](https://eel.is/c++draft/queue)

```cpp
#include <stack>
#include <queue>

std::stack<int> s;
s.push(10);
if (!s.empty()) {
    int value = s.top();
    s.pop();
    // value는 복사한 값이므로 제거 후에도 사용할 수 있다.
}

std::queue<int> q;
q.push(20);
if (!q.empty()) {
    int value = q.front();
    q.pop();
}
```

위 코드는 API의 최소 사용 예다. 실제 문제에서 넣고 빼는 조건은 직접 도출해야 한다. 빈 컨테이너의 top/front/pop을 호출하지 않도록 한다. `auto& value = s.top()`처럼 원소 참조를 잡은 뒤 그 원소를 제거하면 그 참조를 계속 사용할 수 없다.

정수 같은 상수 비용 원소를 기본 deque로 저장할 때 양끝 한 항목 삽입·삭제는 O(1)로 분석한다. vector를 스택처럼 사용하면 `push_back`은 상환 O(1), 재할당하는 단일 호출은 O(K)일 수 있다. vector 앞 삭제는 뒤 원소를 이동시킨다. [deque 변경 연산](https://eel.is/c++draft/deque.modifiers), [vector 변경 연산](https://eel.is/c++draft/vector.modifiers)

## 12 스택과 큐에서 더 나아가기

### 단조 스택

일반 스택의 LIFO 규칙에 값의 단조로운 순서 같은 불변식을 추가한 것이다. 자료를 넣을 때 일부 항목을 제거하여 원하는 순서를 유지한다.

단조라는 모양만 맞추면 되는 것이 아니다. 어떤 비교에서 제거할지, 제거가 답 확정인지 후보 탈락인지, 같은 값은 어떻게 취급할지, 끝까지 남은 항목은 무슨 뜻인지를 문제별로 증명한다. 특히 `<`와 `<=` 중 무엇이 맞는지는 출력의 정의에 따라 다르다.

### 두 스택으로 큐 만들기

두 스택을 이용하면 FIFO를 구현할 수 있다. 심화 연습에서는 어디에 새 항목을 넣고 언제 다른 쪽으로 옮길지 직접 설계한다. 정확성은 앞으로 꺼낼 전체 순서로, 비용은 원소 하나가 각 저장소 사이를 이동하는 총횟수로 설명한다. 단일 호출 비용과 전체 연산열의 비용이 다를 수 있음을 훈련한다.

### 사건 시뮬레이션

시뮬레이션은 규칙을 상태 갱신으로 옮기는 알고리즘이다. 시각 t의 상태가 사건 처리 전인지 후인지 정해야 한다. 같은 시각에 완료·도착·선택이 있다면 지문에 맞는 순서를 명시하고 작은 표로 확인한다.

규칙상 하나만 처리할 수 있을 때와 조건을 만족하는 항목을 모두 처리해야 할 때를 구별한다. `if`와 `while` 선택을 문법 취향으로 정하면 필요한 상태 갱신을 빠뜨릴 수 있다.

### BFS와 큐

BFS는 발견한 상태를 FIFO로 확장하여 이동 횟수의 층을 순서대로 탐색한다. 모든 간선 비용이 같은 양수인 경우 이 순서로 첫 발견 거리가 최단임을 설명할 수 있다. 단순히 큐가 있다는 이유로 가중치가 제각각인 경로의 최소 비용까지 보장되지는 않는다.

## 13 고득점 Kit 전체를 읽는 공통 지도

분류의 층위가 다르다. 해시·스택·큐·힙은 주로 자료구조이고, 그리디·DP는 설계 방식이며, DFS/BFS는 탐색 절차이고, 그래프는 관계를 표현하는 모델이다. 한 문제에 여러 방법이 함께 들어간다.

| 유형 | 줄이거나 체계화하는 일 | 반드시 만들 근거 | 흔한 실패 |
|---|---|---|---|
| 해시 | 같은 키를 찾는 반복 검색 | 키의 의미와 키별 상태가 충분함 | 존재만 저장해 중복 수를 잃음 |
| 스택과 큐 | 다음 처리 대상을 찾는 일 | 다음 대상이 최근 또는 먼저 남은 항목임 | 이전 입력과 현재 남은 항목을 혼동 |
| 힙 | 변하는 후보 집합의 극값 검색 | 저장된 후보의 자격과 비교 기준 | 현재 선택 자격을 확인하지 않고 극값을 선택함 |
| 정렬 | 비교할 관계와 처리 순서 정리 | 정렬 뒤 줄인 조사 범위가 충분함 | 동률 기준 또는 원래 위치를 잃음 |
| 완전탐색 | 후보를 빠짐없이 생성 | 모든 정답 후보가 생성되고 판정이 맞음 | 후보 수와 후보 검사 비용을 혼동 |
| 그리디 | 선택을 즉시 확정해 탐색 축소 | 현재 선택과 양립하는 최적해가 존재함 | 당장 좋아 보인다는 이유로 확정 |
| DP | 같은 부분 문제의 반복 계산 | 상태 충분성·전이의 완전성·계산 순서 | 같은 위치라는 이유로 다른 상태를 합침 |
| DFS와 BFS | 상태와 이동의 탐색 순서 | 방문 상태의 정의와 재방문 규칙 | 경로별 자원 차이를 무시 |
| 이분탐색 | 답 후보 구간을 한 번에 축소 | 올바른 단조 판정·경계 유지·구간 감소 | 가능한 값의 경계를 갱신 중 버림 |
| 그래프 | 관계를 정점과 간선으로 표현 | 실제 관계와 표현이 대응하고 알고리즘 전제가 맞음 | 방향·가중치·간선 수 누락 |

그리디는 안전한 선택을 증명하는 방식이다. `{1, 3, 4}` 동전으로 6을 만들 때 가장 큰 것부터 고르면 3개, 3을 두 번 쓰면 2개다. 큰 값을 먼저 고르는 규칙이 언제나 최적은 아니라는 반례다.

DP는 같은 남은 문제의 답을 다시 사용한다. 같은 위치라도 남은 연료가 다르면 앞으로 할 수 있는 일이 달라질 수 있다. 이 둘을 하나의 상태로 합치기 전에 미래의 선택과 결과가 같다고 할 근거가 필요하다.

이분탐색은 중간을 고르는 기술에 더해 한쪽 구간을 버릴 논리가 필요하다. 판정이 `불가능, 불가능, 가능, 가능`처럼 단조라면 경계를 찾을 수 있다. `가능, 불가능, 가능`이라면 같은 제거 논리를 적용할 수 없다.

그래프는 관계 표현이고, 탐색 목적에 따라 절차를 고른다. 인접 리스트로 각 정점과 간선을 한 번씩 처리하면 O(V+E)지만, 모든 경로를 열거하는 문제는 경로 수가 매우 많을 수 있어 같은 비용식을 사용할 수 없다.

다른 유형에서도 **어떤 정보를 유지하고 어떤 작업을 생략하며 그 생략이 왜 안전한지**를 묻는다. 완전탐색처럼 생략 없이 푸는 절차라면 후보 생성의 완전성과 비용을 설명한다.

## 15 답을 만드는 연습

매 질문에서 설명을 읽기 전에 문장·추적표·의사코드·반례 중 지정된 산출물을 만든다. 막혔을 때는 입력을 줄이고 손으로 수행한 동작을 적는다. 그다음 반복되는 판단, 필요한 정보, 처리 순서로 올라간다.

답변을 평가할 때에는 맞은 결론 외에 근거, 빠진 경계, 도움 정도를 남긴다. 하루 이상 뒤에는 설명과 코드를 가리고 같은 논리를 복원한다. 낯선 조건 변경에서도 적용 조건과 실패 조건을 구별하면 다음 문제로 옮겨 갈 준비가 된 것이다.

**코딩 전 내가 말할 문장:** 입력에서 ___를 구한다. 직접 하면 ___를 반복한다. 그중 ___가 비싸므로 ___를 유지한다. 다음에는 ___를 처리한다. ___가 항상 성립하도록 갱신한다. 종료하면 ___가 답이다. 전체 연산은 ___번이고 한 번에 ___가 들므로 시간은 ___, 보조 공간은 ___다.
