# 자료구조와 알고리즘을 직접 설명하는 100문항

작성일: 2026-10-07 Asia/Seoul

최종 검토: 2026-10-10 Asia/Seoul

매 문제에 적용하는 순서는 기존 검문소 정본을 따르는 [공통 8단계 작성 가이드](WORKFLOW_GUIDE.md)로 유지한다. 이 질문집은 그중 필요한 능력을 따로 연습하는 자료다.

이 질문집은 [자료구조와 알고리즘의 본질에서 스택과 큐까지](ESSENCE_AND_STACK_QUEUE.md)를 읽은 내용을 **문장, 손추적표, 반례, 의사코드, 비용식**으로 바꾸는 연습이다. 정답을 읽고 이해하는 것과 혼자 만드는 것을 구별한다. Kit 문제의 완성 풀이와 제출 코드는 포함하지 않는다.

한 번에 **질문 하나**에 답한다. 100문항을 모두 끝낸 뒤 Kit를 시작하는 방식이 아니다. 아래 첫 경로에서 기초를 확인한 뒤 첫 문제로 들어가고, 막힌 지점에 해당하는 질문으로 돌아온다. A부터 H까지 각 10문항, Kit 지문 해석 K 12문항, 백지 평가 X 8문항으로 총 100문항이다.

## 사용 규칙과 첫 진입 경로

모든 배열과 문자열의 위치는 별도 설명이 없으면 0부터 센다. 스택은 왼쪽이 bottom, 오른쪽이 top이고, 큐는 왼쪽이 front, 오른쪽이 back이다. `pop`은 제거 동작이며, 제거한 값을 요구하면 제거 전에 읽었다고 가정한다. 각 문항의 비용은 별도 조건이 없으면 정수 하나의 읽기·비교·복사·덧셈을 O(1)로 센다.

첫 경로는 **A01 → A03 → A08 → B01 → B05 → C01 → C02 → D01 → E01 → F01**의 10문항이다. 답의 길이를 늘리기보다 요구한 산출물을 빠짐없이 만든다. 이후 **같은 숫자는 싫어 지문 → K01과 K02 → 공통 8단계**로 진행한다. 이미 설명할 수 있는 문항은 짧게 확인하고 넘어간다.

| 단계 | 통과를 판단할 증거 |
|---|---|
| 첫 Kit 진입 | 반환 규칙을 자기 말로 쓰고, 스택·큐의 같은 연산열을 구별하며, 간단한 비용과 경계를 설명한다 |
| 독립 구현 진입 | 작은 입력의 손추적, 올바른 기준선, 상태 뜻, 갱신과 종료를 코드 없이 설명한다 |
| 스택과 큐 기본 이해 | 값과 위치, 입력 순서와 현재 남은 순서, 제거와 완료를 구별하며 빈 상태와 동률을 다룬다 |
| 심화 진입 | 한 번 비용과 전체 횟수를 분리하고, 상태 유지와 제거의 근거를 자기 말로 설명한다 |
| 독립 복원 확인 | 24시간 이상 뒤 설명과 코드를 가리고 복원한 다음, 조건이 바뀌었을 때 기존 근거가 유효한지 판단한다 |

통과 기준은 문항 전부의 완료율이 아니다. 특정 근거가 빠졌다면 그 부분을 다루는 문항으로 돌아가 보완한다. 답을 읽고 바로 따라 말한 경우는 독립 통과로 기록하지 않는다.

## 답의 품질과 도움 정도

| 품질 | 판정 기준 |
|---|---|
| 0 | 산출물이 없거나 문제 규칙과 충돌한다 |
| 1 | 결론은 있으나 추적·상태·근거 중 필요한 부분이 빠져 있다 |
| 2 | 요구 산출물을 완성하고 상태 변화와 결론을 연결한다 |
| 3 | 요구 산출물에 더해 경계 또는 조건 변경으로 설명을 점검하고 필요한 수정을 할 수 있다 |

품질과 별도로 도움을 **독립 / 질문 재진술 / 작은 예시 / 핵심 단서 / 해설 참고** 중 실제 받은 수준으로 기록한다. 정답을 설명받은 뒤 높은 품질의 답을 만든 것은 학습 성과이지만 독립 생성과 같은 증거는 아니다. 아직 답하지 않은 문항의 품질은 미평가로 둔다.

막히면 입력을 2~4개로 줄여 손으로 실행하고, 손이 한 일을 동사로 적는다. 그다음 필요한 정보와 반복 횟수를 찾는다. 이 과정에서도 막히면 현재 막힌 한 부분만 도움받고 도움 정도를 남긴다.

## A 입출력과 본질

### A01 같은 입력의 다른 출력

입력 `[4, 7, 7, 2]`에 대해 요구가 각각 최댓값, 최댓값의 첫 위치, 최댓값의 등장 횟수라고 하자. 세 문제의 반환 규칙은 어떻게 다른가?

**산출물:** 요구별 반환값과 반환 규칙을 담은 문장 세 개.

### A02 동률과 원래 순서

기록이 `[(A, 8), (B, 10), (C, 10), (D, 5)]`다. 점수 높은 순서로 두 ID를 반환하고, 점수가 같으면 입력에서 먼저 나온 기록을 앞에 둔다. 어떤 조건을 놓치면 다른 답이 나오는가?

**산출물:** 반환 ID 목록과 개수·정렬 기준·동률 기준을 포함한 출력 계약.

### A03 저장 규칙과 해결 절차

쟁반을 A, B, C 순서로 쌓고 위에서만 꺼낼 수 있다. 할 일은 세 쟁반을 모두 꺼내며 ID를 기록하는 것이다. 이 상황에서 자료구조가 정하는 것과 알고리즘이 정하는 것은 각각 무엇인가?

**산출물:** 자료구조의 연산 규칙 두 문장과 시작부터 종료까지의 절차.

### A04 답과 종료를 구별하기

목표는 정수 `x=2`에서 출발하여 0을 반환하는 것이다. 후보 절차는 `x가 0이 아닌 동안 x를 1 증가시키고, 반복이 끝나면 x를 반환한다`다. 정수 범위가 무한하다고 가정할 때 이 절차의 어떤 의무가 충족되지 않는가?

**산출물:** 처음 네 번의 상태 변화와 종료를 포함해 수정한 절차.

### A05 개수와 값 범위와 길이

이름이 최대 2,000개이고 각 이름 길이는 최대 30자다. 각 이름에는 0~9의 등급 하나가 붙는다. `N`, `L`, `U`를 각각 정의하고 배열 길이, 문자열 비교, 등급별 빈도 저장에 어느 변수가 관련되는지 구별하라.

**산출물:** 세 변수의 정의와 각 연산에 연결한 짧은 설명.

### A06 존재와 개수

명단 `['민수', '민수', '지수']`에 대해 질문이 “민수가 있는가?”일 때와 “민수가 몇 명인가?”일 때를 비교하라. 중복 이름을 한 개만 남겨도 되는지 각각 판단하라.

**산출물:** 두 질문의 답과 버려도 되는 정보·남겨야 하는 정보.

### A07 같은 상태와 다른 알고리즘

정수 큐 `[2, 5, 1]`을 사용한다. 절차 P는 앞에서 하나씩 꺼내 합을 반환하고, 절차 Q는 앞에서 하나씩 꺼내 최댓값을 반환한다. 컨테이너가 같다는 사실만으로 두 풀이를 같은 알고리즘이라고 할 수 있는가?

**산출물:** P와 Q의 상태·갱신·반환 규칙을 나란히 적은 설명.

### A08 필요한 접근부터 말하기

대기 항목은 A, B, C 순서로 들어왔고 우선순위는 각각 2, 9, 5다. 규칙이 각각 가장 최근 항목, 가장 먼저 들어온 항목, 현재 최고 우선순위 항목, ID가 B인 항목을 요구할 때 다음 대상과 필요한 접근은 무엇인가?

**산출물:** 네 규칙별 대상·필요한 연산·후보 자료구조를 연결한 목록.

### A09 추상 규칙과 구현

스택 S1은 배열의 끝을, S2는 연결된 노드의 맨 앞을 사용한다. 두 스택 모두 `push A, push B, pop`을 실행한다. 관찰 가능한 결과가 같아야 하는 부분과 구현에 따라 달라도 되는 부분은 무엇인가?

**산출물:** 공통 연산 결과와 메모리·비용을 비교할 때 확인할 조건 두 개.

### A10 사고 과정의 산출물

문제는 `[3, -1, 4]`의 모든 값을 더해 반환하는 것이며 길이는 1~100,000이다. 목표, 제약, 예산, 기준선, 병목 검토, 선서술, 검증, 회고에 각각 무엇을 남길지 적어라. 개선할 필요가 없다고 판단해도 근거를 남겨라.

**산출물:** 8단계별 한 줄 기록; 실행하지 않은 검증은 미실시 표시.

## B 손추적과 상태 충분성

### B01 한 번의 상태 변화

`[3, -1, 4]`를 왼쪽부터 읽고 `sum=0`에 현재 값을 더한다. 0개 처리 직후부터 마지막 처리 직후까지 sum의 의미와 값을 추적하라.

**산출물:** 처리 개수·읽은 값·sum을 적은 표와 상태 의미 한 문장.

### B02 동률에 필요한 기억

`[5, 9, 9, 2]`에서 최댓값이 처음 나온 위치를 반환한다. 다음 값을 읽을 때마다 무엇을 기억하고 어떤 경우에 갱신할지 직접 정하라.

**산출물:** 선택한 상태 필드와 네 입력을 처리하는 추적표.

### B03 합만으로 충분한가

과거 P는 `[1, 5]`, Q는 `[2, 4]`다. 저장 상태는 `(원소 수, 합)`뿐이고, 이후 요청은 현재 최댓값 반환이다. 두 과거가 같은 상태로 표현되는지와 요청을 구별할 수 있는지 확인하라.

**산출물:** 두 상태와 두 요청 결과를 비교하고 정보 손실을 설명한 문장.

### B04 연산이 바뀌면 상태도 바뀌는가

과거 P는 `[2, 8]`, Q는 `[6, 8]`다. 현재 최댓값 하나만 저장하고 있다. 두 과거에 동일하게 `현재 최댓값 한 개 삭제 → 남은 최댓값 요청`을 수행하라. 추가만 허용하는 경우와 무엇이 달라지는가?

**산출물:** 두 과거의 후속 결과와 현재 상태의 충분성을 판정한 근거.

### B05 이전 입력과 남은 항목

빈 스택에 `push 4, push 7, pop, push 5, pop`을 실행한다. 마지막 시점의 가장 최근 삽입 값, 가장 최근 제거 값, 현재 top은 같은가?

**산출물:** 연산별 스택과 마지막 시점의 세 정보를 구별한 기록.

### B06 같은 값의 다른 항목

대기열에 `(ID=A, 값=5)`와 `(ID=B, 값=5)`가 이 순서로 들어왔다. 첫 항목을 처리한 뒤 B가 남아 있는지 답해야 한다. 값 5의 존재 여부만 저장하면 충분한가?

**산출물:** 처리 전후 상태와 항목의 정체성을 유지할 표현.

### B07 인덱스에서 값을 복원하기

원본 배열은 `[8, 3, 8]`이고 보조 저장소에는 인덱스 `[0, 2]`가 있다. 원본이 변하지 않을 때 어떤 정보를 복원할 수 있는가? 이후 `원본[2]=1`이 허용되고 과거의 값을 물으면 같은 표현이 충분한가?

**산출물:** 두 조건에서 복원 가능한 정보와 부족해지는 정보.

### B08 과거 두 개를 직접 만들기

저장 상태는 지금까지 등장한 서로 다른 문자들의 집합이다. 문자는 A와 B뿐이며 이후 요청은 A의 총 등장 횟수다. 같은 상태가 되지만 요청 결과는 다른 길이 1~4의 과거 두 개를 만들어라.

**산출물:** 두 입력·저장 상태·다른 정답으로 이루어진 반례.

### B09 손의 행동을 절차로 바꾸기

빈 문자열에서 문자 명령은 맨 뒤에 문자를 붙이고 `BACK`은 맨 뒤 문자 하나를 지운다. 빈 문자열에서 BACK은 아무 일도 하지 않는다. `A, B, BACK, C, BACK, BACK, BACK`을 실행하라.

**산출물:** 명령별 문자열 상태와 그대로 실행 가능한 의사코드.

### B10 제거와 처리 완료

대기열 `[A, B]`에서 A를 꺼냈지만 작업을 끝내지 못해 맨 뒤에 다시 넣었다. 다음으로 B를 꺼내 완료하고 완료 목록에 넣었다. “큐에서 꺼낸 수”와 “완료한 수”를 같은 변수로 세어도 되는가?

**산출물:** 대기열·완료 목록·두 횟수를 구분한 두 단계 추적표.

## C 스택과 큐와 deque의 순서

### C01 스택의 연산열

빈 스택에 `push A, push B, top 조회, pop, push C, pop, pop`을 적용하라. 조회는 상태를 바꾸지 않는다.

**산출물:** 매 연산 후 상태와 조회·제거된 항목; 유효성 확인.

### C02 큐의 연산열

빈 큐에 `push A, push B, front 조회, pop, push C, pop, pop`을 적용하라. C01과 같은 위치의 연산 결과가 어디서 달라지는가?

**산출물:** 매 연산 후 상태와 조회·제거된 항목, C01과의 차이.

### C03 중단된 작업으로 돌아가기

A를 수행하다 중단하고 B를 시작했으며, B를 중단하고 C를 시작했다. 현재 작업이 끝나면 가장 최근에 중단한 미완료 작업을 재개한다. 새 작업은 더 생기지 않는다. C 완료부터 전체 완료까지 무엇을 기억해야 하는가?

**산출물:** 재개 순서와 보존할 항목의 의미 및 후보 자료구조의 선택 이유.

### C04 같은 시각의 접수 순서

시각 0에 A와 B가 이 순서로 도착하고, 시각 1에 C가 도착한다. 매 정수 시각마다 먼저 도착자를 뒤에 넣은 뒤 가장 오래 기다린 항목 하나를 즉시 완료한다. 시각 0~2를 실행하라.

**산출물:** 시각별 도착·대기열·완료 항목 표.

### C05 양쪽 끝을 사용하는 연산열

빈 deque에 `push_back A, push_front B, push_back C, pop_front, push_front D, pop_back`을 적용한다. 왼쪽을 front로 표시하라.

**산출물:** 각 연산 후 deque와 제거 항목의 추적표.

### C06 중간 항목을 지우라는 요구

스택의 bottom→top 상태가 `[A, B, C]`다. 요청은 B만 제거하고 A와 C의 상대 순서를 보존하는 것이다. 기본 스택 인터페이스만으로 B를 즉시 직접 지울 수 있는가? 허용되는 임시 저장을 사용한다면 어떤 일이 추가되는가?

**산출물:** 직접 지원되는 연산과 추가로 필요한 동작을 구분한 설명.

### C07 재삽입되는 항목

큐는 `[(A, 남은 작업=2), (B, 1), (C, 2)]`다. 매 단계 front를 꺼내 남은 작업을 1 줄이고, 양수면 뒤에 다시 넣고 0이면 완료한다. 새 항목은 없다.

**산출물:** 종료까지의 대기열·완료 목록·총 제거 횟수 추적표.

### C08 deque로 규칙을 표현하기

빈 deque에 A, B, C를 이 순서로 저장한다. `push_front`, `push_back`, `pop_front`, `pop_back` 중 사용할 연산을 정하여 LIFO와 FIFO를 각각 구현하라. 선택한 끝은 각 방식 안에서 일관되게 유지한다.

**산출물:** 방식별 삽입·제거 연산의 조합과 실제 제거 순서.

### C09 물리적 배열과 논리적 큐

배열 `[A, B, C]`와 정수 `head=0`으로 큐를 표현한다. 제거는 값을 옮기지 않고 head를 1 늘리며, 삽입은 배열 끝에 붙인다. `제거, 제거, D 삽입` 후 메모리에 있는 항목과 아직 대기 중인 항목을 구별하라.

**산출물:** 배열·head·논리적 큐와 공간 사용에 대한 설명.

### C10 순서와 우선순위의 구별

A, B, C가 이 순서로 들어왔고 우선순위는 각각 1, 5, 3이다. 요청 P는 가장 먼저 대기한 항목 하나, 요청 Q는 우선순위가 가장 높은 항목 하나를 선택한다. P용 기본 큐의 front를 그대로 Q의 답으로 써도 되는가?

**산출물:** 두 요청의 선택 결과와 필요한 연산의 차이.

## D 기준선과 복잡도

### D01 두 번 도는 것과 겹쳐 도는 것

절차 P는 길이 N 배열을 한 번 순회한 뒤 다시 한 번 순회한다. Q는 각 원소마다 길이 N 배열 전체를 순회한다. 반복 본문은 O(1)이다. N=4와 일반 N을 각각 분석하라.

**산출물:** 구체적 반복 횟수와 일반식 및 성장률.

### D02 직접적인 정답 절차

정수 배열 `[2, 5, 3, 4]`에서 서로 다른 위치 두 개의 값 합이 7인 위치 쌍을 모두 반환한다. 같은 쌍을 뒤집어 중복 반환하지 않으며 각 쌍은 작은 인덱스를 먼저 쓴다. 개선을 생각하기 전에 직접적인 절차를 만들어라.

**산출물:** 반환 쌍, 후보 생성·검사·출력 절차, 후보 수의 일반식.

### D03 반복되는 질문 찾기

이름 목록 `['A', 'B', 'A', 'C']`에 대해 조회 `['A', 'C', 'A']`마다 등장 횟수를 묻는다. 이 연습의 이름은 한 글자이며 비교 비용은 O(1)이다. 매 조회 때 전체 명단을 다시 세는 기준선을 만든 뒤 어떤 질문을 반복하는지 적어라.

**산출물:** N개 이름·M개 조회의 기준선 비용과 병목 한 문장, 유지할 정보 후보.

### D04 앞 삭제의 실제 비용

vector `[10, 20, 30, 40, 50]`에서 첫 원소를 지울 때 뒤의 모든 원소를 한 칸씩 앞으로 옮긴다고 하자. 빌 때까지 반복하면 원소 이동은 총 몇 번인가?

**산출물:** 삭제별 이동 수와 길이 N일 때의 합 및 시간복잡도.

### D05 중첩 반복의 총횟수

처음 저장소는 비어 있고 바깥 반복은 N번이다. 각 반복에서 새 항목을 최대 한 개 넣고, 안쪽 while은 이미 들어 있는 항목만 제거한다. 제거한 항목은 다시 넣지 않으며 while의 한 번 실행은 O(1)이다. while이 총 몇 번 실행될 수 있는가?

**산출물:** 항목 하나와 전체 항목을 기준으로 한 실행 횟수 상한 증명.

### D06 재삽입을 무시한 비용 주장

큐에 N개 작업이 있고 i번째 작업은 `r_i`번 서비스받아야 끝난다. 한 번 꺼낼 때 서비스 1회를 제공하고 끝나지 않으면 뒤에 넣는다. 각 큐 연산과 서비스는 O(1)이다. “각 항목을 넣고 빼므로 O(N)”이라는 주장에 필요한 누락 변수를 찾아라.

**산출물:** 총 처리 횟수의 식, `N=3, r=[2,1,4]`의 횟수, 시간·공간 분석.

### D07 연산의 내용까지 세기

문자열 N개를 순회하며 각 문자열을 별도 목록에 복사한다. 문자열 길이는 모두 L이고 문자 하나 복사는 O(1)이다. 같은 순회에서 원본 인덱스만 저장하는 경우와 시간·추가 공간을 비교하라.

**산출물:** 두 방식의 시간·공간식과 복사를 생략해도 되는 전제.

### D08 정렬 뒤의 처리까지 포함하기

정수 N개를 O(N log N) 시간 정렬한 뒤 한 번 순회하여 서로 같은 값의 묶음 크기를 기록한다. 기록할 묶음 수는 G다. 전처리·본 처리·결과 공간을 구별하라.

**산출물:** 전체 시간식과 입력·정렬 보조 공간·결과 공간 중 확인 가능한 범위 및 추가 확인 항목.

### D09 예산의 숫자와 실행 시간

N은 최대 100,000이고 후보 P의 주된 연산 수는 N², Q는 `N log₂ N`이다. 연산의 실제 내용과 시간 제한은 아직 모른다. 두 수치를 계산하고 현재 정보만으로 할 수 있는 판단과 할 수 없는 판단을 나눠라.

**산출물:** 최대 입력 대입값과 시간 예산에 관한 조건부 판단.

### D10 동시에 살아 있는 메모리

입력 정수 N개를 보존하면서 N칸의 인덱스 배열, 최대 K개의 `(값, 인덱스)` 쌍을 담는 보조 저장소, N칸의 결과 배열을 사용한다. 각 정수는 4바이트이고 관리 비용과 여유 용량은 일단 제외한다.

**산출물:** 입력·결과 포함 여부별 공간식과 N=1,000, K=100일 때의 바이트 수.

## E 불변식과 반례

### E01 합 누적의 정확성

`sum=0`으로 시작해 `[3, -1, 4]`를 왼쪽부터 읽고 현재 값을 더한다. “i개 처리 직후 sum은 앞 i개 값의 합이다”라는 주장을 초기화·유지·종료에 연결하라.

**산출물:** 세 단계의 정확성 설명과 반복이 끝나는 별도의 근거.

### E02 스택에 무엇이 들어 있는가

명령은 `push A, push B, pop, push C`이고 빈 스택에서 시작한다. “스택에는 항목들이 들어 있다”보다 구체적인 불변식을 써라. 이미 제거한 항목의 처리와 남아 있는 항목의 순서를 함께 표현한다.

**산출물:** 명령 처리 직후를 기준으로 한 불변식과 각 명령에서 유지되는 이유.

### E03 FIFO 보존 증명

큐에서 새 항목은 뒤에 넣고 제거는 앞에서만 한다. 빈 큐에서 시작하고 빈 상태에서는 제거하지 않는다. 서로 다른 항목 A가 B보다 먼저 들어와 둘 다 아직 남아 있다면 A가 B보다 앞에 있다는 성질을 설명하라.

**산출물:** 삽입과 제거 각각에 대해 성질이 보존되는 이유.

### E04 결론이 맞아도 설명이 부족한 경우

목표는 길이 1 이상의 정수 배열의 최댓값을 반환하는 것이다. 예시 입력은 `[6, 2, 8]`이다. 설명은 “for문으로 비교하면 8이 나와서 맞다”뿐이다. 이 설명에 어떤 내용을 더해야 다른 허용 입력까지 책임질 수 있는가?

**산출물:** 상태 의미·초기값·갱신·종료를 포함한 선서술.

### E05 종료하지 않는 회전

큐 `[A, B]`가 빌 때까지 앞 항목을 꺼내 아무 조건 없이 뒤에 다시 넣는다. 새 항목은 없다. 큐 크기와 항목 수가 유한하다는 사실만으로 종료가 보장되는가?

**산출물:** 네 번의 상태 추적과 종료 주장에 대한 반례 설명.

### E06 제거가 안전하지 않은 경우

원소를 추가할 수 있고 “지금까지 추가한 모든 값의 합”을 언제든 요청할 수 있다. 과거 `[3, 7]`에서 작은 값은 필요 없다고 판단하여 3을 버리고 7만 보관하며 다른 요약은 저장하지 않았다. 이 제거를 정당화할 수 있는가?

**산출물:** 실패하는 요청과 필요한 정보를 보존하는 수정 방향.

### E07 경계의 등호

보관함은 총 무게가 용량 C 이하일 때 물건을 허용한다. 현재 무게 6, 새 물건 무게 4, C=10이다. 허용 조건을 `< C`로 작성한 구현과 지문의 관계를 검토하라.

**산출물:** 해당 입력의 판정과 등호를 시험할 경계 입력 두 개.

### E08 정렬하면 사라지는 정보

요구는 원래 입력에서 A가 B보다 먼저 등장했는지 반환하는 것이다. 입력 `['B', 'A', 'C']`를 사전순으로 정렬하고 원래 위치는 저장하지 않았다. 정렬된 목록에서 위치를 비교해도 되는가?

**산출물:** 원래 요구와 정렬 후 판단의 차이를 드러내는 반례 설명.

### E09 작은 반례로 줄이기

목표는 배열의 최솟값 반환이다. 잘못된 절차는 `best=0`에서 시작하여 현재 값이 best보다 작을 때만 갱신한다. 허용 입력은 길이 1 이상이고 값은 -10~10이다. 가장 짧은 실패 입력을 찾아라.

**산출물:** 최소 길이 반례, 기대 결과·절차 결과, 초기화 수정의 근거.

### E10 불변식과 정답의 연결

배열 `[2, 5, 1]`의 합을 구하면서 입력을 빠짐없이 저장한 큐를 만들었다. “큐에는 아직 읽지 않은 원소가 원래 순서로 있다”만 증명한 뒤 합이 맞다고 주장한다. 합에 대한 어떤 상태와 관계가 추가로 필요한가?

**산출물:** 기존 불변식에 추가할 관계와 종료 시 반환값으로 이어지는 설명.

## F C++ 구현과 경계

이 절의 짧은 코드는 독립적인 API 연습이다. 컴파일 결과와 실행 결과는 직접 확인한 경우에만 기록한다. 문법·라이브러리 확인에는 [C++ stack](https://eel.is/c++draft/stack), [queue](https://eel.is/c++draft/queue), [vector 변경 연산](https://eel.is/c++draft/vector.modifiers)을 참고할 수 있다.

### F01 읽기와 제거

`std::stack<int> s; s.push(12);` 다음에 제거한 값을 변수에 담고 싶어 `int x = s.pop();`을 작성했다. API의 반환 규칙을 확인하고 의도를 만족하는 최소 코드 조각을 작성하라.

**산출물:** 필요한 헤더를 포함한 코드 조각과 실제 Build 결과 또는 미실시 표시.

### F02 빈 컨테이너 접근

빈 `std::queue<int> q`에서 `q.front()`를 읽는 코드가 있다. 비어 있으면 아무 값도 출력하지 않고, 비어 있지 않으면 맨 앞 값을 출력해야 한다. 접근 전에 어떤 조건을 확인할 것인가?

**산출물:** 안전한 코드 조각과 빈 큐·한 원소 큐에 대한 기대 동작.

### F03 참조의 수명

`s`에 정수 7이 하나 들어 있다. `auto& x = s.top(); s.pop();` 뒤에 x를 출력하려 한다. 제거된 원소를 가리키는 참조와 값 복사는 무엇이 다른가?

**산출물:** 수명 문제 설명과 제거 후에도 값을 사용할 수 있게 고친 코드 조각.

### F04 앞과 뒤를 혼동한 조회

빈 `std::queue<int> q`에 `q.push(4); q.push(9);`를 실행한 뒤 다음에 제거할 값을 출력하려 한다. `q.front()`와 `q.back()` 중 무엇을 골라야 하며, `q.pop()` 뒤 두 접근의 의미는 어떻게 되는가?

**산출물:** 두 시점의 큐 상태와 각 API가 읽는 위치.

### F05 빈 vector와 인덱스

빈 vector에도 동작해야 하는 함수에 `for (size_t i = 0; i <= v.size() - 1; ++i)`가 있다. `size()`의 타입과 뺄셈을 고려하여 빈 입력에서의 조건을 검토하라.

**산출물:** 안전한 순회 조건과 빈 입력·원소 하나 입력의 반복 횟수.

### F06 값과 원래 위치

원본 `[8, 8, 3]`의 항목을 큐에 넣으며 값과 원래 위치를 함께 보관하려 한다. 두 8 중 위치 1인 항목을 구별할 수 있어야 한다. C++의 원소 타입을 직접 정하라.

**산출물:** 원소 타입·삽입 코드 조각·읽어 낸 필드의 의미.

### F07 논리적 제거의 공간

`vector<int> data`에 1,000개를 넣고 `head`를 0에서 1,000까지 늘려 모두 처리했다. data에서 실제 원소를 지우거나 용량을 줄이지 않았다. 논리적 큐 크기와 `data.size()`가 각각 무엇을 의미하는가?

**산출물:** 두 크기의 값과 계속 삽입되는 실행에서 검토할 메모리 문제.

### F08 계산 시점의 정수 타입

실습 환경의 int는 부호 있는 32비트이고 `int n=100000, value=100000; long long total=n*value;`를 계산한다. total의 타입만 넓으면 곱셈이 안전한가?

**산출물:** 곱셈 시 피연산자 타입 설명과 계산 전에 타입을 넓히는 코드 수정.

### F09 삭제 후 다음 접근

스택 `[4]`에 대해 `while (s.top() > 0) s.pop();`을 실행하려 한다. 한 번 제거한 뒤 다음 조건 검사가 안전한지 확인하고, 양수인 top을 가능한 동안 제거한다는 의도를 보존하라.

**산출물:** 접근 전제와 단락 평가 순서를 반영한 수정 조건 및 경계 입력.

### F10 실제 검증 기록

함수의 규칙은 정수 큐의 front부터 모두 꺼내 합을 반환하며, 빈 입력의 합은 0이다. 직접 작성한 함수를 `[]`, `[5]`, `[3,-3,2]`로 점검하라. 온라인 Judge 제출 대상이 아니면 해당 게이트를 그렇게 기록한다.

**산출물:** 기대값과 실제 결과를 구분한 Build·Example·Edge·Judge 기록.

## G 심화와 비용 증명

이 절은 기본 구현을 설명할 수 있을 때 선택한다. 풀이의 핵심 갱신 규칙을 먼저 제공받기보다 작은 연산열에서 스스로 후보 규칙을 만들고 반례로 고친다.

### G01 한 번 느린 연산과 전체 비용

배열의 용량은 1에서 시작하고 가득 찬 배열에 삽입할 때마다 두 배로 늘린다. 재할당 때 기존 원소를 모두 복사하고, 새 원소 쓰기는 삽입마다 한 번이다. 8개를 연속 삽입하라.

**산출물:** 삽입별 용량·복사 횟수, 한 번의 최악 비용과 연속 삽입 총비용의 구분.

### G02 평균과 상환을 구별하기

G01의 삽입에 들어오는 값이 모두 같을 때와 서로 다를 때를 비교한다. 값은 정수이고 복사 비용은 동일하다. 비용 근거에 무작위 입력이나 특정 입력의 발생 확률이 필요한가?

**산출물:** 값 분포와 연산열 비용의 관계 및 평균 분석과 상환 분석의 차이.

### G03 두 스택으로 FIFO 설계하기

두 개의 빈 스택만 사용해 `삽입 A, 삽입 B, 제거, 삽입 C, 제거, 제거`를 FIFO로 처리하라. 기본 연산은 각 스택의 push·top·pop·empty이며, 재귀나 제3의 항목 저장소는 사용할 수 없다. 항목 하나를 옮길 임시 변수는 허용한다.

**산출물:** 직접 고안한 삽입·제거 규칙과 두 스택의 전체 추적표.

### G04 두 스택 설계의 비용

G03에서 만든 설계를 `삽입 1, 삽입 2, …, 삽입 N` 후 N번 제거하는 경우와 `삽입 1, 제거, 삽입 2, 제거, …, 삽입 N, 제거`인 경우에 적용하라. 두 경우 모두 빈 상태에서 시작한다. 한 항목이 각 스택 사이를 이동하는 총횟수를 세어라.

**산출물:** 자신의 규칙에 대한 단일 호출 최악 비용·전체 비용·공간과 그 근거.

### G05 재삽입으로 깨지는 증명

처음 스택에 N개 항목을 넣는다. 이후 “전부 빼서 임시 목록에 보관한 뒤, 뺀 순서대로 같은 항목들을 다시 넣기”를 R회 수행한다. 한 항목이 한 번 들어가고 한 번 나온다는 증명을 이 절차에 적용할 수 있는가?

**산출물:** N과 R을 사용한 총연산 수와 기존 증명이 깨지는 문장.

### G06 단조 상태의 갱신 규칙 만들기

입력 `[2, 6, 4, 4, 7, 3]`을 한 개씩 읽는다. 매 입력 직후 저장된 값은 bottom→top으로 비감소 순서여야 하고, 새 값은 반드시 마지막에 넣는다. 새 값을 넣기 전에 기존 top만 제거할 수 있으며 제거 개수를 최소화한다. 갱신 규칙을 직접 정하라.

**산출물:** 여섯 단계의 상태와 비교 조건·반복 조건을 선택한 이유.

### G07 같은 값의 규칙 변경

G06의 입력과 허용 동작을 유지하면서 저장된 값의 조건을 엄격한 증가로 바꾼다. 같은 값 두 개가 들어오는 시점을 중심으로 어느 규칙을 바꿔야 하는지 검토하라.

**산출물:** 변경 전후 상태 비교와 등호 처리의 근거.

### G08 정렬된 모양과 필요한 정보

G06 방식으로 값을 유지한 뒤 “지금까지 입력된 값이 몇 개였는가?”와 “그 값들의 합은 얼마인가?”를 요청한다. 현재 스택만 사용할 수 있고, 처리한 개수·원본 입력·제거한 값에 관한 별도 기록은 없다. 단조 순서를 유지했다는 사실만으로 두 요청에 답할 수 있는가?

**산출물:** 정보가 부족함을 보이는 서로 다른 과거 또는 충분성을 입증하는 근거, 필요한 보완.

### G09 같은 시각의 사건 순서

용량 1인 장비를 X가 사용 중이며 시각 3에 반납한다. Y는 시각 3에 도착한다. 규칙은 같은 시각에 반납을 먼저 반영하고, 그다음 도착자가 빈 장비를 즉시 사용하며, 빈 장비가 없으면 요청을 거절하는 것이다. 도착부터 처리한 구현을 검토하라.

**산출물:** 두 처리 순서의 결과와 지문에 맞는 시각 3의 상태 갱신 순서.

### G10 시간 건너뛰기의 전제

요청은 시각 2와 1,000,000에만 도착하며 도착 즉시 카운터를 1 늘린다. P는 마지막 총 요청 수만 묻고 중간에 아무 변화도 없다. Q는 시각 0부터 마지막 도착 시각까지 매 정수 시각의 도착을 반영한 뒤 현재 대기 요청 수를 출력하며, 요청은 끝까지 대기한다. 두 경우 모두 사건 시각만 방문해 같은 방식으로 끝낼 수 있는가?

**산출물:** 경우별 생략 가능 작업·필요한 출력량·N과 마지막 시각 T를 사용한 비용 분석.

## H 독립 복원과 다른 유형으로의 전이

**산출물:** 기준선·상태·갱신·종료·총비용과 실제 받은 도움 기록.

### H02 키별 조회로 전이하기

입력 `[(A,3),(B,2),(A,4)]`를 처리한 뒤 A와 B의 값 합계를 각각 조회해야 한다. 이전 입력 전체를 조회마다 다시 훑는 기준선에서 출발하여 반복되는 일을 줄일 상태를 제안하라.

### H03 현재 극값 선택으로 전이하기

대기 작업의 비용이 A=7, B=3이고, 가장 낮은 비용 작업 하나를 제거한 뒤 비용 C=2인 새 작업이 추가된다. 다시 최저 비용을 고른다. 최초 배열의 순서만 고정해 두어도 충분한지 판단하라.

**산출물:** 두 선택의 손추적과 현재 후보 집합·필요한 연산·구조 후보의 근거.

### H04 정렬 뒤 원래 위치

기록 `[(A,5),(B,2),(C,5)]`를 점수 내림차순으로 반환하되 동점은 원래 입력 순서로 처리한다. 정렬 키와 보존 정보, 비교가 만족해야 할 조건을 정하라.

**산출물:** 반환 순서·비교 기준·같은 항목과 동점 항목을 비교할 때의 규칙.

### H05 후보를 빠짐없이 만들기

세 물건의 무게는 `[2,3,4]`이며 각 물건은 최대 한 번 선택할 수 있다. 합이 5 이하인 선택 중 합이 가장 큰 것을 구한다. 빈 선택도 허용한다. 후보를 어떤 순서로 만들든 빠뜨리지 않는 절차를 설계하라.

**산출물:** 후보 목록과 판정·최선 갱신 규칙, N개로 일반화한 비용.

### H06 당장 좋은 선택 검증하기

동전은 1, 3, 4이고 각 동전을 원하는 만큼 쓸 수 있다. 금액 6을 최소 개수로 만든다. 현재 남은 금액 이하인 가장 큰 동전을 매번 고르는 규칙을 작은 입력에서 검증하라.

**산출물:** 그 규칙의 선택과 비교 후보, 일반적인 최적성 주장에 대한 판정.

### H07 같은 위치가 같은 상태인가

S에서 G로 가는 이동은 연료 2를 소비한다. 상태 P는 위치 S·연료 1, Q는 위치 S·연료 3이며 충전은 불가능하다. 목적은 G에 도달할 수 있는지 판단하는 것이다. 위치만 같으면 같은 부분 문제로 합쳐도 되는가?

**산출물:** P와 Q의 가능한 행동·결과 및 충분한 상태 정의.

### H08 관계 모델과 탐색 전제

방향 간선은 `A→B`, `B→D`, `A→C`, `C→D`다. 먼저 모든 이동 비용이 1인 경우를 보고, 다음에는 비용을 차례로 1, 10, 4, 4로 바꾼다. 이동 횟수 최소와 비용 합 최소는 같은 요구인가?

**산출물:** 정점·간선 의미, 두 경로의 비교, 일반 BFS를 적용할 때 확인할 전제.

### H09 경계를 찾을 수 있는 조건

후보 x는 1~5다. 판정 결과 P는 `[거짓, 거짓, 참, 참, 참]`, Q는 `[거짓, 참, 거짓, 참, 참]`이다. 처음 참인 위치를 찾을 때 한 번의 판정으로 한쪽 범위를 버리는 근거가 두 경우에 모두 성립하는가?

**산출물:** 경우별 단조성 판단과 버릴 수 있는 범위를 설명하는 논리.

### H10 유형명 없이 필요한 일로 분류하기

**산출물:** 요청별 필요한 연산·후보 방법·다른 후보보다 적합한 조건과 비용.

**산출물:** 배포가 일어나는 날짜별 기록과 반환 배열, 원소의 단위 설명.

### K07 프로세스의 위치와 실행 순번

**산출물:** 대상 프로세스 표시, 규칙에 따른 실행 순서, 반환값의 의미.

### K08 프로세스의 같은 우선순위

같은 문제에서 `priorities=[2,2,2]`, `location=1`이다. 각 항목에 A, B, C라는 임시 이름을 붙이고 지문의 “더 높은” 조건을 그대로 적용하라.

**산출물:** 실행 순서와 대상의 반환 순번, 같은 값인 항목의 구별 설명.

### K09 다리를 지나는 트럭의 종료 시점

[공식 지문](https://school.programmers.co.kr/learn/courses/30/lessons/42583)의 시간표를 확인하고 `bridge_length=2`, `weight=10`, `truck_weights=[6]`을 해석하라. 시각 0부터 트럭이 완전히 다리를 지난 시점까지 기록하라.

**산출물:** 시각·대기·다리 위·통과 완료 상태표와 반환 시점 설명.

### K10 다리를 지나는 트럭의 두 제한

같은 문제에서 `bridge_length=2`, `weight=10`, `truck_weights=[7,4]`다. 두 트럭이 함께 다리 위에 있는 상황이 허용되는지 지문의 각 제한을 따로 대입하라. 대기열이 비었다는 사실만으로 종료해도 되는지도 설명하라.

**산출물:** 개수 제한·무게 제한의 판정과 모든 트럭 통과의 의미.

### K11 주식가격의 같은 값과 하락

**산출물:** 두 반환 배열과 마지막 관측 시각의 처리 규칙.

## X 백지 출력 평가

설명과 이전 답을 가린 뒤 수행한다. 여기서 백지는 아무 생각 없이 답을 외우라는 뜻이 아니라 필요한 근거를 스스로 다시 만들어 보라는 뜻이다. 평가 후에는 부족했던 문항으로 돌아가고, 채점받은 당일의 재작성과 다음날 독립 복원을 구별한다.

### X01 입출력에서 상태까지

길이 1~100,000의 정수 배열에서 가장 큰 값이 처음 나타나는 인덱스를 반환한다. 작은 입력은 `[4,9,9,1]`이다. 코드 없이 요구·기준선·상태·갱신·종료·비용을 설명하라.

**산출물:** 여섯 요소의 선서술과 작은 입력 추적, 동률 경계 한 개.

### X02 FIFO 요구의 독립 구현 준비

접수 명령 `ADD A, ADD B, TAKE, ADD C, TAKE, TAKE, TAKE`가 있다. TAKE는 가장 오래 기다린 항목을 출력하고 제거하며, 비어 있으면 문자열 EMPTY를 출력한다. 자료구조 이름부터 정하지 말고 연산 요구부터 도출하라.

**산출물:** 요구·추적표·자료구조 선택 근거·의사코드·시간과 공간.

### X03 취소 규칙의 독립 설명

문자 명령은 문자열 끝에 문자를 붙이고 UNDO는 가장 최근에 붙여 아직 취소하지 않은 문자 한 개를 지운다. 빈 상태의 UNDO는 무시한다. `A, B, UNDO, C, D, UNDO`를 빈 상태에서 실행한다.

**산출물:** 결과·상태 뜻·선택한 연산 규칙·불변식·빈 상태 처리·비용.

### X04 기준선과 개선의 연결

배열 `[1,4,2,3,5]`에서 서로 다른 위치 두 개의 합이 6인 쌍의 개수를 구한다. `(i,j)`와 `(j,i)`는 하나로 세며 값이 같아도 위치가 다르면 다른 항목이다. 먼저 올바른 직접 풀이를 만들고 반복되는 일을 줄일 수 있는지 검토하라.

**산출물:** 기준선·비용·병목·개선 후보·중복 처리 근거; 개선을 못 만들면 막힌 지점 표시.

### X05 재삽입과 종료의 연결

큐는 `[(A,2),(B,3)]`이고 매번 front를 꺼내 남은 일을 1 줄인다. 남은 일이 있으면 뒤에 넣고 없으면 완료한다. 새 항목은 없다. “큐 크기가 매번 줄어서 끝난다”라는 설명을 검토하고 실제 진행량을 찾아라.

**산출물:** 전체 추적·종료 근거·총연산 수·한 항목 수와 처리 횟수의 구분.

### X06 불변식에서 반환까지

배열 `[3,-2,0,5]`에서 양수인 원소들의 합만 반환한다. 길이는 0 이상 N 이하이며 빈 배열의 답은 0이다. 직접 상태를 정의하고 반복 직후에 무엇이 항상 맞는지 설명하라.

**산출물:** 초기화·유지·종료·종료 근거와 빈 배열 검증.

### X07 반례와 수정과 실제 검증

스택의 양수인 top을 가능한 동안 제거하려고 `while (s.top() > 0) s.pop();`을 작성했다. 입력 상태는 `[]`, `[2]`, `[0,2]`, `[-1]`을 허용한다. 문제를 드러내는 사례를 찾고 의도를 유지하며 고쳐라.

**산출물:** 최소 실패 상태·실패 이유·수정 코드와 Build·Edge 실제 결과 또는 미실시 표시.

### X08 지연 복원과 조건 변경

X02를 학습한 지 24시간 이상 지난 뒤 `ADD P, ADD Q, TAKE, ADD R, TAKE`를 설명 없이 다시 풀어라. 이어 TAKE 규칙만 “가장 최근에 들어와 아직 남은 항목 제거”로 바꾼다. 이전 풀이의 어느 근거가 바뀌는지 설명하라.

**산출물:** 두 규칙의 추적·상태와 처리 순서 비교·수정할 부분·독립 수행 여부.

## 답변 뒤의 기록

잘못된 답을 지우고 정답만 남기기보다 **처음 가정 → 실패 사례 → 수정한 근거**를 짧게 남긴다. 한 문제를 마치면 적용 조건, 실패 조건, 도움받은 단계, 다음날 복원할 항목을 기록한다. AC는 해당 제출이 Judge를 통과했다는 증거이며, 개념의 독립 복원과 처음 보는 변형의 해결은 별도로 확인한다.

처음에는 기초 복원과 기본 문제에 약 70%, 조건 변경과 심화에 약 30%의 시간을 두고 조절한다. 설명을 길게 읽는 진도보다 **한 질문에 직접 답하고 한 문제에서 검증하는 경험**을 쌓는다.
