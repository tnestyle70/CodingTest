# 모든 코딩테스트 문제에 쓰는 8단계 답변 양식

날짜: 2026-10-10 Asia/Seoul

아래 주석을 문제의 코드 위에 붙이고 `내 답`을 채운다. 새 문제는 1~6을 코딩 전에, 7을 구현 뒤에, 8을 풀이 뒤에 작성한다. 이미 푼 문제는 같은 양식으로 사후 복기한다. 막힌 칸은 `미답`으로 남겨도 된다.

```cpp
// 1. 한 문장 목표
// 질문: 어떤 입력에서, 어떤 규칙에 따라, 무엇을 반환해야 하는가?
//       선택 조건·중복 처리·결과 순서에 대한 요구는 무엇인가?
// 내 답:

// 2. 제약 어휘
// 질문: 입력 크기와 값의 범위는 각각 얼마인가?
//       숫자마다 무엇의 개수·길이·값을 의미하는가?
//       가장 작은 입력, 가장 큰 입력, 문제에서 보장하는 조건은 무엇인가?
// 내 답:

// 3. 예산 산술
// 질문: 최대 입력을 후보 비용식에 대입하면 작업량은 얼마인가?
//       예: N, N log N, N², 상태 수 × 상태당 처리 비용.
//       시간·메모리 제한을 고려해 어떤 복잡도를 목표로 할 것인가?
// 내 답:

// 4. 완전탐색 기준선 — 가장 직접적인 풀이
// 질문: 입력을 받아 정답을 반환하기까지 어떤 순서로 처리할 것인가?
//       어떤 대상을 확인하고, 어떤 조건으로 판단하며, 결과를 어떻게 만드는가?
//       이 직접적인 풀이의 시간·공간 비용은 얼마인가?
// 내 답:

// 5. 병목 → 자료구조·알고리즘 선택
// 질문: 위 절차에서 비용이 큰 작업이나 반복해서 해결하는 질문은 무엇인가?
//       다음 판단에 필요한 정보는 무엇이며, 무엇부터 처리해야 하는가?
//       어떤 자료구조와 알고리즘을 선택하고, 그 이유는 무엇인가?
//       이미 충분히 효율적이라면 그 이유는 무엇인가?
// 내 답:

// 6. 선서술·불변식·비용 검산
// 질문: 선택한 풀이에서 저장하는 정보는 무엇을 의미하는가?
//       초기 상태에서 그 의미가 맞고, 각 처리 단계 뒤에도 유지되는 이유는 무엇인가?
//       처리가 종료되는 이유와, 종료 시 결과가 정답이 되는 이유는 무엇인가?
//       각 작업의 실행 횟수 × 한 번 비용을 합산하면 시간 복잡도는 얼마인가?
//       동시에 보관해야 하는 데이터의 최대 크기로 본 공간 복잡도는 얼마인가?
// 내 답:

// 7. 검증
// 질문: 내 풀이의 어떤 실수를 잡기 위해 어떤 입력을 시험할 것인가?
//       예상 결과와 실제 결과는 무엇인가?
//       컴파일·예제·경계값·프로그래머스 채점은 각각 어디까지 확인했는가?
// 내 답:

// 8. 회고
// 질문: 처음에 무엇을 잘못 생각했고, 어떤 근거로 수정했는가?
//       선택한 풀이가 성립하는 조건과 성립하지 않는 조건은 무엇인가?
//       다음 문제에서도 사용할 수 있는 판단 기준은 무엇인가?
// 내 답:
```

## 작성 범위

3번은 작업량의 목표, 4번은 직접 처리 절차, 5번은 필요한 정보와 도구의 선택, 6번은 선택한 절차의 정확성 및 실제 비용을 다룬다. 직접 풀이가 이미 충분히 빠르면 4번의 풀이를 그대로 채택한다.

`N`은 예시다. 그래프에서는 정점 수 V·간선 수 E, DP에서는 상태 수·전이 수처럼 실제 입력과 설계에 맞는 변수를 쓴다. 모든 문제에 N²을 억지로 적용하거나 쓰지 않는 자료구조의 질문에 답할 필요는 없다. 시간 제한이 명시되지 않았으면 미확인으로 적고, 연산 횟수를 고정된 초로 환산하지 않는다.

유형에 필요한 정확성 근거는 6번에 붙인다. 예를 들어 탐색은 후보를 빠뜨리지 않는 이유, 그리디는 선택의 안전성, DP는 상태·전이·초기값·계산 순서, 이분탐색은 단조성과 답을 보존하는 구간 갱신을 설명한다.

## 채점 기준

| 점수 | 기준 |
|---|---|
| 2 | 핵심 내용이 정확하고 필요한 근거가 있다 |
| 1 | 방향은 맞지만 필수 조건이나 근거를 보완해야 한다 |
| 0 | 핵심 판단이나 계산에 오류가 있다. 반례 또는 계산으로 설명한다 |
| 미답 | 답이 없어 판단을 보류한다 |

피드백은 `항목 → 점수 → 판단 근거 → 보완할 질문` 순서다. 문장 길이나 전문 용어 사용 여부는 채점하지 않는다. 미답이 있으면 `작성 3/8항목, 작성분 5/6점`처럼 작성 범위와 점수를 함께 표시한다. 코딩 전 설명, 사후 설명, 도움받은 설명은 증거에 표시하고, 올바른 사후 설명도 내용에 따라 채점한다. 실제 실행 여부는 설명 점수와 별도로 기록한다.
