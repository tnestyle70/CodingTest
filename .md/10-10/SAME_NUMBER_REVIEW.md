## 8단계 채점

**작성 8/8항목, 설명 점수 6/16점.** 이 점수는 이번 답변의 정확성과 근거를 평가한다. 코드의 채점 100점, 일반적인 구현 능력, 코딩 전 독립 설명 여부와는 평가 대상이 다르다.

기준은 2점=정확하고 필요한 근거가 있음, 1점=방향은 맞지만 필수 조건·근거 보완 필요, 0점=핵심 판단·계산에 오류, 미답=판단 보류다. 부분적으로 맞은 내용은 0점 항목에서도 명시한다. 충족은 이 답변의 내용 기준이며 사후 설명이라는 시점은 유지한다.

## 1 목표에서 빠진 조건

연속 구간마다 하나를 남긴다는 해석은 맞다. 출력 순서까지 포함하면 다음과 같이 완성된다.

> 연속해서 같은 값이 나오는 각 구간에서 하나씩 남기고, 원래 순서를 유지한 배열을 반환한다.

서로 떨어진 같은 값은 각각 남는다. 숫자만 반환하므로 구간 안에서 첫 값을 남기든 마지막 값을 남기든 출력 값은 같다. 현재 코드는 마지막 값을 선택한다. 입력 크기는 2번에 두면 목표 문장이 더 선명해진다. [공식 문제](https://school.programmers.co.kr/learn/courses/30/lessons/12906)

## 2 숫자의 역할을 구분하기

| 항목 | 올바른 범위 | 뜻 |
|---|---|---|
| `N = arr.size()` | `1 ≤ N ≤ 1,000,000` | 배열에 담긴 원소의 개수 |
| `arr[i]` | `0 ≤ arr[i] ≤ 9` | 원소 하나에 담길 수 있는 값 |

예를 들어 `[7]`의 원소 개수는 1이고 원소 값은 7이다. 최대 입력은 숫자 1,000,000 하나가 아니라 원소가 1,000,000개인 배열이다. 값의 종류가 열 개여도 0과 1이 번갈아 나오면 결과 길이는 N이 될 수 있다. [공식 제한사항](https://school.programmers.co.kr/learn/courses/30/lessons/12906)

## 3 예산 산술을 고치기

```text
N = 1,000,000 = 10^6
N² = 10^6 × 10^6 = 10^12 = 1,000,000,000,000 = 1조
1억 = 10^8
```

`10^7회 = 1초`를 고정 기준으로 쓰지 않는다. 정수 비교, 문자열 전체 비교, 메모리 할당은 작업 비용이 다르고 실행 환경도 영향을 준다. 공식 문제의 확인한 공개 본문에는 1초라는 제한이 제시되어 있지 않다. 따라서 정확한 초를 만들어 내는 대신 후보 작업량을 비교하고 실제 채점으로 확인한다.

이 문제에서는 N회 수준의 처리와 최악 N개 출력 저장을 목표로 삼을 수 있다. N²은 최대 1조 규모이므로 선형 직접 풀이가 있는 상황에서 채택할 이유가 없다. 최종 목표는 시간 O(N), 결과를 포함한 공간 최악 O(N)으로 쓴다.

## 4 직접 절차는 정확하다

사용자의 설명은 입력부터 마지막 처리까지 실행할 수 있는 절차다. 이 문제에서는 그 직접 풀이가 최종 풀이이므로 더 느린 완전탐색을 억지로 만들 필요가 없다.

마지막을 무조건 넣는 행동의 의미를 붙이면 이해가 더 단단해진다. 오른쪽과 다를 때는 현재 연속 구간이 끝났고, 배열의 마지막일 때도 마지막 연속 구간이 끝났다. 두 분기는 같은 저장 기준을 구현한다. 마지막인지 먼저 분기하므로 오른쪽 원소가 없는 위치에서 `arr[i+1]`에 접근하지 않는다.

## 5 자료구조를 연산에 연결하기

자료구조를 정보를 저장하는 방식으로 설명한 출발점은 맞다. 여기에 **어떤 조회·추가·삭제를 지원하고 얼마의 비용이 드는지**를 붙이면 선택 근거가 된다. 알고리즘은 이 연산들을 어떤 조건과 순서로 수행해 답을 만드는 절차다.

이번 풀이에 필요한 것은 원본의 현재 값·오른쪽 값 읽기, 마지막 위치 판단, 결과 끝에 추가하기다. 원본 vector의 인덱스 접근과 결과 vector의 끝 삽입으로 충족된다. 이미 저장한 전체 결과를 반복해서 검색할 필요가 없다.

모든 원소에 대해 확인하지만 모든 원소를 push하는 것은 아니다. `[1,1,1]`에서는 확인 3회, 결과 추가 1회다. 또한 for문 하나라는 모양만으로 O(N)을 확정하지 않는다. 그 안에서 전체 배열을 다시 검색하면 전체 비용이 달라진다.

## 6 연산과 O(N)의 의미

연산은 프로그램이 수행하는 작업이다. 이 코드에서는 원소 읽기, 정수 비교, 인덱스 증가, 조건 분기, 결과 추가 등이 해당한다. 소스 코드 한 줄이 항상 기계 명령 하나 또는 일정한 시간인 것은 아니다. 분석할 때는 원소 읽기·정수 비교처럼 입력 길이가 늘어도 비용이 일정한 기본 작업을 정해 횟수를 센다.

**O(N)은 입력 크기 N이 커질 때 전체 비용이 선형 규모의 상한을 갖는다는 뜻이다.** 실행 순서나 계산 한 번을 뜻하지 않는다. 가령 추상적인 작업량이 `5N+3`이면 N이 두 배가 될 때 작업량도 대략 두 배가 되고 O(N)으로 표현한다. 5와 3은 설명용 계수이며 현재 코드를 측정한 값이 아니다.

현재 코드에서 N은 원소 개수, K는 연속 구간 수이자 결과 길이다.

| 작업 | 횟수 또는 총비용 | 해석 |
|---|---|---|
| 반복 본문 진입 | N회 | 각 위치를 한 번 처리 |
| 마지막 위치인지 확인 | N회 | 정수 비교 |
| 원본의 인접 값 비교 | N−1회 | 마지막 위치에서는 비교하지 않음 |
| 결과 끝에 추가 | K회, 총 O(K) | K≤N |
| 반복 조건·인덱스 증가 | 총 O(N) | 순회를 위한 비용 |

vector는 가끔 저장 공간을 늘리면서 기존 원소를 옮길 수 있다. 따라서 모든 push_back 한 번의 최악 비용이 O(1)인 것은 아니다. 정수 K개를 연속해서 끝에 추가하는 **전체 비용이 O(K)**라는 상환 비용을 적용한다. [C++ vector의 끝 삽입 비용](https://eel.is/c++draft/vector.overview), [재할당 시 비용](https://eel.is/c++draft/vector.modifiers)

```text
전체 시간 = 순회·비교 O(N) + 결과 추가 총 O(K)
          = O(N + K)
          = O(N)    (K ≤ N)
```

`1 ≤ O(N) ≤ 1,000,000`처럼 적지 않는다. 다음 두 문장으로 분리한다.

```text
입력 크기: 1 ≤ N ≤ 1,000,000.
전체 시간 복잡도: O(N).
```

결과 저장 공간은 O(K), 최악 O(N)이다. 입력과 결과를 제외한 함수 본문의 지역 상태는 O(1)이다. `vector<int> arr`는 값 매개변수이므로 호출 과정에서 복사가 생기면 추가 시간·공간 O(N)도 고려한다. 출력 길이가 N이 되는 입력이 있으므로 결과를 직접 구성하는 이 문제의 최악 시간 O(N)은 일반적인 원소 단위 비용 모델에서 점근적으로 최적이다.

## 6 answer 전체의 의미와 정답 근거

사용자는 바로 전 반복에서 무엇이 추가됐는지를 설명했다. 불변식은 그 한 번의 사건을 누적 결과 전체의 의미로 확장한다.

> i번째 반복 직전, answer에는 원본에서 끝 위치가 i보다 작은 모든 연속 구간의 대표값이 각 구간당 하나씩 원래 순서대로 저장되어 있다.

말로 풀면 **이미 끝난 구간은 하나씩 저장했고, 아직 이어지는 구간은 저장을 기다릴 수 있다**는 뜻이다. 원본의 구간 끝을 기준으로 하므로, 처리한 앞부분을 언제나 완전히 압축했다고 말하면 현재 코드와 맞지 않는다.

“같으면 없다”는 표현도 정확히 해야 한다. `[1,2,1,1]`에서 i=3 직전에는 직전 값과 현재 값이 같지만 answer는 `[1,2]`다. 값 1 자체가 없다는 뜻이 아니라, 바로 전 위치에서는 1을 새로 추가하지 않았다는 뜻이다.

“조건을 검사했으므로 정답”에서 더 설명할 것은 **그 조건이 왜 필요한 값을 정확히 한 번씩 남기는가**다.

1. 한 연속 구간의 마지막 전까지는 오른쪽 값도 같으므로 저장하지 않는다.
2. 그 구간의 마지막에서는 다음 값이 다르거나 배열이 끝나므로 한 번 저장한다.
3. 왼쪽부터 처리하므로 구간의 순서도 유지된다.

따라서 각 구간에서 정확히 하나가 남고 순서도 맞는다. 처음에는 끝난 구간이 없어 빈 answer가 맞고, 한 위치를 처리하면 그 위치에서 끝나는 구간만 추가된다. i가 증가해 N이 되면 모든 구간의 끝이 처리되어 전체 정답이 된다. 이것이 초기화·유지·종료를 이 코드에 적용한 설명이다.

## 7 테스트와 디버거의 역할

| 입력 | 지문으로부터 계산한 기대값 | 확인하려는 실수 | 실제 결과의 출처 |
|---|---|---|---|
| `[7]` | `[7]` | 원소 하나에서 이웃 접근 및 마지막 처리 | 사용자 통과 보고 |
| `[1,1,1,1,1]` | `[1]` | 끝까지 같은 구간을 한 번 남기는지 | 사용자 통과 보고 |

사용자가 테스트를 실행했다고 보고한 것은 새 진전이다. 이 범주는 앞서 코치가 권했던 단일 원소·동일 값 반복과 겹치므로 무힌트 자작 반례 생성으로 확대하지 않는다. 실행 환경과 실제 출력 문자열은 미기록이며, 표의 기대값을 실행 로그로 취급하지 않는다.

| Edge | 위 두 사례 통과 사용자 보고. 실행 환경 미확인 |
| Judge | 이전에 제공한 정확성 17/17·효율성 4/4·100점 보고 |

원하는 입력과 출력이 확인되고 궁금한 내부 상태가 없다면 매번 Visual Studio에서 중단점을 걸 필요는 없다. 실행 흐름이나 변수 값이 예상과 다를 때 디버거를 사용하면 된다. 테스트는 일부 입력에서의 동작을 확인하고, 정확성 설명은 모든 허용 입력에 통하는 이유를 다룬다. 두 테스트의 통과를 전체 경우의 증명으로 바꾸지는 않는다.

## 8 도구 선택에 관한 회고

단원에 stack/queue라고 적혀 있어도 필요한 연산을 먼저 확인한다는 관찰은 유효하다. 다만 “아무 자료구조나 상관없다”에는 조건이 필요하다.

- vector: 원래 순서로 끝에 추가하고 요구된 반환형으로 바로 반환할 수 있다.
- queue나 deque: 저장 방식으로 사용할 수 있지만 현재 함수의 vector 반환형에 맞추는 과정과 비용을 따져야 한다.
- stack: 꺼낼 때 순서가 뒤집히므로 출력 순서를 맞추는 처리가 필요하다.
- set에 값만 넣기: `[1,2,1]`에서 떨어진 두 번째 1까지 합쳐 버리므로 이 명세를 보존하지 못한다.

재사용할 문장은 “필요한 정보·접근 순서·연산 비용·반환 형태를 충족하는 자료구조를 선택한다”다. 이번에는 이미 원본 인덱스로 판단할 수 있고 결과 끝 추가만 필요하므로 vector가 직접적이다. 제거하는 대상도 중복된 인덱스가 아니라 연속된 같은 값의 여러 출현이다.

## 관찰된 진전과 다음 보완

| 관찰 | 이번에 확인한 의미 | 다음 확인 |
|---|---|---|
| 4번 절차가 완결됨 | 본인의 코드 동작을 문장으로 설명했다 | 다른 문제에서도 입력부터 반환까지 직접 절차 만들기 |
| 두 경계 테스트 통과 보고 | 권장받은 테스트를 실제 검증에 연결했다 | 별도의 조건을 겨냥한 입력과 기대값 직접 만들기 |
| stack 강제 선택을 재검토 | 문제 분류와 필요한 도구를 구분하기 시작했다 | 선택한 도구가 지원해야 하는 연산 설명 |
| 개수 상한을 값 범위로 사용 | 숫자의 역할 구분을 다시 확인할 필요가 있다 | 각 숫자에 개수·값·길이 단위 붙이기 |
| 제곱 및 시간 환산 오류 | 거듭제곱 산술과 실행 시간 모델을 분리할 필요가 있다 | 10의 지수로 곱한 뒤 자릿수 검산 |
| 직전 추가와 전체 answer 의미가 섞임 | 사건 설명에서 누적 상태 설명으로 확장해야 한다 | 같은 값이 떨어져 재등장하는 입력에서 상태 추적 |

숫자 역할 혼동은 [기존 gotchas의 제약 해석 항목](../gotchas.md)과 연결된다. 이를 근거로 모든 자료구조의 본질을 이해하지 못한다고 판단하지 않는다. 풀이 절차는 맞고, 비용과 정확성을 설명하는 언어가 아직 정리되지 않은 부분이 구체적으로 드러난 것이다.

보완 순서는 2번의 숫자 역할 → 3번의 산술 → 6번의 상태와 비용이다. 첫 재답변은 **“1,000,000과 9는 각각 무엇의 최댓값인가?”** 한 문장으로 시작한다. 이후에는 틀린 칸만 고쳐 다시 채점하고, 지연 복원·변형 수행은 실제 수행 뒤 별도 기록한다.

이번 검토를 읽은 사실만으로 약점 해결이나 독립 숙달을 기록하지 않는다. 전체 AC는 6/47이며, Reviewed·Mastered를 자동으로 올리지 않는다. 사용자는 붙여 넣을 수 있는 고정 질문과 항목별 채점을 원하므로 앞으로도 같은 8단계를 유지한다.
