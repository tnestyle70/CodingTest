# 같은 숫자는 싫어 사용자 답변 원문

날짜: 2026-10-10 Asia/Seoul

사용자가 대화로 제출한 8단계 답변을 보존한다. 이 기록은 AC 및 해설 이후의 답변이다. 오기와 질문을 포함한 원문이며, 교정은 [별도 검토](SAME_NUMBER_REVIEW.md)에 있다.

```cpp
// 1. 한 문장 목표
// 질문: 이 문제는 어떤 숫자를 남기고, 어떤 숫자를 없애며,
//       결과를 어떤 순서로 반환하라고 하는가?
// 내 답: 문제에서 주어지는 1,000,000 이하의 크기를 가지는 배열을 기준으로,
//연속되는 중복 숫자 중에서 중복 숫자를 제거하고, 한 개의 숫자만을 남긴다.

// 2. 제약 어휘
// 질문: 배열의 원소 개수와 원소 값의 범위는 각각 얼마인가?
//       가장 작은 입력과 가장 큰 입력은 어떤 모습인가?
// 내 답: 원소 개수 1,000,000개 이하, 값의 범위 또한 1,000,000개 이하이다.

// 3. 예산 산술
// 질문: 최대 입력에서 N번 처리하면 몇 번이고, N²번 처리하면 몇 번인가?
//       어느 정도 시간·공간 복잡도를 목표로 할 것인가?
// 내 답: 최대 입력을 기준으로 N번 처리하면 1,000,000번이고 N^2은 1억번이다.
//시간 초과 기준이 10^7 1초이므로 N^2은 터진다.

// 4. 완전탐색 기준선 — 가장 직접적인 풀이
// 질문: 배열을 받아 정답을 반환하기까지, 어떤 순서로 처리할 것인가?
//       무엇을 확인하고, 언제 저장하고, 언제 넘어가는가?
// 내 답: 순서대로 처리를 하고, 해당 숫자가 다음에 나올 인덱스의 숫자와 동일
//한지를 본다. 다음 인덱스의 숫자가 동일하지 않을 때 저장을 하고, 동일할 경우에는 저장하지 않는다.
//예외 처리에 대한 부분은 마지막 인덱스일 경우에 그냥 무조건 넣는 것이다.
//오른쪽과 비교하는 것이기 때문에, 왼쪽 인덱스가 같은 숫자들의 나열이라고 하더라도, 그냥 넣으면 된다.

// 5. 병목 → 자료구조·알고리즘 선택
// 질문: 위 절차에서 반복해서 찾거나 계산하는 비싼 작업이 있는가?
//       필요한 정보는 무엇이고, 어떤 자료구조와 연산으로 처리할 것인가?
//       이미 충분히 효율적이라면 그 이유는 무엇인가?
// 내 답:자료구조와 알고리즘의 본질, 자료구조 - 정보를 어떤 방식으로 저장을 할 것인가? 알고리즘 - 저장된 정보를 어떤 방식으로 계산을 할 것인가?
//비싼 작업이나 반복은 없다. arr 배열 기준으로 전체 탐색을 바탕으로 해당하는 인덱스에 대한 조건 비교를 통한 answer에 push를 하는 작업은 필연적으로 모든 원소 기준으로 해야 하는 작업이기 때문이다. 이미 충분히 효율적이다.
//모든 원소를 기준으로 순회하면서 조건을 비교하고 연산을 하고 있기 때문이다.

// 6. 선서술·불변식·비용 검산
// 질문: 매 반복을 시작할 때 answer에는 어떤 결과가 저장되어 있는가?
//       저장하거나 넘어가는 처리가 왜 필요한 값을 빠뜨리거나 중복시키지 않는가?
//       마지막 원소까지 처리하면 왜 전체 정답이 되는가?
//       선택한 풀이의 전체 시간·공간 복잡도는 얼마이며, 그 근거는 무엇인가?
// 내 답: 매 반복을 시작할 때 answer에는 이전 인덱스를 기준으로 지금 인덱스에 해당하는 원소와의 비교를 통해서, 이전 인덱스가 해당 인덱스와 값이 다를 경우 이전 인덱스의 값이 들어가있고, 아니라면 없다.
//저장하거나 넘어가는 처리가 조건에 대한 검증을 이미 다 끝낸 상태로 진행을 하는 것이기 때문에 값을 빠뜨리거나 중복 시키지 않는다.
//마지막 원소까지 처리하면, 이전에 for문 내부에 조건에 따라서 answer에 원소를 추가하기 때문에 정답이 된다. <- 이게 아닌가? 대답을 어떤 식으로 해야 하는 걸까?
//전체 시간 복잡도는 1 <= O(N) <= 1,000,000 이다. 근거는 for문을 배열의 크기만큼 순회를 하며, 내부적으로 if 문에 따른 비교 연산만 처리하기 때문이다. <- 내가 궁금한 게 내부적으로 처리하는 계산은 뭐지? 그러니까, 이 계산이 의미하는 게 정확히 뭐지? 그냥 계산 한 번? O(N) 이거는? 해당하는 계산을 위에서 아래로 내려오면서 수행을 한다 이건가?

// 7. 검증
// 질문: 내 풀이의 어떤 실수를 잡기 위해 어떤 입력을 시험할 것인가?
//       예상 결과와 실제 결과는 무엇인가?
//       컴파일·예제·경계값·프로그래머스 채점은 각각 어디까지 확인했는가?
// 내 답: 내 풀이의 어떤 실수를 잡기 위해서 원소가 하나인 경우와 동일한 원소가 반복되는 경우에 대한 입력을 테스트 케이스로 넣어서 돌려볼 것이다. <- 와 신기하다 그래 이게 내가 이전에 처음에 풀이를 했었을 때 내가 하지 않았었던 거였어! 테스트 케이스 7 / 1,1,1,1,1 넣어서 깔끔하게 통과했다. 아 오케이, 이러면 visual studio에서 디버깅 안 해도 되지 ㅋㅋ

// 8. 회고
// 질문: 처음에 무엇을 잘못 생각했고, 어떤 근거로 수정했는가?
//       다음 문제에서도 사용할 수 있는 판단 기준은 무엇인가?
// 내 답: 처음에 stack 자료구조를 무조건 사용을 해서, stack을 써야 하는 줄 알고해당 stack에 값을 어떤 식으로 채워넣고 사용을 할까 이런 식으로 생각을 했었는데,지금 다시 생각을 해보면, 그냥 arr 인덱스 기준으로 비교를 해서, 자료 구조 안에 넣기만 하면 되는 거고 array를 사용을 하던, queue를 쓰던, deque을 쓰던 자료 구조, 즉 arr 기준으로 연속되는 중복 인덱스 제거한 정답값을 return하는 것을 기준으로는 그냥 아무 자료구조 써도 상관 없었는데 vector가 return하는 값이니까 vector를 썼다.
```

사용자 소감: “좋다 이제 좀 방향이 잡힌 것 같다”.
