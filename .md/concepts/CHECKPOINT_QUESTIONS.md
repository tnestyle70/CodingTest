## 검문소 1 — 목표 고정 (한 문장)

**질문 형태**: "입력 \_\_\_가 주어질 때, \_\_\_ 규칙으로 \_\_\_를 반환한다"를 한 문장으로.

**요지**: 문제를 내 언어로 재서술한 명세 1문장. 입력·출력·선택 규칙(정렬 기준, 동률 규칙, 개수 제한)이 전부 들어가야 한다.

**본질**: **오독은 코드가 아니라 문장에서 잡는 게 가장 싸다.** 코테 오답의 큰 몫은 알고리즘 실패가 아니라 명세 오해다 — 반환 형식, 정렬 방향, 동률 처리. 목표 문장이 있어야 이후 검문소 5개가 검증할 **대상**이 생긴다. 명세 없는 설계는 채점할 수 없다. 마스터 식의 "문제" 슬롯.

**합격 기준**: 지문을 안 본 사람이 이 문장만 읽고 같은 출력을 만들 수 있는가. "대충 장르별로 뽑는 문제"는 미충족 — 동률 규칙까지 문장 안에 있어야 충족.

**베스트앨범**: "각 장르의 총 재생 횟수가 큰 순서대로 장르를 정하고, 장르마다 재생 횟수가 큰 노래를 최대 2곡 선택하되, 동률이면 고유 번호가 작은 노래부터 담아 선택된 노래들의 고유 번호를 반환한다."

## 검문소 2 — 제약 어휘

**질문 형태**: N의 범위, 값의 범위, 종류 수, 중복/유일성, 보장 조건을 빈칸 문장으로.

**요지**: 제약표의 **모든 숫자와 조건에 역할을 붙인다**. 숫자는 "개수/값의 범위/종류 수" 중 무엇인지, 보장 조건은 "그래서 무엇을 안 해도 되는지".

**본질**: **제약은 장식이 아니라 출제자가 숫자로 미리 알려준 힌트다.** N 상한은 허용 복잡도를 지목하고(검문소 3의 입력값), 보장 조건은 처리하지 않아도 될 분기를 지워준다. 역할 확인을 건너뛰면 실제로 사고가 난다 — gotchas 2026-07-26: 값의 범위 200,000을 루프 횟수·set 크기로 오용 3회, 20자리 번호를 정수 변환 시도 2회, **한 세션 5회 이상 재발**.

**합격 기준**: 숫자마다 개수/값/종류 라벨. 보장 조건마다 "덕분에 \_\_\_를 안 해도 된다" 한 마디.

**베스트앨범**: N ≤ 10,000(개수) · 장르 100개 미만(종류 수) · 장르별 총합은 서로 다름(보장 — 장르 동률 분기를 안 짜도 된다). 2026-10-02 확인한 [공식 지문](https://school.programmers.co.kr/learn/courses/30/lessons/42579)에는 plays[i]의 수치 상한과 장르 문자열 최대 길이가 명시되어 있지 않다. 이전 문서의 plays≤10,000 및 합계≤10⁸은 근거 없는 가정이므로 철회한다. 값의 범위는 오버플로뿐 아니라 배열·DP·탐색 범위를 결정할 수도 있다.

## 검문소 3 — 예산 산술

**질문 형태**: N 최댓값은? O(N²)이면 몇 번? 목표 시간·공간 복잡도는?

**요지**: 설계를 시작하기 **전에** 입력 규모를 후보 비용식에 대입하고 목표 시간·공간 복잡도를 세운다. 숫자 역할 확인 → 후보 비용식에 대입 → 제한·연산 내용 검토 → 목표 선언. 알고리즘 선택 후 전체 비용을 다시 계산한다.

**본질**: **복잡도는 설계 전의 예산이자 설계 후의 검산이다.** 연산당 비용과 호출 횟수를 나누면 병목을 구체적으로 찾을 수 있다. 과거 map 사용 풀이의 시간 초과 기록은 연산 비용을 비교할 이유지만, O(N log N)이라는 표기만으로 시간 초과를 확정할 수는 없다. 제한과 연산 내용, 실제 실행 증거를 구분한다.

**합격 기준**: N 등의 의미, 최댓값 대입, 연산 횟수×한 번 비용, 목표 시간·공간까지. 최악/평균/상환을 구분한다. "N²은 느릴 것 같다" 또는 "10⁸회니까 정확히 1초"는 근거가 부족하다. 미확인 시간 제한은 미확인으로 남긴다.

**베스트앨범**: N=10,000에서 N²=10⁸, N log₂ N≈1.33×10⁵ 규모를 비교한다. 그룹 수 G와 문자열 길이 L도 구분한다. 해시 그룹핑은 최악 O(NGL), 평균 O(NL); 그룹별 정렬은 Σ n_g log n_g≤N log N. 문자열 길이를 유계로 취급하면 평균 O(N log N), 추가 저장은 문자열까지 포함해 O(N+GL)로 요약할 수 있다. 실제 입력 제약 G<100도 함께 검토한다.

## 검문소 4 — 완전탐색 기준선

**질문 형태**: 손으로 정답을 만들던 절차를 가장 직접적으로 프로그램으로 옮기면 어떻게 되는가? 그 비용은?

**요지**: 후보/진행 상태 생성 → 조건 판정 → 출력 구성까지 반복 구조가 보이게 서술한다. 배열·방문 표시·재귀 등의 사용은 허용된다. 일부러 무저장·비효율적인 풀이를 만들 필요는 없다.

**본질**: 기준선은 ① 작은 입력에서 최적화 풀이와 비교할 **정확성 기준** ② 반복 비용을 찾는 **병목 노출 장치**다. 단, 완전탐색이라는 이름만으로 정확성이 보장되지는 않는다. 후보의 완전성과 판정·출력 규칙이 맞아야 한다. 직접 풀이가 이미 예산 안이라면 그것을 최종 풀이로 사용해도 된다.

**합격 기준**: 입력부터 출력까지의 직접 절차와 비용. 후보가 빠지지 않는 이유를 설명하고 비싼 부분이 있으면 가리킨다. 막히면 원소 3~4개로 손풀이한 동작부터 적는다.

**베스트앨범**: 각 곡 i마다 모든 곡을 훑어 같은 장르의 총합과 장르 안에서 i보다 앞설 곡 수(재생 수 내림차순, 번호 오름차순)를 구한다. 앞설 곡이 2개 미만인 곡만 남기고, 장르 총합→재생 수→번호 기준으로 최종 정렬해 번호를 반환한다. 직접 스캔은 최악 O(N²L), 이후 정렬할 곡은 최대 2G개다. 장르 합계 스캔만 적고 출력 구성은 생략하면 아직 전체 기준선이 아니다.

## 검문소 5 — 병목 → 유형 선택 (프레임워크의 심장)

**질문 형태**: 기준선에서 무엇을 반복해서 찾거나 계산하는가? 다음 판단에 어떤 정보가 필요하고, 어떤 순서로 조회·선택·갱신해야 하는가?

**요지**: ① 비싼 일을 문장으로 뽑고 ② 필요한 상태·조회·갱신·처리 순서를 정하고 ③ 저장/정렬/재사용/안전한 후보 제거 중 비용을 줄이는 방법을 검토한다. 키/값 질문은 연관 조회에 유용하지만 모든 유형의 필수 형식은 아니다.

**본질**: **필요한 연산과 상태가 자료구조의 요구사항이다.** 해시는 키 조회, 스택/큐는 다음 처리 순서, 힙은 현재 극값, DP는 같은 부분 문제의 재사용, 이분탐색은 단조성을 이용한 후보 제거로 읽는다. 입력·상태가 변하는지만으로 구조를 결정하지 않는다. 추가만 하는 최솟값은 변수 하나로 유지할 수 있고 해시도 갱신할 수 있다. 개선 후에는 절약한 비용뿐 아니라 유지·갱신 비용도 다시 계산한다.

**합격 기준**: 비싼 연산의 문장 + 보존할 정보/처리 순서 + 선택 근거 + 개선 후 비용. 연관 조회이면 키/값을, 스택/큐이면 제거 순서와 저장 내용을, DP이면 상태와 전이를 설명한다. 불필요한 정보 제거와 후보 생략에는 정확성 근거가 필요하다.

**베스트앨범**: 반복 질문 = "이 장르의 총 재생 횟수는?"(입력 고정 후 불변) + "이 장르의 소속 노래 목록은?"(불변) → 키 = 장르(문자열, 키끼리 순서 불요) → `unordered_map<string, long long>` + `unordered_map<string, vector<{plays, index}>>`.

## 검문소 6 — 선서술·불변식 (X014)

**질문 형태**: 루프가 인덱스 i까지 돈 순간 무엇이 참인가? 입력 처리가 끝난 뒤 무엇을 어떤 순서로 하는가?

**요지**: 코딩 전에 ① 루프 불변식("i까지 처리한 순간 \_\_\_가 저장되어 있다")과 ② 후처리 순서(정렬 기준, 동률 규칙, 개수 제한)를 말로 서술한다. **코딩 전에 말한 것만 X014로 카운트** — 코딩 후 역산 서술은 0점.

**본질**: **불변식은 구현과 검증의 기준이다.** 상태의 의미를 정하고 초기화·유지·종료 후 정답과의 연결을 설명한다. 종료성도 확인한다. 그리디는 선택의 안전성, DP는 상태·전이의 충분성, 이분탐색은 단조성처럼 유형별 근거가 추가로 필요하다. 문장 하나가 구현이나 증명을 자동으로 완성해 주지는 않는다. 코딩 전에 한 설명과 코딩 후 복원한 설명은 별도로 기록한다.

**합격 기준**: 상태 의미 + 갱신 + 종료 후 출력 + 정확성 근거. 정렬 비교자의 true는 “a가 b보다 앞선다”는 뜻이다. **전체 기준에서 동등한 원소나 같은 원소 자신에 대해서는 false**여야 한다. 1차 기준만 동률이고 2차 기준이 다르면 true가 가능하다. 비반사성 외에도 추이성 등 엄격 약순서 조건이 필요하다. priority_queue에서는 비교 기준상 뒤인 원소가 top에 오므로 `less`가 max-heap을 만든다.

**베스트앨범**: "i까지 처리한 순간 totals에는 지금까지 본 노래들의 장르별 합계만, byGenre에는 지금까지 본 {plays, index}만 들어 있다. 입력 처리 후 장르는 총합 내림차순, 장르 내부는 (plays 내림차순, 동률 시 고유 번호 오름차순)으로 정렬하고 앞에서 최대 2곡." — 동률 분기의 코드 표현식은 복습 과제(프로브 목격·수정, 2026-07-28) 완료 후에 이 자리에 복원한다.

## 판결 후 — 7 4게이트 · 8 회고 (요약)

**7 4게이트**: Build · Example · Edge · Judge는 **서로 다른 증거**다. 컴파일 성공은 정답 증거가 아니며, 로컬 예제 통과는 숨은 테스트 통과 증거가 아니다. AC는 채점 통과의 증거이지만 모든 입력에 대한 수학적 증명은 아니다. 베스트앨범에는 AC 보고와 별개로 현재 보존된 동률 분기에서 명세와 반대 방향이 확인되는 미결 기록이 있다. 실제 제출본과의 일치나 숨은 테스트 내용은 확인하지 않았으므로 **특정 테스트가 없다고 단정하지 않는다.** 반례 실행과 수정은 미결 복습 과제로 유지한다.

**8 회고**: 회고 템플릿의 칸 = 마스터 식의 슬롯 (ESSENCE_BRIDGE 대응표). 예측 vs 실제(복잡도·실측 시간)를 대조해야 한 바퀴가 닫힌다. AC 뒤에만 tracker와 회고를 갱신한다.

## 운영 규칙 (Teaching Contract 요약 — 세션이 바뀌어도 불변)

- **한 턴에 질문 하나.** 대량 양식·정석 덤프 금지. 검문소 1~6 미답 시 구현 보류.
- 정석 공개는 **AC 후 요청 시에만**. 공개 후에도 다음 문제는 다시 질문 1단부터.
- 힌트 사다리: 질문 → 핵심 관찰 → 의사코드 → 부분 코드 → 전체 풀이. 위 단계로 바로 점프하지 않는다.
- 틀린 접근도 즉시 정정하지 않는다 — 시간 복잡도나 반례로 **판결**한 뒤 고친다.
- 책·해설 경험은 친숙함일 뿐이다. 빈 화면에서 독립 유도·구현·검증한 증거만 풀이 능력으로 기록한다.
