예시는 전부 베스트앨범(AC 2026-07-27, 공개 가능)으로 통일한다.

검문소 1 — 목표 고정 (한 문장)

질문 형태
"입력 가 주어질 때, 규칙으로 를 반환한다"를 한 문장으로.
요지
문제를 내 언어로 재서술한 명세 1문장. 입력·출력·선택 규칙(정렬 기준, 동률 규칙, 개수 제한)이 전부 들어가야 한다.
본질 — 오독은 코드가 아니라 문장에서 잡는 게 가장 싸다. 코테 오답의 큰 몫은 알고리즘 실패가 아니라 명세 오해다(반환 형식, 정렬 방향, 동률 처리). 목표 문장이 있어야 이후 검문소 5개가 검증할 대상이 생긴다 — 명세 없는 설계는 채점할 수 없다. 마스터 식의 "문제" 슬롯.

합격 기준: 지문을 안 본 사람이 이 문장만 읽고 같은 출력을 만들 수 있는가. "대충 장르별로 뽑는 문제"는 미충족 — 동률 규칙까지 문장 안에 있어야 충족.

베스트앨범 — "각 장르의 총 재생 횟수가 큰 순서대로 장르를 정하고, 장르마다 재생 횟수가 큰 노래를 최대 2곡 선택하되, 동률이면 고유 번호가 작은 노래부터 담아 선택된 노래들의 고유 번호를 반환한다."

검문소 2 — 제약 어휘

질문 형태
N의 범위, 값의 범위, 종류 수, 중복/유일성, 보장 조건을 빈칸 문장으로.
요지
제약표의 모든 숫자와 조건에 역할을 붙인다. 숫자는 "개수/값의 범위/종류 수" 중 무엇인지, 보장 조건은 "그래서 무엇을 안 해도 되는지".
본질 — 제약은 장식이 아니라 출제자가 숫자로 미리 알려준 힌트다. N 상한은 허용 복잡도를 지목하고(검문소 3의 입력값), 보장 조건은 처리하지 않아도 될 분기를 지워준다.
실사고 앵커 — gotchas 2026-07-26: 값의 범위 200,000을 루프 횟수·set 크기로 오용 3회, 20자리 번호를 정수 변환 시도 2회, 한 세션 5회 이상 재발. 역할 확인을 건너뛰면 반복되는 사고다.

합격 기준: 숫자마다 개수/값/종류 라벨. 보장 조건마다 "덕분에 를 안 해도 된다" 한 마디.

베스트앨범 — N ≤ 10,000(개수) · plays ≤ 10,000(값 — 합산 상한 10⁴×10⁴ = 10⁸ → int 안, 단 합산 변수라는 역할을 먼저 확인) · 장르 100개 미만(종류 수) · 장르별 총합은 서로 다름(보장 — 장르 동률 분기를 안 짜도 된다).

검문소 3 — 예산 산술

질문 형태
N 최댓값은? O(N²)이면 몇 번? 목표 시간·공간 복잡도는?
요지
설계를 시작하기 전에 시간·공간 상한을 숫자로 계산하고 목표 복잡도를 선언한다. 절차는 ESSENCE_CORE 2장(숫자 역할 확인 → 대입 → 10⁸ 비교 → 목표 선언).
본질 — 복잡도는 사후 분석이 아니라 사전 예산이다. 예산 없이 설계하면 "돌려보고 TLE면 고친다"는 도박이 된다. 예산이 있어야 검문소 4의 기준선을 탈락 판정할 수 있고, 검문소 5의 목표가 생긴다. 마스터 식의 "옮겨간 비용" 슬롯.
실사고 앵커 — gotchas 2026-07-26: map을 해시처럼 써서 효율성 테스트 시간 초과. 예산을 먼저 세웠으면 연산당 O(log N)×문자열 비교가 설계 단계에서 걸렸다.

합격 기준: 대입한 숫자와 판정("10⁸ = 1초 경계라 위험")과 목표 복잡도 선언까지. "N²은 느릴 것 같다"는 미충족 — 숫자가 있어야 충족.

베스트앨범 — N = 10,000 → O(N²) = 10⁸ (1초 경계, 도박 금지) → 목표 = 그룹핑 O(N) + 정렬 O(N log N), 공간 O(N).

검문소 4 — 완전탐색 기준선

질문 형태
아무것도 미리 저장하지 않으면 어떻게 푸는가? 그 복잡도는?
요지
가장 정직한(무저장) 풀이를 루프 구조가 보이게 서술하고 비용을 계산한다.
본질 — 기준선은 두 가지 일을 한다. ① 정확성의 기준선: 완전탐색에는 생략에 의한 오류가 없다 (단 명세 오독·오버플로는 그대로 공유한다 — 검문소 1이 먼저인 이유). 최적화 풀이가 의심스러울 때 비교할 정답 생성기가 된다. ② 병목 노출 장치: 안쪽 루프가 무슨 질문을 반복하는지 보려면 먼저 루프를 적어야 한다. 이걸 건너뛰면 검문소 5가 "이런 문제는 해시"라는 유형 암기로 퇴화한다 — 기준선 없이 고른 자료구조는 유도가 아니라 도박이다. 마스터 식의 "생략·재사용할 일" 슬롯의 전반부(무엇을 생략할지 보이게 만드는 단계).

합격 기준: 의사코드 수준 서술 + 복잡도. "그건 느리니까 패스"는 미충족 — 어느 루프가 느린지 가리켜야 충족.

베스트앨범 — 각 노래 i마다 전체 노래를 다시 훑어 ① 같은 장르의 plays 합산 ② 같은 장르 안에서 i의 순위 계산 → 같은 질문을 노래 수만큼 재계산 → O(N²).

검문소 5 — 병목 → 유형 선택 (프레임워크의 심장)

질문 형태
기준선에서 반복되는 질문은 무엇인가? "X가 주어지면 Y는?" 꼴로. 키는 무엇이고 값은 무엇인가?
요지
3단 판별 — ① 안쪽 루프가 반복하는 질문을 문장으로 뽑고 ② 그 답이 물을 때마다 변하는지 판정하고 ③ 불변이면 선계산(해시·누적 합·정렬), 변하면 갱신형(힙·트리)으로 번역한다. 표는 ESSENCE_CORE 4·5장.
본질 — 자료구조 선택은 암기가 아니라 유도다. 반복되는 질문이 곧 자료구조의 사양서다: "X가 주어지면 Y는?"로 정규화하면 X = 키, Y = 값이고, X의 성질(문자열/조밀 정수/순서 필요)이 구조를 정한다. 이 검문소가 무너지면 남는 것은 패턴 매칭이고, 패턴 매칭은 처음 보는 문제에서 즉시 파산한다 — Mission이 "처음 보는 문제를 번역하는 능력"인 이유가 이 칸이다. 복잡도 개선의 정체도 여기서 드러난다: O(N²)→O(N)은 마법이 아니라 "N번의 질문 × O(N) 재계산"을 "O(N) 선불 + N번의 O(1) 조회"로 바꾼 회계다.

합격 기준: 질문을 문장으로 + 키/값 명시 + 왜 이 구조인가(키의 성질) 한 마디. "해시 씁니다"는 미충족 — 질문이 먼저 나와야 충족.

베스트앨범 — 반복 질문 = "이 장르의 총 재생 횟수는?"(입력 고정 후 불변) + "이 장르의 소속 노래 목록은?"(불변) → 키 = 장르(문자열, 키끼리 순서 불요) → unordered_map<string, long long> + unordered_map<string, vector<{plays, index}>>.

검문소 6 — 선서술·불변식 (X014)

질문 형태
루프가 인덱스 i까지 돈 순간 무엇이 참인가? 입력 처리가 끝난 뒤 무엇을 어떤 순서로 하는가?
요지
코딩 전에 ① 루프 불변식("i까지 처리한 순간 가 저장되어 있다")과 ② 후처리 순서(정렬 기준, 동률 규칙, 개수 제한)를 말로 서술한다. 코딩 전에 말한 것만 X014로 카운트 — 코딩 후 역산 서술은 0점.
본질 — 코드는 불변식의 번역이고, 버그는 불변식 위반이다. 불변식을 먼저 말하면 ① 루프 몸통이 기계적으로 나오고(불변식을 유지하는 최소 행동이 곧 몸통) ② 디버깅이 "어느 줄이 불변식을 깨는가" 탐색으로 바뀌고 ③ 초기값과 종료 후 상태가 저절로 점검된다. 선서술 없는 AC는 양치기 재발이다(ESSENCE_BRIDGE 가동 규칙). 마스터 식의 "지켜야 할 불변식" 슬롯.
비교자 각주 (실사고 앵커) — 정렬이 있으면 비교자의 의미까지 선서술한다: 비교자 반환값은 "최종 순서에서 a가 b보다 앞인가?"에 대한 답이다 — swap 명령이 아니다. 부등호 방향 = 배치 방향(> 큰 것부터, < 작은 것부터), 동률에서 true 반환은 미정의 동작. gotchas 2026-07-27 — 부등호 도박으로 제출 1회가 2건 실패로 사망한 실사고. 단 이 독법은 std::sort 기준 — priority_queue의 비교자는 반대로 true = a가 뒤(낮은 우선순위)라서 less가 max-heap을 만든다.

합격 기준: "~까지 처리한 순간 ~만 들어 있다" 형식의 문장 + 후처리 순서(정렬 기준·동률·개수 제한까지).

베스트앨범 — "i까지 처리한 순간 totals에는 지금까지 본 노래들의 장르별 합계만, byGenre에는 지금까지 본 {plays, index}만 들어 있다. 입력 처리 후 장르는 총합 내림차순, 장르 내부는 (plays 내림차순, 동률 시 고유 번호 오름차순)으로 정렬하고 앞에서 최대 2곡." — 동률 분기의 코드 표현식은 복습 과제(프로브 목격·수정, 2026-07-28) 완료 후에 이 자리에 복원한다.

게이트증거아닌 것

운영 규칙 (Teaching Contract 요약 — 세션이 바뀌어도 불변)

  • 한 턴에 질문 하나. 대량 양식·정석 덤프 금지. 검문소 1~6 미답 시 구현 보류.
  • 정석 공개는 AC 후 요청 시에만. 공개 후에도 다음 문제는 다시 질문 1단부터.
  • 힌트 사다리: 질문 → 핵심 관찰 → 의사코드 → 부분 코드 → 전체 풀이. 위 단계로 바로 점프하지 않는다.
  • 틀린 접근도 즉시 정정하지 않는다 — 시간 복잡도나 반례로 판결한 뒤 고친다.
  • 책·해설 경험은 친숙함일 뿐이다. 빈 화면에서 독립 유도·구현·검증한 증거만 풀이 능력으로 기록한다.
