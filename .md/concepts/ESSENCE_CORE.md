## 1. 두 정의

### 자료구조의 본질

> **자료구조 = 필요한 조회·삽입·삭제·선택을 원하는 비용으로 수행하도록 상태를 표현하고 배치하는 방법.**

- 각 구조의 **지원 연산과 비용 계약**을 읽는다. 고정 크기 키 기준 해시 조회는 최악 O(N)·평균 O(1), 힙의 극값 확인은 O(1), 스택의 마지막 잔여 원소 확인은 O(1)이다.
- 선계산은 그중 한 전략이다. 스택·큐는 처리 순서를, 힙은 극값을 찾기 위한 부분 순서를 유지한다.
- 따라서 먼저 **무엇을 보존하고, 무엇을 조회·선택·갱신하는가**를 묻는다. 키로 값을 찾는 문제라면 키/값을 정하고, 다음 처리 대상을 고르는 문제라면 최근·먼저 도착·극값 등 선택 규칙을 정한다.

### 알고리즘의 본질

> **알고리즘 = 입력에서 요구한 출력을 얻기 위해 상태를 바꾸고 판단하는, 명확하고 유한한 절차.**

- **정확성의 근거를 설명한다.** 반복문은 불변식의 초기 성립·유지·종료 후 결론을 확인하고, 종료 자체도 설명한다. 재귀의 귀납, 그리디의 교환 논증, 이분탐색의 단조성 등 문제에 맞는 근거를 함께 쓴다. 컨테이너가 정상 동작한다는 사실만으로 문제의 정답은 보장되지 않는다.
- **비용은 실제 연산 수로 설명한다.** 최적화는 반복 계산·불필요한 후보·재탐색을 줄이거나, 배치·처리 순서·연산 자체를 바꾼다. 생략한 일을 말하는 것은 유용한 질문이지만 모든 알고리즘의 정의는 아니다.

### 둘의 관계 — 3단 판별

알고리즘은 처리 규칙을 정하고, 자료구조는 그 규칙에 필요한 상태와 연산을 지원한다. 판별 순서는:

1. **필요 연산 찾기** — 가장 직접적인 올바른 풀이에서 무엇을 반복해서 조회·선택·계산하는가?
2. **변화 규칙 확인** — 입력이 고정되는가, 추가만 되는가, 삭제·수정도 되는가?
3. **전체 비용 비교** — 저장·구축·조회·갱신을 합쳐 선택한다. 고정 구간 합에는 누적 합, 동적 빈도에는 해시, 추가만 하는 최솟값에는 변수 하나로 충분할 수 있다.

## 2. 시간 복잡도 — 성장률과 예산

### 정의

- 빅오는 입력 크기에 따른 비용의 **점근적 상한**이다. 대표식 N·N²·log₂N에 N의 10배를 넣으면 각각 10배·100배·약 3.3 증가한다. 이 대입값은 실제 초나 정확한 CPU 명령 수가 아니다.
- **최악을 먼저 적고**, 평균(unordered 계열)은 조건을 명시한 뒤에만 쓴다 (Evidence Rules). 상환(vector push_back)도 같은 취지로 조건 명시 후에만 쓴다 (이 문서의 확장).
- 후보는 복잡도로 좁히고 **승자는 채점기 실측으로만** 확정한다 (보정 3 — 빅오가 예산 안이어도 상수·캐시로 흔들린다).

### 성장률 사다리 (N = 10⁵를 대표식에 대입)

| 비용의 대표식 | N=10⁵ 대입값 | 설계 판단 |
|---|---:|---|
| 1 | 1 | 연산 1회의 비용 확인 |
| log₂N | ≈17 | 단계당 비용 확인 |
| N | 10⁵ | 후보로 검토 |
| N log₂N | ≈1.7×10⁶ | 후보로 검토 |
| N² | 10¹⁰ | 일반적인 코테 제한에서 개선 필요성이 매우 큼 |
| N³ | 10¹⁵ | 일반적인 코테 제한에서 전량 실행 곤란 |
| 2ᴺ | 2¹⁰⁰⁰⁰⁰ | 전량 열거 곤란 |

### 예산 산술 절차 (검문소 3에서 이 순서대로)

1. 제약의 숫자마다 **개수 N, 값 범위 U, 문자열 길이 L, 질의 수 Q**처럼 역할을 붙인다. 값 범위가 곧 입력 개수는 아니다. 다만 계수 배열·값 기반 DP·답 이분탐색에서는 U도 시간·공간에 들어간다.
2. **연산 횟수 × 한 번의 비용**을 단계별로 쓰고, 순차 단계는 합한다. N·N²·N log N 등의 대입값을 공식 시간 제한·연산 종류와 함께 판단한다. '10⁸회 = 1초' 같은 고정 환산이나 언어별 고정 속도는 쓰지 않는다. 제한이 없으면 미명시로 기록한다.
3. 문자열 비교·해시·복사처럼 **길이에 의존하는 연산에만** L을 반영한다. 최대 길이가 L이면 문자열 비교는 최악 O(L)이고, 전체 문자를 읽는 해시 계산은 O(L)이다. 정수 인덱스 접근까지 L을 곱하지 않는다.
4. 합산·곱셈 결과의 상한도 계산한다. 가령 'N≤10⁴, 각 값≤10⁴'가 실제 주어진 문제라면 합은 ≤10⁸이다. 32비트 int와 64비트 long long의 최댓값은 각각 약 2.1×10⁹, 9.2×10¹⁸이며, 저장 전 중간 계산 타입도 확인한다. 지문에 없는 상한은 만들어 넣지 않는다.

### 입력 크기별 비용 규모 — 허용 복잡도 확정표가 아님

| 입력 규모 | 대입 예 | 함께 확인할 것 |
|---|---|---|
| N=10 / 11 | 10!≈3.6×10⁶ / 11!≈4.0×10⁷ | 순열 1개 생성·검사·복사 비용 |
| N=20 / 25 | 2²⁰≈10⁶ / 2²⁵≈3.4×10⁷ | 부분집합당 검사 비용과 저장량 |
| N=500 | N³=1.25×10⁸ | 삼중 루프 내부 연산과 시간 제한 |
| N=5,000 | N²=2.5×10⁷ | 비교·할당·문자열 처리 여부 |
| N=10⁶ | N log₂N≈2.0×10⁷ | 정렬·힙·트리의 서로 다른 상수와 메모리 |
| N=10⁷ | N=10⁷ | 입력 자체의 읽기·저장 비용 |
| 값 범위 U=10¹⁸ | √U=10⁹ / log₂U≈60 | 입력 개수와 구분. 이분탐색은 판정 1회 비용도 곱함 |

표는 후보를 비교하기 위한 규모 감각이다. 출력량·테스트 케이스 수·내부 연산·메모리 접근까지 확인하고, 비용이 큰 후보는 개선 가능한 병목을 찾는다. 통과 여부는 실제 제출 증거로만 기록한다.

### 자주 쓰는 수치 (암산용)

- log₂10 ≈ 3.3 → log₂(10⁵) ≈ 17, log₂(10⁶) ≈ 20
- 2¹⁰ ≈ 10³, 2²⁰ ≈ 10⁶, 2³⁰ ≈ 10⁹
- 10! ≈ 3.6×10⁶ · 11! ≈ 4.0×10⁷ · 12! ≈ 4.8×10⁸ — 경우당 비용을 곱하기 전 값
- 조합 폭발 감각: 2ᴺ은 N+10마다 ×1000

## 3. 공간 복잡도 — 메모리 예산

- 정의: 사용하는 메모리의 점근적 크기. 여기서는 기본적으로 **보조 공간**(입력 외 추가 공간)을 적고, 출력 공간 포함 여부를 명시한다. 제한과 비교할 때는 입력·출력·복사본을 포함한 최대 동시 사용량을 바이트로 추산한다.
- 메모리 제한은 공식 조건을 확인하고, 미명시이면 임의의 한도를 사실처럼 두지 않는다. 원소당 4바이트라면 10⁶개≈4MB, 10⁷개≈40MB, 10⁸개≈400MB다. 10⁴×10⁴ 배열도 400MB이며, 컨테이너 부가 비용은 별도다.
- **재귀 깊이도 공간이다.** 깊이 × 프레임 크기를 고려한다. 호출 스택 한도는 환경·빌드 설정에 따라 다르므로 고정 MB를 가정하지 않는다. 깊이가 큰 입력에서는 명시적 스택/반복 구현을 검토한다.
- 선계산·캐시는 시간과 공간을 교환할 수 있다. 예를 들어 해시로 반복 선형 검색을 대체하면 추가 O(N) 공간으로 **평균** O(N) 전체 처리를 얻을 수 있으나, 충돌에 따른 최악 O(N²)은 별도로 적는다.

## 4. 필요한 연산 → 자료구조 표

사용법: 기준선의 반복 조회·선택·갱신을 아래 왼쪽 열과 연결한다. 아래는 고정 크기 원소·O(1) 비교 기준이며, 문자열·복사 비용은 따로 합친다. 컨테이너별 비용·함정 상세는 [STL_COST_SHEET.md](STL_COST_SHEET.md).

| 반복되는 질문 | 답하는 구조 | 질문당 비용 | 선불 비용 | 신호 |
|---|---|---|---|---|
| i번째 값은? | vector / 배열 | O(1) | O(N) 저장 | 기본값 — 고민 없으면 이것 |
| 이 키의 값은? / 본 적 있나? / 몇 번인가? | unordered_map / unordered_set | **최악 O(N)** · 평균 O(1) | 최악 O(N²) · 평균 O(N) 구축 | 존재·빈도·짝·그룹핑 |
| 정렬 순서상 존재/위치/범위는? (이후 갱신 없음) | 정렬 배열 + 이분탐색 | O(log N) | O(N log N) 정렬 | 여러 번 묻는 존재·경계 질문 |
| 이상/이하/최근접 키는? (삽입·삭제 섞임) | map / set (일반적으로 균형 검색 트리) | O(log N) 비교 | O(N log N) (N개 삽입, 문자열 비교는 길이 비용 추가) | 순서 질문 또는 최악 로그 조회 보장이 필요 |
| **가장 최근의 미해결 항목은?** | stack | O(1) | — | 괄호, 되돌리기, 가장 가까운 이전/다음 큰 원소 |
| **가장 오래 기다린 항목은?** | queue | O(1) | — | 대기열 시뮬, 도착 순 공정, BFS |
| 양끝 모두에서 넣고 뺀다 | deque | O(1) | — | 슬라이딩 윈도우 극값 |
| 지금 최솟/최댓값은? (삽입·극값 삭제 섞임) | priority_queue (힙) | top O(1) · push/pop의 힙 조정 O(log N); 기본 vector 재할당은 별도 | N회 push 총 O(N log N) · make_heap O(N) | 반복 극값 추출. 기본은 **max-heap** |
| 구간 [i, j]의 합은? (원소 불변) | 누적 합 | O(1) | O(N) | 구간 질문 다발 |
| 같은 그룹인가? / 그룹 합치기 | 유니온 파인드 | 랭크 union+경로 압축: 연산 1회 최악 O(log N), 연산열에서 상환 O(α(N)); 두 최적화가 없으면 최악 O(N) 가능 | O(N) | 연결성·병합 |
| 이 노드의 이웃은? | 인접 리스트 | O(차수) | O(V+E) 구축 | 관계·연결 문제 전부 |

**갱신 종류를 구분한다**: 추가만 하는 '지금까지의 최솟값'은 변수 하나를 `min`으로 갱신하면 된다. 현재 최솟값이 삭제될 수 있으면 남은 후보 정보가 더 필요하다. 해시도 갱신 가능하며, 답이 변한다는 사실만으로 힙·트리가 결정되지는 않는다.

## 5. 알고리즘 패러다임 — 본질 한 문장 표

ESSENCE_BRIDGE 10유형에서 알고리즘 패러다임을 추리고, 정본에 없는 투 포인터·백트래킹·분할정복을 추가했다 (해시·스택/큐·힙 등 자료구조 유형은 4장 표가 담당). 여기는 "본질 한 문장 + 적용 판별"만 담는다. 유형별 불변식은 ESSENCE_BRIDGE 참조.

| 패러다임 | 본질 한 문장 | 적용 판별 질문 | 전형 복잡도 |
|---|---|---|---|
| 완전탐색 | 생략하지 않기로 한 **결정** — 대신 예산 산술이 선행한다 | 최악 경우 수 × 경우당 비용이 예산 안인가? | 상태 공간 크기에 비례 |
| 정렬 기반 | 순서 재배치로 비교·처리 구조를 단순화 | 정렬 후 이웃·경계·차례대로 처리할 근거가 생기는가? | 비교 O(N log N); 비교 1회 비용 별도 |
| 이분탐색 | **단조성**으로 후보 절반을 생략 | 판정 함수가 거짓→참 또는 참→거짓으로 많아야 한 번 뒤집히는가? | O(log 범위) × 판정 비용 |
| 투 포인터 / 슬라이딩 윈도우 | 포인터의 단조 이동으로 이중 루프의 **재시작을 생략** | 뒤로 돌아갈 필요가 없음을 증명할 수 있는가? | O(N) |
| DFS/BFS | 상태=노드, 행동=간선 **번역** + visited로 재방문 생략 | 상태 공간이 그래프로 그려지는가? | O(V+E) — 인접 리스트 + O(1) visited 전제 (set/map visited·문자열 상태면 log·L 배수) |
| 백트래킹 | 선택을 쌓고 되돌리는 탐색; 불가능하거나 개선 불가능한 가지는 증명 후 생략 | 부분 상태를 어떻게 확장·복원하며, 어떤 가지를 안전하게 자를 수 있는가? | 최악 탐색 노드 수 × 노드당 비용; 가지치기가 안 되는 경우부터 계산 |
| 그리디 | 선택이 안전하다는 증명으로 다른 선택 탐색을 생략 | 지역 선택이 최적해로 이어질 가능성을 보존하는가? 교환 논증·앞서가기 등으로 설명 가능한가? | 정렬·선택·갱신 비용의 합; 정렬 기반이면 흔히 O(N log N) |
| 분할정복 | 같은 꼴의 더 작은 문제를 풀고 결합 | 어떻게 줄이고, 기저 사례는 무엇이며, 답을 어떻게 합치는가? | 재귀식으로 계산; 2T(N/2)+O(N)이면 O(N log N) |
| 동적 계획법 | 상태별 부분 문제 답의 **재사용** — 상태는 부분 문제를 유일하게 정하는 정보 | 상태 의미·기저값·점화식·계산 순서를 설명할 수 있는가? | 총 상태별 전이 비용의 합 |

Kit 카테고리는 배타적인 분류가 아니다. 자료구조(해시·스택/큐·힙), 절차·설계 전략(정렬·완전탐색·그리디·DP·DFS/BFS·이분탐색), 표현 대상(그래프)이 섞여 있으며 한 풀이에서 조합된다. 기준선의 낭비는 후보를 제안하고, 상태 충분성·단조성·최적성 보존 같은 조건을 확인해야 최종 선택이 된다.

## 6. 검문소 접속점 (이 문서를 언제 펴는가)

| 검문소 | 이 문서에서 보는 곳 |
|---|---|
| 3 예산 산술 | 2장 절차 + 역표, 3장 메모리 (옆에 STL_COST_SHEET) |
| 4 완전탐색 기준선 | 1장 필요한 상태·연산 — 직접적인 올바른 절차가 노출할 병목 |
| 5 병목→유형 | 4장 질문 표 + 5장 패러다임 표 — 안쪽 루프의 질문을 소리 내 읽고 찾기 |
| 6 선서술·불변식 | 1장 정확성 근거·종료성 (유형별 예는 ESSENCE_BRIDGE) |

이 문서는 정의와 표만 담는다. **문제별 풀이는 담지 않는다** (Teaching Contract 준수).
