# 코딩테스트 답변과 도움 요청 원칙

적용일: 2026-10-11 Asia/Seoul

목표는 풀이 코드를 받아 실행하는 데서 끝나지 않고, 조건·상태·갱신·비용을 스스로 설명하고 검증하는 것이다. 공통 8단계는 그 과정을 확인하는 질문이다. 장문의 답변이나 특정 표현의 암기를 요구하지 않는다.

## 답변을 쓰는 시점

| 시점 | 작성할 내용 | 충분한 초안의 기준 |
|---|---|---|
| 코딩 전 | 1 목표, 2 제약, 3 예산 | 입력·규칙·출력, 숫자의 역할, 후보 작업량을 짧게 작성 |
| 코딩 전 | 4 직접 절차, 5 선택, 6 상태·근거·비용 | 작은 입력에서 실행할 수 있는 절차와 각 상태의 의미를 설명 |
| 코딩 전 | 7의 예상 테스트 | 잡으려는 오류를 정하고 입력·기대값을 먼저 적음 |
| 구현과 검증 후 | 6 재검산, 7 실제 결과 | 구현이 초안과 같은지 확인하고 컴파일·예제·경계·채점을 구분 |
| 한 번의 시도 후 | 8 회고 | 처음의 가정, 처음 어긋난 상태, 수정 이유, 재사용할 기준 |

1~6의 각 답은 보통 1~3문장으로 시작한다. 표나 작은 손추적을 사용해도 된다. 16/16은 설명의 정확성을 높이는 목표이며 코딩 착수 자격증이 아니다. 막힌 칸에는 무엇이 불확실한지 적고 그 부분부터 도움을 받는다. 이미 코드를 가져온 경우 그 시도를 검토하면서 빠진 설명에 연결한다.

## 상태를 먼저 설명한다

5~6번 안에서 아래 내용을 확인한다. 별도의 아홉 번째 양식을 만들지 않는다.

```text
변수/자료구조의 의미:
초기값이 맞는 이유:
한 단계에서 일어나는 사건과 처리 순서:
사건마다 바뀌는 값 / 유지되는 값:
끝나는 조건과 그때 결과가 정답인 이유:
```

같은 사실을 여러 곳에 저장한다면 함께 갱신할 조건도 적는다. 예를 들어 목록과 합계를 동시에 보관하면 목록에 추가·삭제하는 사건에서 합계가 어떻게 변해야 하는지 확인한다. 자료구조의 이름보다 필요한 읽기·추가·제거 연산을 먼저 적는다.

## 수정 전에 한 가지 원인을 정한다

- 처음부터 전체 코드를 다시 바꾸지 않고, 기대 상태와 실제 상태가 처음 달라지는 지점을 찾는다.
- `front`, `top`, 인덱스 접근 전 유효성 조건이 먼저 평가되는지 확인한다.
- 삭제·추가 뒤에도 쓰는 인덱스·참조·반복자가 유효한지 확인한다. 범위 for에서 순회하는 vector를 구조적으로 바꾸는 경우 특히 점검한다.
- 코드를 옮기는 수정은 중괄호까지 확인한다. “반복마다 실행”과 “반복 종료 후 한 번 실행”을 구분한다.
- 줄을 켜거나 끄기 전에 예상 변화를 한 문장으로 적고, 실행 뒤 실제 변화와 비교한다.

## 막히면 질문할 자료를 작게 만든다

```text
입력:
기대 결과 또는 기대 상태:
실제 결과 또는 막힌 지점:
현재 생각하는 원인 한 문장:
```

아직 실행할 수 없으면 실제 결과 대신 손추적에서 막힌 지점을 적는다. 원인을 모르면 모른다고 쓰고, 가장 작은 입력부터 같이 추적한다. 이 형식을 완성하지 못했다는 이유로 질문을 막지 않는다.

도움은 한 번에 한 초점으로 질문 → 관찰 → 의사코드 → 부분 코드 순서로 진행한다. 작은 과제를 해도 막히면 같은 질문만 반복하지 않고 도움을 한 단계 구체화한다. 전체 풀이·양식을 명시적으로 요청하면 요청 범위에 맞춰 제공한다.

## 도움받은 뒤 직접 확인한다

수정 코드를 받았으면 왜 달라지는지 자기 말로 설명하고, 다른 작은 입력에서 다음 상태를 예측한다. 그 다음 예시를 가리고 필요한 부분을 직접 구현하고 검증한다. 한 번에 해내지 못하면 막힌 단계로 돌아가 도움을 받는다.

“도움받아 해결”, “코드 없이 설명”, “백지에서 복원”, “새 문제에 적용”을 별도로 기록한다. 도움받은 해결도 진행으로 인정하되 독립 풀이로 바꾸어 적지 않는다. 이후 복원은 실제 수행과 결과가 있을 때 기록한다.

## 원문과 검증 증거를 보존한다

- 사용자 답변 원문은 유지하고 틀리거나 빈 부분만 보완한다. 1번에 쓴 절차는 버리지 말고 알맞은 칸으로 옮긴다.
- 채점은 기존 0·1·2점 기준을 유지한다. 미답은 미답이며, 문장 길이와 용어 일치로 감점하지 않는다. 사후 답변에 새 기준을 소급하지 않는다.
- 시도와 오류 기록은 AC 전에도 남긴다. 컴파일, 일부 테스트, 채점 통과, 독립 설명을 구별한다.
- 프로그램이 정상 동작하지 않는 원인과 아직 측정하지 않은 성능을 구별한다. 최악 비용을 계산하되 실제 채점 없이 시간 초과나 AC를 확정하지 않는다.
- 코치는 여러 오류를 한꺼번에 고치게 하기보다 현재 확인할 한 가지를 먼저 정하고, 코드 예시 뒤에는 학습자가 확인할 작은 과제를 남긴다.
