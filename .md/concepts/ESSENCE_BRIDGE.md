# 본질 브리지 — Winters 마스터 식 × 프로그래머스 Kit

작성일: 2026-07-25. 원본 = Winters 레포 `.md/interview/cards/11_자료구조_알고리즘_본질_Winters실물.html` (자료구조·알고리즘 본질 포털). 이 문서는 그 포털의 재유도 문법을 Kit 10개 유형에 투영한 지도다. **문제별 풀이는 담지 않는다** (Teaching Contract 준수 — 유형 수준의 불변식·신호까지만).

교정일: 2026-10-02. 마스터 식은 풀이를 되짚는 관점이며 모든 문제를 선계산·키/값으로 만드는 규칙은 아니다. 코딩 전 작성 순서는 [통합 풀이 사고 가이드](2026-10-02_UNIFIED_PROBLEM_SOLVING.md)를 따른다.

## 마스터 식 (모든 유형을 같은 문법으로 읽는다)

```text
문제 → 보존할 상태·활용할 성질 → 정확성 근거 → 생략·재배치·재사용할 일 → 전체 비용 → 구현 결과 → 검증과 반례
```

경계 보정 3 (포털 판정과 동일):

1. 조회 이득은 정보량 하나가 아니다 — 실제 이득 = 활용한 정보 − 유지·이동 비용.
2. "안 보는 법"은 강력한 휴리스틱이지 모든 알고리즘의 정의가 아니다 — 정렬·변환처럼 일을 전부 하되 배치·순서·재사용으로 이기는 알고리즘도 있다.
3. 빅오는 성장률이지 시간이 아니다 — 후보는 복잡도로 좁히고 승자는 목표 기계(채점기)에서 측정한다.

## 회고 템플릿 = 마스터 식의 코테 버전

`../templates/PROBLEM_REVIEW_TEMPLATE.md`의 칸이 마스터 식의 슬롯과 대응한다. 템플릿을 채우는 행위가 곧 본질 훈련이다.

| 마스터 식 슬롯 | 템플릿 칸 |
|---|---|
| 문제 | Interpretation · 한 문장 목표 |
| 보존할 상태·활용할 성질 | Approach · 자료구조/알고리즘 |
| 정확성 근거 | Approach · 불변식, 초기화·유지·종료 등 |
| 생략·재사용할 일 | Approach · 핵심 관찰 (완전탐색 기준선에서 무엇을 잘랐나) |
| 전체 비용 | Complexity Budget · 목표 시간/공간 |
| 구현 결과 | Result · 최종 복잡도 (채점기 실측 시간은 Metadata · 제출 결과에 기록) |
| 검증과 반례 | Counterexamples + Result · 예측 vs 실제 |

**가동 규칙 (X014 훈련)**: 코딩 시작 전에 한 문장 목표 + 불변식을 소리 내어 선서술한다. 선서술 없는 AC는 양치기 재발이다.

## 유형 10개 × 마스터 식

Winters 앵커는 실존 코드만 적는다. 앵커 없음 = 순수 신규 획득 레인 (솔직 표기).

10개 유형은 서로 배타적이지 않다. 자료구조·알고리즘 전략·그래프 표현이 섞인 분류이므로 한 풀이에 여러 행이 함께 쓰일 수 있다. 아래의 **구조 계약**(예: 힙 루트가 극값)과 **문제의 불변식**(예: 힙에 현재 선택 가능한 후보가 정확히 들어 있음)을 구분한다. 구조 계약만으로 정답이 증명되지는 않는다.

| 유형 | 상태·활용할 성질 | 정확성 근거·불변식 예 | 생략·재배치하는 일 | 비용 | Winters 앵커 |
|---|---|---|---|---|---|
| 해시 | 키별 정보와 키를 찾을 버킷. 빈도·존재·그룹 조회 | 구조 계약: 동등 키는 같은 해시값. 문제 불변식 예: count[k]가 처리한 입력에서 k의 빈도와 같음 | 전체 검색 대신 키 조회; 최악 O(N), 평균 O(1) | 메모리 O(N). N회 삽입은 최악 O(N²), 평균 O(N); 키 해시·비교 비용 별도 | FNV-1a 64 (checkpoint 컴포넌트 이름 해시 + soak 하네스 world_hash) · sparse-set의 `sparse[entity]` 직접 주소 |
| 스택/큐 | LIFO/FIFO로 후보 처리 순서를 보존 | 구조 계약: top은 마지막 삽입, front는 먼저 삽입한 잔여 원소. 이 순서가 문제의 처리 규칙에 맞음을 별도로 설명 | 다음 처리 대상을 O(1)에 선택; 각 원소를 넣고 빼는 총횟수 계산 | 최대 동시 잔여 원소 수만큼 공간, 최악 O(N) | Chase-Lev deque: owner는 bottom에서 LIFO, thief는 top에서 FIFO — 한 구조에 스택+큐 공존 (Day 3 재구현 대상) |
| 정렬 | strict weak ordering을 만족하는 비교 기준에 따른 배치 | 비교자 계약을 지키고, 이 순서에서 선택·이웃 검사 등이 왜 충분한지 별도로 설명 | 조건에 따라 이웃·경계·순서대로 처리하는 것으로 비교를 줄임 | 정렬 비교 O(N log N), 비교 1회 비용 별도. 원본 순서 필요 시 보존 비용 추가 | DeterministicEntityIterator — ForEach 수집 후 std::sort로 순회 순서 고정 |
| 완전탐색 | 후보·진행 상태를 체계적으로 생성하고 검사하는 방법; 보조 저장 허용 | 필요한 후보가 빠짐없이 생성되고, 중복 처리와 후보 판정·정답 집계가 올바름 | 안전한 생략 근거가 없으면 전량 검사 | 후보 생성·검사·집계 비용의 합. 최악 경우 수 × 경우당 비용을 구해 시간 제한과 판단 | 봇 utility 후보 전량 평가 후 argmax (탐색 공간이 작아서 전량이 정답인 사례) |
| 힙 | 극값 선택에 필요한 부분 순서 유지 (최소힙은 부모≤자식) | 구조 계약: 루트가 현재 극값. 문제 불변식: 현재 유효한 후보들이 정확히 보관됨 | 동적 삽입·극값 추출 또는 일부 K개 추출에 유용. 정적 N개를 모두 추출하면 정렬과 같은 O(N log N) 규모 | 힙 구성 O(N), K회 추출 O(K log N), 힙 조정 O(log N). 기본 vector 재할당 비용 별도 | A* open set (Engine Pathfinder.cpp) — "다음에 펼칠 최소 f 노드"만 필요하므로 priority_queue (C++ 기본은 max-heap, 최소힙은 `greater<>`) |
| DFS/BFS | 상태=노드, 행동=간선이라는 번역 + 필요한 방문 기록 | BFS: 같은 양의 이동 비용에서 큐에 처음 넣을 때 방문 표시하면 거리 순으로 진행. DFS: 재귀 호출 경로와 탐색 완료 영역을 구분; 명시적 스택은 구현에 따라 형제도 포함 | 방문한 **전체 상태**의 중복 확장을 막고 미탐색 공간을 체계적으로 탐색. 경로 열거는 방문 복원 등 별도 설계 필요 | 명시적 인접 리스트 탐색 O(V+E), 보조 공간 O(V); 상태·간선 생성 비용 별도 | NavGrid 최단 경로 — 그리드도 그래프. A* open set은 휴리스틱을 포함한 우선순위로 선택하며, 균일 이동 비용만으로 BFS와 같은 확장 순서가 되지는 않음 |
| 탐욕법 | 교환 논증·앞서가기 등으로 현재 선택의 안전성을 증명 | 각 선택 후에도 그 선택과 양립하는 최적해가 존재함 | 다른 선택의 탐색을 생략 — 선택의 안전성 증명이 근거 | 증명 부담과 실제 정렬·선택·갱신 비용. 반례 1개가 있으면 기각 | 앵커 없음 — 순수 신규 획득 레인 |
| 이분탐색 | 판정 함수가 거짓→참 또는 참→거짓으로 많아야 한 번 바뀌는 단조성 | 구간의 의미와 답 포함 여부를 유지하며, 매번 구간이 줄어듦; 답 없음·범위 밖 경계도 정의 | 후보 구간을 절반씩 줄임 | O(log 범위) × 판정 비용. 단조성·경계·mid 계산·종료 조건 확인 | 앵커 없음 — 순수 신규 획득 레인 |
| 동적계획법 | 상태별 부분 문제의 답. 상태 = 부분 문제를 유일하게 정하는 정보 | 상태 의미·기저값·점화식·계산 순서가 맞고, 이미 계산한 값이 해당 부분 문제의 정답임 | 중복 부분 문제 재계산 생략. 상태 수 자체가 지수이거나 값 범위에 비례할 수도 있음 | 총 상태별 전이 비용의 합과 저장량 계산; 다항 시간 보장은 아님 | 앵커 없음 — 순수 신규 획득 레인 |
| 그래프 | 관계의 명시적 표현(인접 리스트/행렬) + 문제별 도구(도달성·위상·최단) | 표현이 문제의 관계 의미를 보존 (방향·가중치·다중간선) | 관계 재유도 생략 — 매번 "누가 누구와 연결인가" 계산 대신 선불 구축 | 표현 메모리: 리스트 O(V+E)·행렬 O(V²). 구축 비용 선불 | Engine CPathfinder A* (Pathfinder.cpp — 그리드도 그래프. GameRoomNav는 위임층) |
| (기반) 복잡도 | 성장률 질문: "N이 10배면 무엇이 10배고 무엇이 100배인가" + 채점기 예산 산술 | 최악 기준 먼저 (Evidence Rules). 평균은 조건 명시 후에만 | — | — | -75.5% lazy pose = "빠르게"가 아니라 "안 하기"의 실측 사례 |

## 사용법

1. 목표·제약·비용 규모를 읽고 가장 직접적인 올바른 기준선을 세운다.
2. 기준선의 필요한 조회·선택·갱신과 병목을 이 표에 연결해 유형 가설을 세운다. 키/값이 모든 문제의 필수 답안은 아니다.
3. 선택한 구조·전략의 적용 조건을 확인하고, 문제별 상태 의미와 정확성 근거를 자기 문장으로 선서술한다.
4. AC 후 회고 템플릿을 채우면 마스터 식 한 바퀴가 닫힌다.
