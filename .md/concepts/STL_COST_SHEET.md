# STL 컨테이너 비용 정본 (코테용)

작성일: 2026-07-26 (해시 3/5 마감 후 바닥 훈련). 예산 산술 때 옆에 두는 표다.

교정일: 2026-10-02. 아래 비용은 C++17에서 사용하는 주요 연산을 기준으로 한다. 표의 N은 **현재 컨테이너 원소 수**, L은 **해당 문자열 연산이 읽는 최대 길이**다. 별도 표시가 없으면 원소의 비교·복사·이동은 O(1)로 가정한다. 비용 합성 예는 [통합 풀이 사고 가이드](2026-10-02_UNIFIED_PROBLEM_SOLVING.md) 참고.

## 대원칙 2개

1. **연산당 비용과 구축 비용을 구분한다.** map/set의 연산당 비용은 O(log N)이고, N개를 전부 넣는 구축 비용이 N × O(log N) = O(N log N)이다. "map은 N log N"이라고만 외우면 조회 1번 비용을 물을 때 틀린다.
2. **유형 이름은 컨테이너가 아니라 질문이다.** 해시 단원 = "본 적 있나 / 몇 번인가 / 이 키에 뭐가 붙어 있나 / 같은 키끼리 모아라"를 평균 O(1)에 선불하는 사고. 도구는 보통 unordered_*지만, 같은 문제를 정렬로 이길 수도 있다 (2026-07-26 전화번호 목록 — 해시 단원 문제를 사전순 인접성으로 AC).

## 비용표

| 컨테이너 | 내부 구조 | 핵심 연산 비용 | 순서 | 코테에서 꺼내는 신호 |
|---|---|---|---|---|
| vector | 연속 배열 | 인덱스 O(1) · 끝 삽입 1회 최악 O(N), 연속 삽입 상환 O(1) · 중간 삽입/삭제 O(N) | 삽입 순서 | 인덱스 접근·순차 저장 |
| array | 고정 크기 연속 배열 | 인덱스 O(1) | 고정 | 크기가 컴파일 타임 상수 |
| string | 문자 연속 배열 | 인덱스 O(1) · 비교 최악 O(L) · 전체 문자를 읽는 해시 계산 O(L) · 길이 L 복사 O(L) | — | 길이를 읽는 연산에만 L 비용 반영 |
| list | 이중 연결 리스트 | 임의 접근 O(N) · 아는 위치 삽입 O(1) | 삽입 순서 | 코테에선 거의 안 씀 (캐시 불리) |
| stack | deque 어댑터 | push/pop/top O(1) | LIFO | "가장 최근의 미해결" (괄호·되돌리기) |
| queue | deque 어댑터 | push/pop/front O(1) | FIFO | "도착 순 공정" (BFS·대기열) |
| deque | 블록 연결 배열 | 양끝 O(1) · 인덱스 O(1) | 양방향 | 양끝 모두에서 넣고 뺄 때 |
| priority_queue | 이진 힙 (기본 **max**) | top O(1) · push/pop 힙 조정 O(log N); 기본 vector의 push 재할당 시 원소 이동 최악 O(N) | 극값만 | 동적 극값 선택; 연속 N회 push 총 O(N log N). 최소힙 = `greater<T>` |
| map / set | 보통 균형 검색 트리 | 조회·일반 삽입 O(log N)회 비교; 비교 비용을 곱함 | 키 정렬 순회 | 순서·범위 또는 최악 로그 조회 보장 |
| unordered_map / unordered_set | 해시 테이블 | 조회·단일 삽입 최악 O(N), 평균 O(1) 수준의 키 처리; 문자열 해시·동등 비교 비용 별도 | 없음 | 존재·빈도·짝·그룹 |
| multiset / multimap | 중복 키를 허용하는 정렬 컨테이너 | 조회·일반 삽입 O(log N) 비교; 같은 키 K개 검색 결과 열거·삭제는 K 비용 추가 | 키 정렬 | 중복을 유지하며 정렬이 필요할 때 |

해시로 N개를 구축하면 최악 O(N²), 평균 O(N)이다. 문자열 길이 상한 L과 전체 문자를 읽는 해시를 가정하면 구축은 최악 O(N²L), 평균 O(NL)로 적을 수 있다. 트리 문자열 조회는 O(log N)번의 비교 × 최악 O(L)로 O(L log N)이다. **문자열의 L은 해당 연산 항에만** 붙인다.

상환 비용은 무작위 입력의 평균과 다르다. vector의 연속 N회 끝 삽입은 재할당에 드는 이동까지 합쳐 O(N)이므로 삽입당 상환 O(1)이다. 반면 unordered 계열의 평균 비용을 최악 보장으로 읽어서는 안 된다. [C++ 표준 초안의 vector 비용](https://eel.is/c++draft/vector.modifiers), [unordered 컨테이너 요구사항](https://eel.is/c++draft/unord.req).

## 함정 노트 (전부 이번 세션 실사고 또는 그 예방)

1. **operator[]**: map/unordered_map의 `[]`는 없는 키를 만지면 기본값을 **삽입**한다. 카운팅(`++m[k]`)에선 기능, 존재 확인에선 사고 — 존재 확인은 `count()`/`find()`. set 계열엔 `[]` 자체가 없다 (2026-07-26 실충돌).
2. **size()는 unsigned(size_t)**: int와 섞으면 부호 비교 오류가 생길 수 있다. `size_t`로 순회하거나, 크기가 int 범위 안임을 확인한 뒤 명시적으로 변환한다. 빈 컨테이너에서 `size()-1`도 주의한다.
3. **iterator 무효화**: vector는 재할당(용량 초과 push_back) 시 전부 무효. unordered_*는 rehash 시 iterator 무효(원소 참조는 생존). map/set은 지운 원소만 무효. 순회 중 삭제는 `it = c.erase(it)` 패턴.
4. **priority_queue 기본은 max-heap**: 최소힙은 `priority_queue<T, vector<T>, greater<T>>`.
5. **문자열 길이 비용**: 최대 길이가 L일 때 비교 최악 O(L), 전체 문자를 읽는 해시 O(L). 지문에 L 상한이 없으면 변수 L이나 총 문자열 길이로 남긴다. 사전순 비교는 첫 불일치에서 끝날 수 있으며, 연산 수를 고정 초로 바꾸지 않는다.
6. **트리 vs 해시 선택**: 존재·빈도에는 unordered가 후보이고, 순서·범위 또는 최악 로그 조회 보장이 필요하면 트리가 후보다. 과거 한 문제의 map TLE를 모든 문제의 금지 규칙으로 일반화하지 않는다.
