# 같은 숫자는 싫어 AC와 공통 사고 과정 세션 기록

날짜: 2026-10-10 Asia/Seoul

이번 기록의 범위는 같은 숫자는 싫어의 코드 수정, 사용자 보고 AC, 공통 8단계의 설명과 증거다. 쉬운 문제에서도 상태의 의미·경계·비용을 직접 설명하는 연습을 이어간다. [문제 회고](../../problems/stack_queue/12906_같은_숫자는_싫어/REVIEW.md)는 풀이 근거, [코드 해설](../../docs/study/SAME_NUMBER_WALKTHROUGH.md)는 8단계 작성 예시를 담당한다.

## 관찰된 이력

1. 처음 공유한 왼쪽 인접 비교 코드는 과거 풀이를 슬쩍 참고한 코드였다고 사용자가 정정했다. 처음부터 독립적으로 재유도한 풀이라는 해석은 철회한다.
2. 재풀이 초안에서는 오른쪽 값과 비교해 구간의 마지막 값을 남겼다. 다만 마지막 위치에서는 왼쪽과 다른 경우에만 추가하여 마지막 동일 구간을 누락했다.
3. 사용자가 보고한 실패 결과는 `[1,1,3,3,0,1,1] → [1,3,0]`, `[4,4,4,3,3] → [4]`였다.
4. 코치는 작은 입력 `[1,1]`의 손추적을 질문하고 단일 원소 점검을 권했다. 이에 대한 사용자 손추적표 응답이나 단일 원소의 별도 실행 증거는 확인되지 않았다.
5. 사용자는 마지막 원소를 무조건 추가하는 코드로 수정했다. 이 수정 뒤 정확성 17개와 효율성 4개 모두 통과한 100점 결과를 제공했다.
6. 사용자는 AC 코드의 Git 보관과 함께 공통 8단계, 코드 근거, 약점과 훈련 기록을 계속 유지해 달라고 요청했다.

현재 풀이에 대한 설명은 **사용자가 만든 수정 코드와 AC 이후의 사후 학습**이다. 코치가 채운 불변식·비용식을 사용자가 코딩 전에 말했다는 증거로 바꾸지 않는다.

## Judge 결과

증거 출처는 사용자가 제공한 프로그래머스 제출 결과다. 코치가 별도로 계정에 접속해 제출한 결과가 아니다. 개별 테스트의 시간·메모리 수치는 [JUDGE_REPORT](../../problems/stack_queue/12906_같은_숫자는_싫어/JUDGE_REPORT.md)에 보존한다.

| 구분 | 통과 | 점수 |
|---|---:|---:|
| 정확성 | 17 / 17 | 71.9 |
| 효율성 | 4 / 4 | 28.1 |
| 합계 | 21 / 21 | 100.0 |

측정치는 해당 제출 환경의 결과다. 메모리 수치를 결과 vector만의 사용량으로 해석하거나, 실행 시간만으로 독립적인 복잡도 설명 능력을 판정하지 않는다.

## 로컬 검증

- 코치가 `Tools/Build.ps1`로 Debug·Release 빌드를 각각 시도했다. 두 시도 모두 cmake 명령이 없어 실제 소스 컴파일 전 단계에서 실패했다. 환경 문제이며 소스의 컴파일 오류로 판정하지 않는다.
- 공식 예제 2개, 작은 경계 8개, 최대 입력 2개로 총 12개 하네스를 준비했다. 빌드가 완료되지 않아 Example·Edge의 로컬 실행 결과는 없다.
- 프로젝트 XML 4개 파싱, 중복 main 없음, 보존 소스 해시 일치, 하네스 기대값의 정적 검토는 확인되었다. 이 정적 검토를 빌드·실행 통과로 바꾸어 기록하지 않는다.
- Judge의 AC는 로컬 환경과 독립적으로 사용자 제공 제출 결과에 근거한다. 코치가 준비한 경계를 사용자 자작 반례로 기록하지 않는다.

## 도움과 직접 수행의 구분

| 구분 | 확인된 범위 |
|---|---|
| 과거 참고 | 첫 왼쪽 비교 코드는 과거 풀이를 참고했다는 사용자 정정 |
| 코치 질문 | `[1,1]` 추적 질문, 단일 원소 점검 권장 |
| 사용자 수행 | 오른쪽 비교 재풀이 초안 제시, 실패 결과 보고, 마지막 분기 수정, AC 제출 결과 제공 |
| 사후 코치 해설 | 구간 끝이라는 공통 규칙, 현재 코드에 맞는 불변식, 비용·경계·8단계 문서 작성 |
| 아직 확인되지 않음 | 질문에 대한 추적표 응답, 자작 반례, 코딩 전 독립 증명, 지연 복원과 무힌트 변형 해결 |

이번 결과를 무힌트 백지 풀이로 분류하지 않는다. 동시에 도움을 받았다는 이유로 사용자가 수행한 수정과 실제 AC를 지우지 않는다.

## 공통 8단계의 판결 후 증거

아래 충족 여부는 **독립 산출물과 검증 기록이 갖춰졌는지**에 관한 것이다. 미확인은 능력 부족 판정이 아니다. 사후 해설은 준비되었지만 사용자가 자기 말로 재생성했는지는 다음 문답에서 확인한다.

| 단계 | 충족 여부와 현재 증거 | 다음 확인 |
|---|---|---|
| 1 목표 | 미충족: 반환 규칙에 맞는 AC 코드는 확인, 독립 목표 문장은 확인 전 | 연속 구간과 원래 순서를 포함해 한 문장 생성 |
| 2 제약 | 미충족: 공식 범위는 문서화, N과 값 범위를 사용자가 구별한 산출물은 확인 전 | N 상한과 값 범위가 각각 무엇에 영향을 주는지 설명 |
| 3 예산 | 미충족: 코치가 O(N)과 최대 입력 규모 설명, 사용자 비용식은 확인 전 | 횟수와 단일 비용을 분리해 직접 합산 |
| 4 기준선 | 미충족: 완결된 선형 직접 풀이 코드 있음, 코딩 전 절차·비용 설명은 확인 전 | 코드 없이 구간 끝 선택 절차 복원 |
| 5 병목과 설계 | 미충족: 원본 인접 비교를 쓴 사실은 확인, 충분성과 선택 근거의 독립 설명은 확인 전 | 왜 전체 검색·별도 stack이 필요 없는지 설명 |
| 6 선서술 | 미충족: 코드의 구간 끝 규칙은 수정됨, 사용자 불변식·유지·종료 증명은 확인 전 | 현재 코드의 반복 직전 상태를 설명 |
| 7 네 가지 검증 | 미충족: Judge 충족, Debug·Release Build는 cmake 부재로 컴파일 전 실패, Example·Edge 실행 미실시 | 환경에서 빌드가 가능해지면 준비한 12개 하네스를 실행 |
| 8 회고 | 미충족: 사후 회고 문서 작성, 사용자 복원·전이 증거는 확인 전 | 한 가지 배운 규칙을 자기 말로 정리한 뒤 지연 복원 |

코딩 전 산출물을 사후에 완성해 과거의 코딩 전 통과로 기록하지 않는다. 이미 받은 AC를 취소하거나 전체 진도를 처음으로 돌리지 않고, 남은 설명과 검증을 하나씩 이어 간다.

## 관찰과 해석과 미확인

| 관찰 | 제한적으로 가능한 해석 | 아직 단정할 수 없는 것 |
|---|---|---|
| 중간은 오른쪽 비교, 마지막은 왼쪽 비교를 사용해 마지막 구간 누락 | 대표를 구간의 시작에서 남길지 끝에서 남길지 경계까지 일관되게 연결하는 연습이 필요 | 모든 문제에서 경계 처리가 약하다거나 스택을 이해하지 못한다는 결론 |
| 작은 반례 질문 뒤 마지막 무조건 추가로 수정하고 AC | 마지막 구간이 종료 시점에 확정된다는 규칙을 코드에 반영했다 | 질문에 실제로 손추적했는지, 같은 원리를 혼자 일반화할 수 있는지 |
| 사용자가 과거 참고 사실을 정정 | 첫 코드를 독립 생성의 근거로 삼으면 안 된다 | 이번 수정까지 단순 복사였다는 주장 |
| 비용·불변식의 독립 답변이 아직 없음 | 다음에 확인할 학습 산출물이 분명하다 | 해당 개념을 전혀 모른다거나 이전 약점이 악화되었다는 결론 |

현재 우선 훈련은 **정한 대표 선택 규칙을 마지막 원소에도 일관되게 적용하기**, **중간 상태의 의미를 실제 코드에 맞춰 쓰기**다. 이는 이번 사례에서 확인할 항목이며, 반복 실수로 확인되기 전에는 새 상습 약점으로 승격하지 않는다.

## 설명 자료의 교정

이전 walkthrough는 왼쪽 비교 코드를 현재 풀이로 설명하고 있었다. 사용자 정정을 반영해 그것을 과거 참고 풀이로 명시하고, 최신 AC인 오른쪽 비교 풀이로 갱신했다.

왼쪽 비교에서 쓰던 “처리한 접두사를 모두 압축한 결과”라는 불변식은 최신 코드에 옮겨 쓸 수 없다. 예를 들어 `[1,1]`의 첫 반복 후 answer는 아직 비어 있다. 최신 불변식은 **원본 전체에서 끝 위치가 현재 i보다 작은 구간들만 대표값이 저장되었다**는 것이다. 이 교재 교정을 학습자의 추가 오답으로 세지 않는다.

## 다음 훈련

지금 바로 확인할 한 질문은 “`[2,2,5,2,2]`에서 매 반복 **직전** answer에는 무엇이 들어 있는가?”다. 표를 사용자가 먼저 만들고, 그 표를 설명하는 불변식 한 문장으로 이어 간다. 여러 미충족 항목을 한꺼번에 다시 제출하게 하지 않는다.

이후 순서는 실제 응답에 따라 조절한다.

1. 같은 값인 구간의 첫 값과 마지막 값 중 무엇을 남겼는지 말하고, 마지막 무조건 추가가 예외 암기가 아닌 이유를 설명한다.
2. N회 순회, N−1회 인접 비교, K회 추가를 분리해 시간과 공간을 계산한다.
3. 2026-10-11 이후이면서 학습 종료로부터 24시간 이상 지난 시점에 코드·해설을 가리고 목표·절차·불변식·비용을 복원한다. 수행 시각과 결과는 아직 없다.
4. 값 대신 대표 인덱스를 반환하는 작은 변형에서 현재 선택 규칙이 반환 결과에 미치는 영향을 설명한다.

이번 요청에는 미래 알림 설정이 포함되지 않았으므로 자동화는 만들지 않았다. 다음 Kit 문제는 지문 해석과 사용자 접근부터 다시 시작하며, 이번 AC 해설에 다음 문제의 완성 풀이를 포함하지 않는다.
