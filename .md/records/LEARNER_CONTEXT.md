# Learner Context

갱신일: 2026-10-07

## Background

- 과거에 자료구조·알고리즘 책을 보며 문제를 순서대로 많이 풀어본 경험이 있다.
- 그러나 책의 설명, 풀이 방향, 예제 코드에 기대어 진행한 비중이 컸고, 빈 화면에서 문제 해석부터 알고리즘 선택·구현·검증까지 완전히 독립적으로 해결한 문제는 많지 않았다.
- 따라서 용어와 풀이를 보면 익숙하거나 이해되는 느낌은 있을 수 있지만, 이를 독립적인 생성 능력이나 숙달의 증거로 간주하지 않는다.

## Teaching Implication

- 현재 병목은 지식의 양보다 문제 문장에서 구조를 추출하고 풀이를 스스로 생성하는 능력이다.
- 수업은 정답 설명보다 문제 재서술, 필요한 연산 도출, 표현 선택, 불변식 선언, 반례 생성, 빈 화면 구현을 우선한다.
- 힌트를 사용한 단계와 도움의 양을 기록해 독립 풀이와 구분한다.
- 같은 문제를 다시 읽는 복습보다 지연된 백지 복원과 변형 문제 전이를 숙달 증거로 사용한다.

## Mastery Evidence

다음 단계는 서로 다르게 기록한다.

1. Recognition: 해설이나 코드를 보면 이해된다.
2. Explanation: 코드를 보지 않고 핵심 원리를 설명한다.
3. Reconstruction: 빈 화면에서 풀이와 코드를 다시 만든다.
4. Transfer: 처음 보는 변형 문제에 같은 원리를 적용한다.

목표는 문제별 Transfer 단계다.

## 이전 관찰 — 2026-10-02

- 사용자 요청: 해시 이후 스택/큐부터 모든 유형에 공통으로 적용할 문제 읽기·설계 질문과 각 질문의 답을 생성하는 방법을 익히기.
- 본인 보고: 목표 문장은 작성했지만 시간 복잡도 계산과 완전탐색 기준선 답변을 깔끔하게 만들지 못했던 기억이 있음.
- 기존 관찰: 베스트앨범 소스에 `O(20,000)` 뒤 비용식이 미완이며 기준선은 공란. 당시 회고에도 기준선·코딩 전 불변식 미작성, 자작 Edge 0개가 기록되어 있음.
- 해석: 단계 이름을 아는 것과 각 단계의 답을 독립적으로 생성하는 것 사이를 우선 훈련한다. 모든 유형의 지식 부족이나 현재의 구현 능력 부족으로 확대 해석하지 않는다.
- 지도 보정: 기존 문서의 “기준선=무저장”, “모든 유형=키/값”, “10⁸회=1초”, 잘못된 값 상한 등은 교재의 문제이며 학습자 오류와 분리한다.
- 진행 방식: 작은 입력 손풀이 → 직접 절차 → 실행 횟수×한 번 비용 → 상태/처리 순서 → 정확성 근거를 한 질문씩 연결한다. 새로운 유형 문제의 완성 풀이를 선공개하지 않는다.
- 증거 수준: tracker에는 해시 5/5 AC, 전체 5/47 AC. 오늘 신규 구현·제출·백지 복원·전이 성과는 미측정. 설명을 제공했다는 사실로 Mastered나 약점 해결을 기록하지 않는다.
