# Problem Review

## Metadata

- 문제: 베스트앨범
- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42579
- 유형: 해시 (그룹핑) + 정렬 (다중 기준 비교자)
- 난이도: Level 3 (첫 L3 AC)
- 시도 시간: 심야 세션 수 시간 (막힘 → 프로토콜 → 디버깅 → 2회 제출)
- 제출 결과: 1차 — 2건 실패. 비교자 else 분기(재생수 오름차순 → 내림차순) 수정 후 2차 — 통과 (2026-07-27, 사용자 보고)
- 힌트 사용 (코치 기록): 이번 문제는 스캐폴드 소비가 큼 — 막힘 프로토콜 5단계 제공, 유도 질문 3개(총합 동시 집계·순서는 vector로·2기준 비교자), 비교자 계약("반환값 = a가 앞인가") 2회 교육 + CompareTotal 1분기 유도 시범, 동률 프로브 TC 제공, map sort 불가 3중 근거, VS 디버깅 절차(스테일 exe 함정 포함). 사용자 자력 = 그룹핑 구조 설계, 총합 집계 루프 재작성(자가 수정), 조립 루프(1곡 예외 포함), 최종 비교자 수정, F11 진단 수행

## Interpretation

- 한 문장 목표: 많이 재생된 장르순 → 장르 내 많이 재생된 곡순(동률 시 번호순) → 장르당 최대 2곡의 고유번호 배열 (사용자)
- 입력 크기: 곡 ≤ 10,000, 장르 < 100
- 중복·순서·범위 조건: 장르 총합은 모두 다름(동률 분기 생략 근거 — 사용자가 제약으로 판단), 곡 1개 장르는 1곡만
- 요구되는 출력: vector<int> (수록 순서)

## Approach

- 핵심 관찰: L3 = L1 도구들의 합성 (그룹핑 + 합산 + 다중 기준 정렬 + 상위 2 추출). 새 도구 0개

## Counterexamples

- **미결 복습 과제 (중요): 동률 프로브 {"a","a"}, {100,100}** — 명세("재생 횟수가 같으면 고유번호 낮은 노래 먼저")상 답은 [0,1]인데, 제출 코드의 동률 분기(`a.first > b.first`)는 [1,0]을 낼 것으로 예상됨. **그런데 채점기를 통과함** — 동률 순서를 판정하는 숨은 테스트가 없는 것으로 추정. 하네스로 검증하고 분기를 명세대로 수정할 것. **교훈: AC ≠ 명세 부합. 채점기의 커버리지에도 구멍이 있다.**
- 곡 1개 장르: 조립 루프에서 처리됨 ✓ (구현으로 확인, 별도 TC 미실행)
- 직접 만든 반례: 프로브는 코치 제공 — 자작 Edge 0개 (채무)

## Result

- 예측 vs 실제: 1차 제출 전 로컬 하네스 미실행 → 2건 실패로 진단 비용 지불. "채점기는 판결만 주고 진단은 안 준다"를 실비용으로 학습
- 실패 원인: 비교자를 "참이면 swap" 모델로 오해 → 부등호 3분기 도박 (gotchas 승격됨). else 분기 수정으로 통과
- 최종 복잡도: 시간 O(N log N), 공간 O(N)
