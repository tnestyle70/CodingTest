- 힌트 사용 (코치 기록): **세션 중 최고 자력도.** 공식 (개수+1) 곱 −1을 자가 유도("0 포함 곱셈" 직관 → 예제 손 계산 3×2−1=5로 자가 검증), 코드의 +1 누락 버그를 코치 지적 전에 자가 발견. 코치 제공 = 2¹⁰≈10³ 변환 트릭, int 최대 21억 교정(42억 아님), "동시→독립" 단어 교정, Edge 카테고리 3종 제시. 정답 코드 제공 없음

## Interpretation

- 한 문장 목표: 서로 다른 옷 조합의 수를 return (사용자)
- 입력 크기: clothes 길이 1~30
- 중복·순서·범위 조건: 같은 이름 없음, 종류별 최대 1벌 착용, 최소 1벌은 입는다 (사용자 추출)
- 요구되는 출력: int (조합 수)

## Complexity Budget

- 완전탐색: 30벌 입는다/안 입는다 전부 열거 = 2³⁰ ≈ 10⁹ (2¹⁰≈10³ 변환) ÷ 10⁸ ≈ 10초 → 죽음. N=30은 지수 풀이 경계 지형 (N=20이면 10⁶으로 삶)
- 목표 시간 복잡도: O(N) — 30 삽입 × 해시 O(20) + 종류 수(≤30) 곱셈 ≈ 10³ 연산 → ~10⁻⁵초
- 목표 공간 복잡도: O(종류 수)
- **값의 범위 검증: 답 ≤ 2³⁰ ≈ 10.7억 < int 최대 2.1×10⁹ — 아슬아슬하게 int 통과.** (기준선 계산과 상한 논증에 같은 수 2³⁰이 등장 — 모든 조합은 입/안입 부분집합이므로)

## Approach

- 핵심 관찰: 조합을 열거할 필요 없음 — 종류별 개수만 알면 산술로 답이 나온다. 병목 = 종류별 빈도 세기 → unordered_map
- 자료구조/알고리즘: unordered_map<string,int> 카운팅 (평균 O(1)) + 곱의 법칙
- 불변식 (사용자, 승인본): 답 = Π(종류별 개수 + 1) − 1. **+1** = 그 종류를 안 입는 선택지까지 센 것. 종류 간 선택은 **독립**이므로(한 종류의 선택이 다른 종류의 선택지 수를 바꾸지 않음) 경우의 수는 곱. **−1** = 전부 안 입는 조합 1개 제거 (최소 한 벌 제약).
- 이 접근이 틀리는 조건: (사용자 작성 — 힌트: 종류 간 제약이 생기면? "같은 색 금지" 같은)

## Counterexamples

- 최소 입력: 의상 1벌 → (1+1)−1 = 1 (사용자 손 계산 ✓)
- 한 종류 몰빵 30벌 → (30+1)−1 = 30 — 단일 종류에선 +1과 −1이 상쇄 (사용자 초기 혼동 → 해소)
- 종류 4개 각 1벌 → 2⁴−1 = 15 (사용자 손 계산, k 역산으로 자가 검증)
- 하네스 실행: 미실시 — 프로토콜 v3(연습 문제는 채점기 직행 허용) 범위 내. 손 계산 검증은 수행됨
