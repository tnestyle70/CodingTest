# Problem Review

## Metadata

- 문제: 전화번호 목록
- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42577
- 유형: 해시 (제출 풀이는 정렬 — 합법, 해시 별해 비교는 Reviewed에서)
- 난이도: Level 2 (첫 L2 AC)
- 시도 시간: 수 시간 (사용자 자기 보고 "몇 시간 걸린 거야")
- 제출 결과: 정확성 20/20 + 효율성 4/4, 합계 100.0 — 최대 46.5ms, 35.9MB (2026-07-26, 사용자 보고)
- 힌트 사용 (코치 기록): 갈래 질문 2개(정렬 인접/해시 접두사) 제공, 조합 사다리 C(20,10) 제공, 접두사 조각 열거 예시 직접 제시(핵심 관찰 — 3회 실패 후), 인접성 유도 질문("사이에 낀 C는 무엇으로 시작하나"), string API 2개(substr/compare 시그니처+일반 예제) 지급. 사용자 자력 = 갈래 A 조립("알았다, 인접만 비교"), 불변식 문장, 경계선 예산 계산 완주(log₂ 분해 포함), compare 무할당 선택, 구현. 좀비 3종(값의 범위→루프 횟수, string→int 변환 2회, set 우회) 재발 후 교정

## Interpretation

- 한 문장 목표: 어떤 번호가 다른 번호의 접두사인 경우가 있으면 false, 없으면 true (사용자)
- 입력 크기: phone_book 길이 ≤ 10⁶, 번호 길이 1~20
- 중복·순서·범위 조건: 같은 번호 중복 없음 (→ 인접 동일성 불가능의 근거). 번호 20자리 > long long 19자리 → int 변환 불가능
- 요구되는 출력: bool

## Complexity Budget

- 완전탐색: 쌍별 비교 10⁶ × 10⁶ = 10¹² ÷ 10⁸ = 10⁴초 = 1만 초 → 죽음 (사용자)
- 목표 시간 복잡도: O(N log N × L) — sort 비교 10⁶ × 20 = 2×10⁷회 × 문자열 비교 O(20) ≈ 4×10⁸ 연산 → 종이 판정 ≈ 4초 "경계선" (사용자 산술 — log₂(10⁶)=6×log₂(10)≈20 분해 포함)
- **핵심 교훈: 종이 4초 → 실측 46.5ms (약 100배 여유).** ×20은 최악 상수 — 사전순 비교는 첫 불일치 문자에서 종료. "종이가 경계선이어도 사형 확정은 실측으로만" (경계 보정 3 양방향)
- 목표 공간 복잡도: O(1) 추가 (in-place sort)

## Approach

- 핵심 관찰: 접두사 관계는 사전순 정렬에서 이웃으로 모인다 → 쌍별 비교 10¹²를 인접 N−1회로 축소
- 자료구조/알고리즘: 사전순 정렬 + 인접 접두사 비교 (string::compare(0, len, other) — 무할당이라 substr 대신 선택, 예산 근거)
- 불변식 (사용자 선서술, 승인본): A가 B의 접두사이고 정렬에서 A < C < B인 C가 끼어 있다면 C는 A로 시작할 수밖에 없다. 따라서 A가 어떤 번호의 접두사라면 정렬 후 A의 바로 다음 원소도 A로 시작한다 — 인접 쌍만 검사하면 충분하다.
- 이 접근이 틀리는 조건: (사용자 작성 — 힌트: 중복이 허용된다면? 접두사가 아니라 "포함"이라면?)

## Result

- 예측 vs 실제: 종이 "4초 초과 안 됨" 오판 → 실측 46.5ms 통과. 판정 프로세스 교정이 이 문제 최대 수확
- 실패 원인: 없음 (1회 제출 통과)
- 최종 복잡도: 시간 O(N log N × L), 공간 O(1) 추가
