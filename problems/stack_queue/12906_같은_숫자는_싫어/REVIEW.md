# Problem Review

## Metadata

- 문제: 같은 숫자는 싫어
- 링크: [프로그래머스 12906](https://school.programmers.co.kr/learn/courses/30/lessons/12906)
- 유형: 스택/큐 분류, 실제 제출 방식은 원본 인접 비교와 vector 끝 삽입
- 난이도: Level 1
- 시도 시간: 미측정
- 제출 결과: 2026-10-10 Asia/Seoul, 사용자 보고 AC 100점. 정확성 17/17, 효율성 4/4 통과. 상세 수치는 [JUDGE_REPORT](JUDGE_REPORT.md)에 보존한다.
- 풀이 이력: 처음 공유한 왼쪽 비교 코드는 과거 풀이를 참고한 코드였다고 사용자가 정정했다. 이번 재풀이의 최종 AC 코드는 오른쪽 값을 비교하여 각 연속 구간의 마지막 값을 저장한다.
- 도움: 이전 풀이 참고와 코치의 작은 반례 질문이 있었다. 무힌트 백지 풀이로 기록하지 않는다. 구체적 지원과 증거 구분은 [세션 기록](../../../.md/records/2026-10-10_STACK_QUEUE_SESSION.md)에 둔다.

## Interpretation

- 한 문장 목표: 각 연속된 같은 값 구간에서 하나만 남기고 구간의 원래 순서대로 반환한다.
- 입력 크기: `N = arr.size()`, `1 ≤ N ≤ 1,000,000`.
- 중복·순서·범위 조건: `0 ≤ arr[i] ≤ 9`. 떨어져 있는 같은 값은 다른 구간이다. 모든 같은 값을 하나로 합치는 문제가 아니다.
- 요구되는 출력: 각 구간의 대표값을 순서대로 담은 `vector<int>`. 원본 위치는 반환하지 않으므로 같은 구간의 첫 값이나 마지막 값을 선택해도 반환값은 같다.

이 문서의 목표·비용·불변식은 AC 코드에 대한 사후 해설이다. 사용자가 코딩 전에 독립적으로 같은 문장을 작성했다는 증거로 올리지 않는다.

## Complexity Budget

- 직접 풀이 기준선: 왼쪽부터 각 위치를 한 번 확인한다. 다음 값이 다르거나 배열이 끝나면 해당 위치의 값을 남긴다. 이 올바른 직접 풀이가 최종 풀이이므로 느린 완전탐색을 따로 만들 필요는 없다.
- 최대 입력 대입: N²은 10¹², N은 10⁶ 규모다. 특정 실행 시간으로 환산하지 않고 작업량을 비교한다.
- 목표 시간 복잡도: O(N). 순회 N회, 인접 값 비교 N−1회, 결과 추가는 구간 수 K회이며 K≤N이다.
- 목표 공간 복잡도: 결과 O(K), 최악 O(N). 함수 본문에서 입력과 결과를 제외한 지역 상태는 O(1)이다. 값 인자 `vector<int> arr`의 복사가 발생하면 호출 과정의 추가 시간·공간은 O(N)이다.
- 비용 전제: 정수 읽기와 비교는 O(1). vector의 연속 끝 삽입은 재할당을 포함한 총비용으로 분석하며, 모든 단일 `push_back`이 최악 O(1)이라고 주장하지 않는다.

## Approach

- 핵심 관찰: 마지막 위치는 반드시 어떤 구간의 끝이다. 마지막이 아닌 위치에서는 `arr[i] != arr[i+1]`일 때에만 구간이 끝난다.
- 자료구조/알고리즘: 원본을 변경하지 않는 한 번의 순회와 결과 vector. 원본 오른쪽 값에 O(1)로 접근할 수 있어 별도 검색이나 stack 선언이 필요하지 않다.
- 갱신: 마지막 위치이면 현재 값을 추가한다. 그 외에는 오른쪽 값과 같으면 건너뛰고, 다르면 추가한다.
- 불변식: **i번째 반복 직전 answer에는 원본 전체에서 끝 위치가 i 미만인 연속 구간의 대표값만, 각 구간당 정확히 하나씩 원래 순서대로 들어 있다.** 앞의 i개를 읽었어도 원본에서 아직 끝나지 않은 구간의 대표는 대기 중일 수 있다.
- 초기화: i=0이면 끝 위치가 0 미만인 구간이 없으므로 빈 answer가 조건을 만족한다.
- 유지: 마지막이 아니고 오른쪽 값과 같으면 i에서 끝나는 구간이 없으므로 추가하지 않는다. 오른쪽 값과 다르면 i에서 끝난 구간 하나의 대표를 추가한다. 마지막 위치도 구간 끝이므로 한 번 추가한다.
- 종료와 답: i=N이면 모든 구간의 끝 위치가 N 미만이므로 answer가 전체 답이다. i가 매번 1씩 증가하고 N에서 멈추므로 종료한다.
- 이 접근이 틀리는 조건: 구간의 대표로 원래 첫 위치를 반환해야 하거나, 원소 제거로 새로운 이웃 관계를 다시 처리해야 하는 규칙으로 바뀌면 현재 근거를 그대로 적용할 수 없다. 이 문제는 값만 반환하고 원본의 고정된 인접 관계를 사용한다.

`answer`가 매번 처리 접두사의 압축 결과라는 불변식은 현재 코드에 맞지 않는다. `[1,1]`에서 i=1 반복 직전 answer는 비어 있다. 첫 값 저장 방식과 마지막 값 저장 방식은 같은 최종 값을 내도 중간 상태의 뜻이 다르다.

## Counterexamples

| 입력 | 기대값 | 확인할 규칙 |
|---|---|---|
| `[7]` | `[7]` | 마지막 분기가 첫 원소도 처리하며 오른쪽 접근을 하지 않음 |
| `[1,1]` | `[1]` | 마지막 구간을 끝에서 반드시 확정함 |
| `[0,0,0]` | `[0]` | 전체가 한 구간인 경우 |
| `[1,2,1]` | `[1,2,1]` | 떨어진 같은 값을 유지함 |
| `[1,1,3,3,0,1,1]` | `[1,3,0,1]` | 여러 구간과 마지막 동일 구간 |
| `[4,4,4,3,3]` | `[4,3]` | 길이가 여러 개인 마지막 구간 |
| 길이 1,000,000의 0과 9 교대 배열 | 원본과 같은 배열 | 결과 길이가 N까지 커지는 경우 |

이 표는 명세에서 도출한 기대 결과다. 표를 작성한 사실만으로 사용자 또는 코치가 전부 실행했다고 기록하지 않는다. `[1,1]`은 코치가 제시했고 단일 원소 점검도 코치가 권했다. 사용자 손추적표 응답·별도 경계 실행·자작 반례의 증거는 아직 없다.

## Result

- 예측 vs 실제: 최신 코드의 구간 끝 선택 규칙은 명세와 일치하며, 사용자 보고 Judge에서 정확성·효율성 전체 통과가 확인되었다.
- 실패 원인: 재풀이 초안은 중간에서 오른쪽과 비교해 구간의 끝을 고르면서 마지막 위치에서는 왼쪽과 다를 때만 저장했다. 마지막 구간 길이가 2 이상이면 그 구간의 대표가 한 번도 저장되지 않았다.
- 확인된 실패 결과: `[1,1,3,3,0,1,1] → [1,3,0]`, `[4,4,4,3,3] → [4]`. 사용자가 보고한 결과이며 로컬 재현 기록과 구별한다.
- 사용자 수정: 마지막 위치의 왼쪽 비교를 없애고 마지막 원소를 무조건 저장하도록 바꿨다. 이 수정 후 AC를 보고했다.
- 최종 복잡도: 시간 O(N), 결과 최악 O(N), 본문 지역 상태 O(1). 값 인자 복사를 포함하는 경우를 별도로 센다.
- 다른 풀이와 차이: 과거 참고 코드는 구간 시작에서 대표를 저장하고, 이번 AC 코드는 구간 끝에서 저장한다. 마지막 값 방식에는 아직 끝나지 않은 구간의 확정 시점을 설명해야 한다.
- 로컬 검증: 코치가 `Tools/Build.ps1`로 Debug·Release를 각각 시도했으나 cmake 명령 부재로 컴파일 전에 실패했다. 공식 예제 2개·작은 경계 8개·최대 입력 2개의 하네스는 준비했으며 실행은 미실시다. 소스 컴파일 오류나 테스트 실패로 판정하지 않는다. Judge는 사용자 제공 제출 결과로 충족한다.

## Transfer

- 다음에 알아볼 신호: 반복되는 같은 값의 연속 구간, 구간 시작과 끝, 대표값 확정 시점, 배열 끝으로 확정되는 마지막 작업.
- 재사용할 질문: “결과에 대표값을 언제 넣는가?”, “마지막 구간도 같은 의미로 처리되는가?”, “현재 불변식에 아직 확정하지 않은 항목이 포함되어 있는가?”
- 다음 독립 출력: `[2,2,5,2,2]`에서 각 반복 **직전** answer를 적고 위 불변식을 자기 문장으로 설명한다. 아직 수행 결과는 없다.
- 24시간 복습일: 2026-10-11 이후이면서 이번 학습 종료로부터 실제 24시간 이상 지난 시점. 완료 여부는 미확인이고 자동 알림은 설정하지 않았다.
- 연결 변형: 같은 구간의 대표값 대신 대표 원소의 인덱스를 반환한다면 구간 시작·끝 방식의 출력이 어떻게 달라지는지 설명한다. 다른 미풀이 Kit 문제의 풀이를 선공개하지 않는다.
- 숙련 판정: AC는 확인. 독립 선서술·지연 복원·무힌트 변형 해결은 별도 확인 전이므로 완료로 올리지 않는다.
